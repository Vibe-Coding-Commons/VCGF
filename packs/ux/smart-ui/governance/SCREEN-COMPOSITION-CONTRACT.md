# VCGF Smart Screen Composition Contract

## الغرض
يعرّف العقد ما يجب أن يثبته أي تركيب شاشة قبل اعتماده. التركيب ليس صفحة HTML جاهزة ولا تبعية برمجية؛ هو عقد يحدد نية الشاشة، مناطقها، هرمية المعلومات والإجراءات، وتحولها عبر المقاسات.

## قواعد إلزامية
1. اختيار التركيب يحتاج `composition_signals` صريحة أو دليل مكافئ موثق.
2. يسمح بتركيب أساسي واحد فقط لكل Screen Context، مع مُعدّلات صريحة مثل MobileFocusedTask أو LargeScreenOperations.
3. اختيار التركيب لا يفعّل مكونات أو Interaction Patterns؛ العلاقات `review-only`.
4. إعادة استخدام Shell/Layout موجود مناسب يسبق بناء Shell جديد، مع تقييم ملاءمة ودليل.
5. Role adaptation لا يمنح صلاحية ولا يغير الحقيقة أو قواعد الأعمال.
6. Responsive transformation يحافظ على المهمة وترتيب القراءة، وليس على الشكل الحرفي.
7. اختبار التطبيق الفعلي يبقى `not_run` حتى توجد شاشة منفذة ودليل قبول.

## Evidence
يسجل لكل تركيب: سبب الاختيار، الإشارات المطابقة، نوع primary/modifier، قرار reuse/extend/replace/build، الأجهزة والأدوار، والاستثناءات ونتائج القبول.
