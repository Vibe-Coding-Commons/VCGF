# Smart Screen Composition Selection

## القاعدة
يفهم الوكيل هدف الشاشة وسياق المستخدم أولًا، ثم يختار **تركيبًا أساسيًا واحدًا كحد أقصى** من كتالوج `VCGF-UI-SCR-*`. يمكن إضافة Modifiers فقط عند وجود إشارات صريحة. لا يعني وجود مكونات معينة أن تركيبًا معينًا مطلوب.

## الترتيب
1. اقرأ `screen_purpose` و`composition_signals` والأجهزة والأدوار وتكرار المهمة وكثافة المعلومات.
2. اجمع التركيبات الأساسية المطابقة.
3. رتّبها حسب عدد الإشارات المطابقة ثم رتبة التخصص.
4. اختر أفضل مرشح. إذا تعادل مرشحان في أعلى الدرجة، اختر الأسبق رتبة وأصدر Review صريحًا بدل إخفاء الالتباس.
5. أضف Modifiers المطابقة فقط.
6. شغّل مصفوفة التوافق.
7. حل سياسات الكثافة والاستجابة والإجراءات دون تغيير الصلاحيات أو البيانات.
8. حمّل فقط وثيقة التركيب المختار والمعدلات والحوكمة اللازمة.

## عدم الاختيار
إذا لم توجد إشارة تركيب، لا يحمل الكتالوج كاملًا ولا يخترع قالبًا. يعيد `needs_review` أو `not_selected` حسب وجود UI وسياق المهمة.
