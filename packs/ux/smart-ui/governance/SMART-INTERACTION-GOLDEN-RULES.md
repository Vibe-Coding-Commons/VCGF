# Smart Interaction Golden Rules

1. **وظيفة قبل الشكل:** ابدأ بمهمة المستخدم لا بلقطة الواجهة.
2. **الأبسط الذي ينجز المهمة:** لا تستخدم مكوّنًا أو نمطًا ثقيلًا بلا قيمة.
3. **إعادة الاستخدام قبل الإنشاء:** افحص الموجود ودليله.
4. **المعيار قبل المكتبة:** العقد مستقل عن package أو framework.
5. **لا تحميل شامل:** لا تبنِ 36 مكوّنًا ولا 24 نمطًا ولا 20 تركيب شاشة في كل مشروع.
6. **افصل المكوّن عن السلوك:** وجود Form لا يعني Unsaved/Conflict تلقائيًا.
7. **الإشارات الصريحة فقط:** `signals` للمكونات و`interaction_signals` للأنماط و`composition_signals` لتركيب الشاشة.
8. **التبعيات علاقات مراجعة:** لا Auto-Activation.
9. **الخادم مصدر السلطة:** إخفاء زر أو نجاح الحالة المحلية لا يمثل تفويضًا أو Commit.
10. **الحالة النهائية تحتاج تأكيدًا:** لا تقل Saved/Submitted/Deleted قبل المصدر الموثوق.
11. **الطلبات المتأخرة لا تحكم الحاضر:** ألغها أو تجاهلها عند تغير السياق.
12. **Retry ليس آمنًا تلقائيًا:** الكتابة تحتاج Idempotency أو Reconciliation.
13. **Optimistic للأفعال المؤهلة فقط:** لا للمدفوعات أو التوقيع أو الأثر النهائي غير القابل للعكس.
14. **Confirmation حسب الخطر:** لا تؤكد كل شيء؛ استخدم Undo عندما يكون التراجع حقيقيًا وأنسب.
15. **Offline متطلب صريح:** لا تضف Queue محلية لمجرد احتمال فقد الشبكة.
16. **Conflict لا يدفن:** لا Last-write-wins صامت عندما قد يضيع عمل.
17. **Unsaved Changes يقيس التغيير الحقيقي:** لا تحذر بسبب Focus أو تنسيق مكافئ.
18. **Session Expiry لا يساوي Permission Revocation:** لكل منهما مسار تعاف مختلف.
19. **Step-up لا يمنح صلاحية:** يتحقق Authorization أولًا ثم مستوى المصادقة.
20. **Bulk له نطاق ثابت:** الصفحة، النتائج المرشحة، أو IDs صريحة؛ لا معنى غامض لـSelect All.
21. **Loading وEmpty وError حالات مختلفة:** لا تستخدم رسالة واحدة.
22. **Long-running يحتاج Job قابلًا للاستئناف:** لا Spinner لا نهائي.
23. **الوصولية جزء من آلة الحالة:** التركيز والإعلانات وحالات الخطأ ليست تحسينًا لاحقًا.
24. **RTL/LTR من البداية:** الحالة والقرار والترتيب الدلالي لا يعتمد left/right ثابتًا.
25. **لا تخزن الأسرار في Draft/Telemetry:** أقل بيانات لازمة فقط.
26. **الذكاء الاصطناعي يشرح قراره:** كل اختيار أو استثناء أو تعارض له سبب ودليل.
27. **Unknown ليس Not Applicable:** عدم المعرفة يستدعي `verify_first`.
28. **التقييم لا يعني التفعيل:** Recommended لا يثبت شيئًا دون قرار تنفيذ.
29. **التغيير قابل للتراجع:** Replace/Migration يحتاج خطة Rollback.
30. **لا ادعاء بلا دليل:** Runtime Acceptance تبقى `not_run` حتى الاختبار الفعلي.

31. **Composition لا يعني Activation:** تركيب الشاشة لا يفعّل مكوّنًا أو نمطًا تلقائيًا.
32. **Primary واحد:** لا تجمع Primary Archetypes متعددة بلا قرار صريح؛ استخدم Modifier أو Review.
33. **التكيف يحفظ المهمة:** Responsive/Adaptive UX يعيد الترتيب والكثافة ولا يغير معنى العملية أو يدفن الإجراء اللازم.
34. **الدور ليس صلاحية:** Role adaptation لا يمنح وصولًا ولا يوسع البيانات.
35. **المساحة ليست مبررًا للبيانات:** الشاشة الكبيرة لا تزيد نطاق البيانات الحساسة تلقائيًا.
