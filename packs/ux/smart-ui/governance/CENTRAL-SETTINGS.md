# حوكمة الإعدادات المركزية

## تصنيف الإعداد
افصل **سياسة الأمان والأعمال** عن **افتراضات المنشأة** وعن **تفضيل المستخدم** وعن **حالة الشاشة المؤقتة**. ليست كل خاصية في جدول الإعدادات قابلة للتحرير في لوحة الإدارة. القيمة مثل `scanPolicy` أو `defaultDecision` عقد أمان، بينما pageSize أو theme تفضيل محدود.

النطاق `system/tenant` يعني أن النظام يسمح للمسؤول بتخصيص مدروس داخل قيوده؛ لا يعني تفويض المستأجر لإلغاء القيد الأعلى. والنطاق `tenant/user` لا يمنح المستخدم حق تجاوز إعداد منشأة مقفل. يحدد Adapter قائمة سماح دقيقة للخصائص القابلة للتغيير.

## حسم القيمة الفعالة
1. افحص السياسة الإلزامية والقيم المسموحة والحدود والصلاحيات.
2. ابدأ بافتراضات النظام ثم المنشأة داخل الحدود.
3. طبّق تفضيلات المستخدم المسموح بها فقط.
4. طبّق حالة الشاشة المؤقتة على خصائص العرض المسموحة فقط.
5. أعد التحقق من النتيجة في الطبقة الموثوقة، وأرجع `effectiveValue` مع `source` و`locked` و`configRevision` عند ملاءمته.

هذه ليست عملية spread أو merge عمياء. القيم الأمنية تتقاطع مع القيود الأعلى ولا تستبدلها طبقة أقل. المصفوفات لا تجمع تلقائيًا لأن إضافة نوع ملف قد توسع الصلاحيات. `null` وغياب المفتاح و`false` معان مختلفة؛ تعرفها المخططات بوضوح.

## التخزين والعزل
إعداد المنشأة دائم في قاعدة بيانات أو خدمة تهيئة موثوقة. تفضيلات المستخدم مقيدة بمعرف المستخدم والمستأجر وإصدار المخطط. localStorage يجوز لتفضيلات عرض غير حساسة، ولا يعد المصدر الوحيد لسياسة عامة. عند تبديل الحساب أو المنشأة أزل cache السابق وما لا يجوز الاحتفاظ به.

## التعديل والانتشار
غيّر إعدادات حساسة بطلب مفوض مع expectedRevision ومعاينة أثر وسبب عند الحاجة. سجل السابق واللاحق والفاعل والوقت دون أسرار. انشر configRevision جديدًا وابطل cache الخاص بالنطاق. لا تعمم تغييرًا على كل المنشآت بسبب قيمة افتراضية مشتركة قابلة للكتابة.

## الإعدادات والأعمال التاريخية
تغيير تنسيق التاريخ أو ألوان الحالة أو الكثافة ليس ترحيل بيانات. تغيير قواعد تقريب مالي أو تكرار مواعيد أو انتقال حالة قد يغير المعنى ويحتاج قرار مجال وترحيلًا مستقلًا. لا تعيد كتابة وثيقة مقفلة أو موعد مؤكد أو سجل تدقيق بسبب تفضيل واجهة.

## أمثلة الحزمة
[مثال الإعدادات](../config/central-settings.example.json) يحتوي 288 إعدادًا موثقًا، لكنه في وضع `assessment-only` وقائمة التفعيل فارغة. بعض القيم مثل حجم الملف صفر أو سياسة التقريب `domain-defined` تعني ضرورة حسم سياسة قبل التنفيذ، لا قيمة إنتاج جاهزة. لا تثبت المثال كما هو في الإنتاج.

## اختبارات لازمة
تحقق من رفض override غير مسموح، وعدم تسرب تفضيل بين منشأتين، ومنع خفض ضابط أمني، واكتشاف conflict في تحديث التهيئة، ومهاجرة مخطط قديم، وعدم تغيير قيم الأعمال عند تبديل العرض. اجمع الدليل على القيمة الفعالة ومصدرها، لا لقطة شاشة فقط.

## Interaction Policies — v0.5.0

إعدادات المكونات تبقى في `config/central-settings.example.json`. سياسات أنماط التفاعل موجودة في `config/interaction-policy.example.json` بعدد 144 قيمة افتراضية تقييمية. لا يعني وجودها تفعيل الأنماط؛ `enabledInteractions` يجب أن يبقى فارغًا في نموذج assessment-only.


## Screen Orchestration Policies — v0.5.0

سياسات تركيب الشاشة موجودة في `config/screen-orchestration-policy.example.json`، بينما الإعدادات المرجعية المشتقة لكل Archetype في `screen-composition-catalog.json` بعدد **120**. وجودها لا يعني تفعيل أي Composition.

قواعد الحسم:
- لا يسمح إلا بـPrimary Composition واحد.
- Modifiers تحتاج إشارات صريحة.
- `densityPolicy` و`responsiveStrategy` وتفضيلات العرض لا توسع Authorization أو Data Scope.
- `roleAdaptation` يغير الأولوية والشرح والكثافة فقط ضمن المسموح.
- `mobileTransform` يحافظ على المهمة والمعلومات اللازمة، ولا يحذفها لتناسب المساحة.
- `largeScreenTransform` يستخدم المساحة لإظهار سياق أو مقارنة مفيدة، لا لتحميل بيانات حساسة إضافية أو تمديد المحتوى بلا حدود.

إجمالي القيم المرجعية في الطبقات الثلاث: **288 + 144 + 120 = 552**، لكنها ليست كلها إعدادات Admin قابلة للتحرير؛ بعضها عقود سياسة ثابتة أو افتراضات تقييمية.

## Journey Policies — v1.0.0

كل Journey Pattern يعرّف 6 سياسات مرجعية: `entryPolicy`, `completionPolicy`, `returnPolicy`, `contextPreservation`, `authorizationRecheck`, `telemetryMode`. المجموع **108** سياسة عبر 18 رحلة. لا تعد هذه السياسات global activation؛ تطبق فقط على رحلة مختارة.

## Final Reference Count

288 Component Settings + 144 Interaction Policies + 120 Screen Composition Policies + 108 Journey Policies = **660** إعدادًا/سياسة مرجعية.
