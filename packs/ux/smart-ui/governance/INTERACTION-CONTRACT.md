# عقد نمط التفاعل — Interaction Pattern Contract

كل نمط داخل `interaction-catalog.json` يجب أن يعرّف:

1. معرفًا ثابتًا `VCGF-UI-INT-NNN`.
2. الهدف ومتى ينطبق ومتى لا ينطبق.
3. إشارات اكتشاف صريحة.
4. مخطط حالة مرجعي يميز الحالات التي تؤثر في القرار.
5. مصدر السلطة والحدود بين UI والخادم والهوية والتخزين المحلي.
6. إعدادات أو سياسات مركزية لا تسمح لتفضيل المستخدم بتخفيف الأمان.
7. حالات الفشل والتعافي والاستجابات المتأخرة.
8. صلاحيات وإعادة تحقق عند الأثر.
9. إمكانية الوصول وإدارة التركيز.
10. التعريب وRTL/LTR والاستجابة.
11. الأداء والمراقبة والتدقيق.
12. متطلبات وحالات قبول قابلة للتتبع.

**قاعدة:** Pattern ليس API جاهزًا ولا مكتبة JavaScript. الـAdapter يترجم العقد للتقنية الحالية.

## Existing Behavior

قبل تنفيذ Pattern جديد، افحص السلوك الموجود. القرار المفضل:
`reuse → extend → wrap → replace → build_new`

وعند نقص الدليل:
`verify_first`

إعادة الاستخدام تحتاج دليلًا يثبت أن السلوك الحالي يحقق الحالة والفشل والسلطة، وليس مجرد تشابه مرئي.
