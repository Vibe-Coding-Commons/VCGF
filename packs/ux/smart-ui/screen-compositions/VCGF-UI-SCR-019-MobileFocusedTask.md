# مُعدّل المهمة المحمولة المركزة

**المعرّف:** `VCGF-UI-SCR-019`  
**الدور:** `modifier` — مُعدّل يركب فوق تركيب أساسي عند وجود دليل

## 1. الهدف ونطاق التطبيق

تكييف شاشة قائمة أو سجل أو نموذج لتصبح مناسبة لمهمة ميدانية/محمولة قصيرة دون إنشاء نسخة أعمال مختلفة.

**ينطبق عندما:** عندما يكون الهاتف أو الجهاز اللوحي هو السطح الأساسي والمهمة تتطلب استخدامًا سريعًا أو ميدانيًا أو بيد واحدة نسبيًا.

**لا ينطبق عندما:** لا يفعّل لمجرد دعم Responsive؛ يلزم أن يكون الاستخدام المحمول أولوية حقيقية.

## 2. إشارات الاكتشاف والاختيار

الإشارات المرجعية: `mobile_focused_task`, `field_task`, `mobile_primary`. هذه إشارات دليل وليست أسماء مسارات إلزامية. لا يفترض المعيار أن وجود مكوّن مرتبط يعني اختيار هذا التركيب.

## 3. بنية الشاشة المرجعية

إجراء أساسي واحد واضح، معلومات ضرورية أولًا، عناصر لمس مناسبة، تقليل الحقول المتجاورة، والحفاظ على الاستمرارية عند انقطاع الشبكة إن كانت مطلوبة.

البنية مرجع وظيفي؛ يجوز حذف أو إعادة ترتيب المناطق وفق المهمة، لكن لا يجوز كسر تسلسل القراءة أو إخفاء متطلبات القرار.

## 4. هرمية المعلومات والإجراءات

ابدأ بالهوية والهدف والحالة الحالية ثم المعلومات اللازمة للمهمة ثم التفاصيل الثانوية. الإجراء الأساسي واحد افتراضيًا في كل منطقة عمل، وتفصل الإجراءات الخطرة عن الإجراءات العادية.

## 5. التكيف حسب الدور والسياق

تكييف الدور يغير الأولوية والكثافة والشرح فقط ضمن البيانات والقدرات المصرح بها. يمنع استخدام الدور في الواجهة كمصدر صلاحية أو كبديل لفحص الخادم.

## 6. Responsive وAdaptive UX

هذا المعيار نفسه هو Modifier؛ لا يغير قواعد الأعمال ولا يخفي معلومات لازمة للصلاحية أو القرار.

يجب اختبار الهاتف والتابلت وسطح المكتب والشاشات الكبيرة عندما تكون ضمن نطاق المشروع. التحول بين المقاسات يحافظ على الهدف وسياق المهمة ولا يشترط بقاء نفس الترتيب البصري.

## 7. الحالات والانتقالات

يجب تغطية Ready وLoading وEmpty وError وPartial/Stale وSubmitting/Processing عندما تنطبق، وربطها بأنماط التفاعل المختارة بدل إنشاء سلوك محلي متكرر.

## 8. المكونات وأنماط التفاعل للمراجعة

**مكونات للمراجعة فقط:** `VCGF-UI-COMP-009`, `VCGF-UI-COMP-008`.

**أنماط تفاعل للمراجعة فقط:** `VCGF-UI-INT-015`, `VCGF-UI-INT-024`.

هذه العلاقات لا تفعل أي مكوّن أو نمط تلقائيًا؛ محركات الاختيار المستقلة تحتاج إشاراتها الخاصة.

## 9. سياسات التركيب المركزية

- `densityPolicy` — النوع `string` — الافتراضي `adaptive` — النطاق `system/tenant/user` — adaptive أو comfortable أو compact ضمن حدود الوصولية ولا يغيّر صلاحيات أو بيانات.
- `primaryActionLimit` — النوع `integer` — الافتراضي `1` — النطاق `system/tenant` — عدد الإجراءات الأساسية المرئية في المنطقة الواحدة؛ أي استثناء يبرر بالمهمة.
- `progressiveDisclosure` — النوع `boolean` — الافتراضي `true` — النطاق `system/tenant` — يخفي التعقيد الثانوي لا المعلومات اللازمة لاتخاذ القرار أو إكمال المهمة.
- `mobileTransform` — النوع `string` — الافتراضي `task-preserving-reflow` — النطاق `system/tenant` — reflow أو list-detail أو stacked-panels حسب العقد؛ لا تصغير حرفي لسطح المكتب.
- `largeScreenTransform` — النوع `string` — الافتراضي `context-expansion` — النطاق `system/tenant` — توسيع السياق أو المقارنة بدل تمديد الحقول/النص بلا حدود.
- `roleAdaptation` — النوع `string` — الافتراضي `priority-only` — النطاق `system/tenant` — يغير ترتيب/إبراز المعلومات المصرح بها فقط؛ لا يمنح ولا يسحب صلاحية ولا يغير حقيقة الأعمال.

## 10. المتطلبات الإلزامية

<a id="VCGF-UI-SCR-019-R01"></a>
### VCGF-UI-SCR-019-R01 — اختيار قائم على نية الشاشة

لا يُختار هذا التركيب من اسم المسار أو شكل سابق فقط. يلزم وجود إشارات سياق تطابق: mobile_focused_task, field_task, mobile_primary. عند غياب الدليل يعاد تقييم السياق بدل فرض القالب.
<a id="VCGF-UI-SCR-019-R02"></a>
### VCGF-UI-SCR-019-R02 — هيكل المعلومات

يبنى الهيكل حول هدف المستخدم: تكييف شاشة قائمة أو سجل أو نموذج لتصبح مناسبة لمهمة ميدانية/محمولة قصيرة دون إنشاء نسخة أعمال مختلفة. ويستخدم البنية المرجعية: إجراء أساسي واحد واضح، معلومات ضرورية أولًا، عناصر لمس مناسبة، تقليل الحقول المتجاورة، والحفاظ على الاستمرارية عند انقطاع الشبكة إن كانت مطلوبة. مع حذف المناطق غير اللازمة للمهمة.
<a id="VCGF-UI-SCR-019-R03"></a>
### VCGF-UI-SCR-019-R03 — هرمية الإجراءات

يجب تحديد إجراء أساسي واحد في السياق الواحد متى كان هناك إجراء مهيمن، وفصل الإجراءات الثانوية والخطرة بصريًا ودلاليًا. لا يساوي ترتيب الأزرار صلاحية التنفيذ.
<a id="VCGF-UI-SCR-019-R04"></a>
### VCGF-UI-SCR-019-R04 — الفصل بين الصلاحية والتقديم

أي إخفاء أو إظهار أو ترتيب حسب الدور هو قرار عرض فوق صلاحية موثوقة من الخادم. لا يسمح للتخصيص أو Role Adaptation بمنح فعل غير مصرح أو إخفاء معلومة لازمة قانونيًا/تشغيليًا.
<a id="VCGF-UI-SCR-019-R05"></a>
### VCGF-UI-SCR-019-R05 — التكيّف مع الهاتف

يطبق التحول المتجاوب بما يحافظ على المهمة لا شكل سطح المكتب. هذا المعيار نفسه هو Modifier؛ لا يغير قواعد الأعمال ولا يخفي معلومات لازمة للصلاحية أو القرار.
<a id="VCGF-UI-SCR-019-R06"></a>
### VCGF-UI-SCR-019-R06 — الاستفادة من الشاشات الكبيرة

عند توفر عرض كبير يستفاد منه لإظهار سياق إضافي أو مقارنة أو معاينة ذات قيمة. يمنع تمديد السطور والحقول والجداول دون حد أو إنشاء فراغات/كثافة غير مفيدة.
<a id="VCGF-UI-SCR-019-R07"></a>
### VCGF-UI-SCR-019-R07 — الكثافة والإفصاح التدريجي

تضبط كثافة المعلومات وفق تكرار المهمة وخبرة المستخدم وحجم الشاشة. يستخدم الإفصاح التدريجي للتفاصيل الثانوية فقط، ولا يخفي المتطلبات أو الأخطاء أو أسباب القرار.
<a id="VCGF-UI-SCR-019-R08"></a>
### VCGF-UI-SCR-019-R08 — الحالات الفارغة والتحميل والخطأ

يجب أن تملك الشاشة حالات Loading وEmpty وError وPartial/Stale حيث تنطبق، مع انتقالات مفهومة وإجراء تعافٍ. لا تستبدل الخطأ بحالة Empty ولا Skeleton دائم.
<a id="VCGF-UI-SCR-019-R09"></a>
### VCGF-UI-SCR-019-R09 — الحفاظ على السياق

يحافظ التنقل والتحديث والعودة على الفلاتر والموضع والاختيار والمسودة عندما يكون ذلك جزءًا من المهمة، مع احترام سياسات الخصوصية والجلسة.
<a id="VCGF-UI-SCR-019-R10"></a>
### VCGF-UI-SCR-019-R10 — الوصولية والاتجاه واللغة

يلتزم التركيب بلوحة المفاتيح وقارئات الشاشة والتباين وحركة مخفضة وRTL/LTR وترجمة النصوص. الترتيب المرئي لا يجوز أن يكسر ترتيب القراءة أو التركيز.
<a id="VCGF-UI-SCR-019-R11"></a>
### VCGF-UI-SCR-019-R11 — الأداء والبيانات

لا يستخدم تركيب بصري لتبرير تحميل بيانات غير لازمة. تظل Pagination/Virtualization/Server Filtering/Chunking قرارات بيانات مستقلة تُختار حسب الحجم والمهمة.
<a id="VCGF-UI-SCR-019-R12"></a>
### VCGF-UI-SCR-019-R12 — القياس والتحقق

يُختبر نجاح التركيب بقياس إكمال المهمة والأخطاء والاسترداد لا بالانطباع البصري فقط. تبقى اختبارات التطبيق الفعلية not_run حتى التنفيذ وجمع دليل.

## 11. معايير القبول

<a id="VCGF-UI-SCR-019-AC01"></a>
### VCGF-UI-SCR-019-AC01 — اختيار صحيح

**Given** سياق شاشة يحمل واحدة على الأقل من إشارات mobile_focused_task, field_task, mobile_primary **When** يعمل محرك التركيب **Then** يظهر VCGF-UI-SCR-019 كمرشح/اختيار حسب القواعد دون تحميل تراكيب أخرى بلا إشارة.
<a id="VCGF-UI-SCR-019-AC02"></a>
### VCGF-UI-SCR-019-AC02 — لا اختيار بلا دليل

**Given** سياق لا يحمل أي إشارة لهذا التركيب **When** يعمل المحرك **Then** لا يُختار VCGF-UI-SCR-019 لمجرد تشابه الاسم أو وجود مكونات مرتبطة.
<a id="VCGF-UI-SCR-019-AC03"></a>
### VCGF-UI-SCR-019-AC03 — الإجراء الأساسي

**Given** شاشة لها عدة إجراءات **When** تُركب الواجهة **Then** يظهر الإجراء الأساسي بوضوح وتبقى الإجراءات الخطرة منفصلة ولا يتجاوز العدد المرئي السياسة دون استثناء موثق.
<a id="VCGF-UI-SCR-019-AC04"></a>
### VCGF-UI-SCR-019-AC04 — الصلاحيات

**Given** اختلاف دور المستخدم **When** تتكيف الأولوية **Then** لا تظهر أي قدرة غير مصرح بها ويعاد التحقق من السلطة عند التنفيذ.
<a id="VCGF-UI-SCR-019-AC05"></a>
### VCGF-UI-SCR-019-AC05 — الهاتف

**Given** عرض هاتف فعلي **When** تُعرض الشاشة **Then** يحافظ Reflow على المهمة وترتيب القراءة ولا يعتمد على تصغير تخطيط سطح المكتب أو تمرير أفقي غير ضروري.
<a id="VCGF-UI-SCR-019-AC06"></a>
### VCGF-UI-SCR-019-AC06 — الشاشة الكبيرة

**Given** شاشة كبيرة **When** تتوفر مساحة إضافية **Then** تستخدم للسياق أو المقارنة المفيدة ولا تمتد النصوص/الحقول إلى عرض يضعف القراءة.
<a id="VCGF-UI-SCR-019-AC07"></a>
### VCGF-UI-SCR-019-AC07 — الكثافة

**Given** محتوى ثانوي كبير **When** يستخدم Progressive Disclosure **Then** تبقى المعلومات اللازمة للقرار والأخطاء والمتطلبات ظاهرة أو قابلة للوصول دون غموض.
<a id="VCGF-UI-SCR-019-AC08"></a>
### VCGF-UI-SCR-019-AC08 — الحالات

**Given** Loading أو Empty أو Error أو Stale **When** تتغير حالة البيانات **Then** تميز الواجهة الحالة الصحيحة وتوفر تعافيًا مناسبًا دون فقد السياق.
<a id="VCGF-UI-SCR-019-AC09"></a>
### VCGF-UI-SCR-019-AC09 — السياق

**Given** عودة المستخدم من تفاصيل/إجراء **When** يعود للشاشة **Then** تستعاد حالة المهمة المسموح بها وفق سياسة Navigation Context.
<a id="VCGF-UI-SCR-019-AC10"></a>
### VCGF-UI-SCR-019-AC10 — الوصولية

**Given** العربية والإنجليزية ولوحة المفاتيح وقارئ شاشة **When** تُستخدم الشاشة **Then** يبقى ترتيب التركيز والقراءة والاتجاه والتسميات صالحًا.
<a id="VCGF-UI-SCR-019-AC11"></a>
### VCGF-UI-SCR-019-AC11 — الأداء

**Given** بيانات كبيرة أو بطيئة **When** تُحمّل الشاشة **Then** لا يتم تحميل مجموعات غير لازمة فقط لأن التخطيط يستطيع عرضها.
<a id="VCGF-UI-SCR-019-AC12"></a>
### VCGF-UI-SCR-019-AC12 — الأدلة

**Given** تنفيذ فعلي **When** يُعلن اجتياز هذا التركيب **Then** يوجد دليل Acceptance مرتبط ولا تعتبر اختبارات الوثائق بديلًا عن اختبار التطبيق.

## 12. مضادات الأنماط والحالات الحدية

- لا تحول كل شاشة إلى Dashboard أو Cards لمجرد الجمال.
- لا تستخدم تعدد الأعمدة لملء المساحة فقط.
- لا تخف معلومات لازمة لإكمال المهمة تحت Progressive Disclosure.
- لا تجعل الهاتف نسخة مصغرة من سطح المكتب.
- لا تجعل الشاشات الكبيرة ذريعة لزيادة كثافة غير مقروءة.
- لا تخلط التخصيص بالصلاحيات أو حقيقة البيانات.
- لا تعتبر وجود المكونات المرتبطة دليلًا على وجوب هذا التركيب.

## 13. دليل التنفيذ والتتبع

قبل اعتماد التنفيذ يجب تسجيل سبب اختيار التركيب، سياق الأجهزة والأدوار، المكونات والأنماط المختارة بصورة مستقلة، نتائج الاختبارات، والاستثناءات. حالة اختبارات التطبيق في هذه الحزمة `not_run` حتى يطبق المعيار في منتج حقيقي.
