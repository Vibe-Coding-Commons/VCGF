# VCGF-UI-COMP-004 - البحث والفلاتر المحفوظة

**AdvancedFilterBuilder**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

جعل نطاق النتائج مفهومًا وقابلًا للتكرار والمشاركة المصرح بها، بدل مجموعة فلاتر تخفي سبب ظهور البيانات أو تغيّر معنى الاستعلام بين الشاشات.

**متى ينطبق:** ينطبق على قوائم تحتاج أكثر من معيار بحث أو طرق عرض متكررة. يدعم فلاتر بسيطة أولًا، ثم مجموعات AND وOR فقط عند الحاجة المؤكدة.

**متى لا ينطبق:** لا يضيف محرر شروط متداخلًا إلى بحث بسيط، ولا يسمح بكتابة SQL أو أسماء أعمدة حرة، ولا يضع استعلامات حساسة تلقائيًا في عنوان الصفحة.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `debounceMs` | `integer` | `300` | `system/tenant` | اقتراح قابل للقياس للبحث الخارجي؛ ليس تأخيرًا إلزاميًا للبحث المحلي. |
| `applyMode` | `string` | `"explicit"` | `tenant/user` | live مناسب للبحث الخفيف؛ explicit للمرشحات المركبة أو المكلفة. |
| `urlSync` | `string` | `"allowlisted"` | `system` | لا تدرج بيانات حساسة أو معرفات محمية في URL بلا سياسة. |
| `savedViews` | `boolean` | `true` | `tenant` | الحفظ الشخصي افتراضيًا؛ المشاركة تتطلب صلاحية مستقلة. |
| `defaultOperator` | `string` | `"AND"` | `system/tenant` | تعريف صريح؛ لا تبدّل المعنى بصريًا دون تعديل الاستعلام. |
| `maxDepth` | `integer` | `3` | `system/tenant` | حد اقتراحي لتعقيد الشروط يطابق حدود الخادم. |
| `maxRules` | `integer` | `20` | `system/tenant` | منع الاستعلامات المفرطة؛ يُضبط حسب المجال. |
| `persistSensitiveSearch` | `boolean` | `false` | `system` | عدم حفظ كلمات البحث الحساسة في history أو localStorage. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-004-R01"></a>
### VCGF-UI-COMP-004-R01 - سجل حقول وعوامل

عرّف لكل حقل نوعه والعوامل المسموحة ومصدر خياراته وصلاحية استخدامه. النصوص والأرقام والتواريخ لا تتشارك عوامل غير ملائمة، ويُرفض العامل أو الحقل غير المسجل في الخادم.

<a id="VCGF-UI-COMP-004-R02"></a>
### VCGF-UI-COMP-004-R02 - قيد ظاهر

اعرض الفلاتر النشطة كشرائح أو ملخص مقروء، مع العدد وأزرار إزالة مفردة وإعادة ضبط. يعيد reset إعدادات العرض الافتراضية المعلنة ولا يزيل حدود صلاحيات الخادم.

<a id="VCGF-UI-COMP-004-R03"></a>
### VCGF-UI-COMP-004-R03 - قيمة محفوظة ومعنى ثابت

طرق العرض المحفوظة تخزن مخطط الاستعلام وإصداره ومعرفات الخيارات لا تسمياتها المترجمة فقط. عند حذف حقل أو تغيير صلاحيته تُنبّه إلى عدم صلاحية العرض بدل إسقاط الشرط بصمت.

<a id="VCGF-UI-COMP-004-R04"></a>
### VCGF-UI-COMP-004-R04 - الزمن نطاق مضبوط

استخدم معيار التاريخ المركزي، وحوّل الحدود المحلية إلى نطاق مقارنات واضح في الخادم. عرف شمول البداية والنهاية وتفضيل النطاق نصف المفتوح للأوقات عند مناسبته.

<a id="VCGF-UI-COMP-004-R05"></a>
### VCGF-UI-COMP-004-R05 - مقاومة الطلبات القديمة

ألغِ الطلب السابق أو تجاهل استجابته عند تغير query revision، وأعد الترقيم إلى نقطة صالحة. لا تُعلن نتائج قديمة تخص فلاتر مختلفة كأنها حديثة.

<a id="VCGF-UI-COMP-004-R06"></a>
### VCGF-UI-COMP-004-R06 - روابط آمنة

زامن الحالة غير الحساسة مع URL بقائمة سماح وترميز ثابت. الاستعلامات الحساسة تستخدم مرجعًا آمنًا عند الحاجة بدل نص في التاريخ أو سجلات الويب، وتراجع صلاحيات الرابط عند فتحه.

<a id="VCGF-UI-COMP-004-R07"></a>
### VCGF-UI-COMP-004-R07 - مشاركة طرق العرض

افصل personal وteam وtenant، مع مالك وإصدار وأذونات تعديل. مشاركة تعريف الفلتر لا تمنح صلاحية البيانات التي يشير إليها، ولا يظهر عدد غير مصرح به في الملخص.

<a id="VCGF-UI-COMP-004-R08"></a>
### VCGF-UI-COMP-004-R08 - تعقيد مفهوم

استخدم قيمًا افتراضية مناسبة وتلميحات أمثلة، واعرض صياغة مفهومة للـAND وOR والتداخل. عند تجاوز التعقيد أو انتهاء المهلة قدم طريقة تبسيط بدل إعادة المحاولة بلا حد.

<a id="VCGF-UI-COMP-004-R09"></a>
### VCGF-UI-COMP-004-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-004-R10"></a>
### VCGF-UI-COMP-004-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-004-R11"></a>
### VCGF-UI-COMP-004-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-004-R12"></a>
### VCGF-UI-COMP-004-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `fieldRegistry`, `filterAST`, `schemaVersion`, `activeView`, `permissions`, `resultState`

**الأحداث المفاهيمية:** `filterEdited`, `applyRequested`, `resetRequested`, `viewSaved`, `shareRequested`

**مصدر السلطة:** الخادم يفسر AST المسجل ويطبق النطاق والصلاحيات؛ الواجهة تعرض وتحرر الاستعلام المسموح.

```text
draft -> validating -> applied -> loading -> results/empty/error
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`, `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- مثل الفلتر كشجرة AST محدودة وأنشئ الاستعلام بمعاملات مربوطة؛ لا تقبل أسماء أعمدة أو ترتيب حر من العميل.
- تعالج null والقيم الفارغة كعوامل واضحة لا كمطابقة نصية مضللة.
- الاستعلام الحي لا يبدأ أثناء IME composition ثم يعتمد النص المكتمل.
- يشمل cache تعريف الفلتر ومراجعة الصلاحيات والمستأجر؛ لا يشارك بين مستخدمين دون ضمان النطاق.
- حدّد سياسة count التقريبي أو غير المتاح؛ لا تعرض رقمًا دقيقًا مزعومًا عند عدم حسابه.

## 6. الوصولية والعربية والتجاوب

- لكل شريحة زر إزالة باسم يذكر الفلتر، ولا يكتفى بأيقونة ×.
- عند إزالة فلتر يعود التركيز إلى موضع منطقي ولا يختفي داخل DOM محذوف.
- على الهاتف تظهر لوحة الفلاتر مع زر تطبيق واضح وتعود النتائج إلى موضع مفهوم بعد الإغلاق.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- تغيير اللغة لا يغير معرف الحالة ولا معنى الفلتر المحفوظ.
- توقف خدمة الخيارات لا يحذف الشروط المخزنة؛ يوضح تعذر تحميل التسميات.
- استعادة رابط قديم بإصدار مخطط غير مدعوم تنتج مسار ترحيل أو رفضًا آمنًا لا تجاهلًا صامتًا.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [TanStack Query / @tanstack/react-query](https://tanstack.com/query/latest/docs/framework/react/overview) | تنسيق حالة البيانات والطلبات وcache وإعادة الجلب. | اضبط query keys وإبطال البيانات حسب المستأجر والصلاحيات؛ ليست محرك تفويض أو قاعدة بيانات. |
| [nuqs](https://nuqs.dev/) | ربط حالة غير حساسة بمعلمات البحث في URL مع أنواع واضحة. | تحتاج مراجعة adapter الخاص بإطار المشروع وقائمة سماح؛ لا تضع بيانات شخصية في الرابط تلقائيًا. |
| [shadcn/ui](https://ui.shadcn.com/docs/components) | مكوّنات قابلة للتخصيص ضمن نظام تصميم React مناسب. | افحص primitive والبنية في الإصدار الفعلي؛ لا تفترض أن كل Combobox يضع البحث داخل النافذة، ولا تثبّت كل المكوّنات دفعة واحدة. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **يجب أن يعرف المستخدم سبب ظهور النتائج وكيف يعود للنطاق السابق.**
- **مشاركة فلتر لا تشارك صلاحيات البيانات.**
- **لا تسقط شرطًا غير صالح بصمت؛ فقد يوسع الاستعلام على نحو خطير.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-004 / AdvancedFilterBuilder - البحث والفلاتر المحفوظة.
جعل نطاق النتائج مفهومًا وقابلًا للتكرار والمشاركة المصرح بها، بدل مجموعة فلاتر تخفي سبب ظهور البيانات أو تغيّر معنى الاستعلام بين الشاشات.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: يجب أن يعرف المستخدم سبب ظهور النتائج وكيف يعود للنطاق السابق. مشاركة فلتر لا تشارك صلاحيات البيانات. لا تسقط شرطًا غير صالح بصمت؛ فقد يوسع الاستعلام على نحو خطير.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: جهز فلتر معاملات بالتاريخ والحالة والمسؤول مع عرض محفوظ مشترك، واختبر اختلاف الصلاحيات وتغيير اللغة وفشل خدمة الخيارات ووصول استجابة قديمة.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.

- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
