# VCGF-UI-COMP-024 - التبويبات والأقسام القابلة للطي واللوحات المقسمة

**AdaptiveContentPanels**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تنظيم المعلومات المتوازية أو التفصيلية مع الحفاظ على حالة المستخدم وإمكانية الوصول، دون استخدام التبويبات لإخفاء بنية شاشة غير مفهومة أو أخطاء يجب علاجها.

**متى ينطبق:** ينطبق على أقسام متوازية مثل البيانات والمرفقات والسجل، أو تفاصيل يمكن كشفها تدريجيًا، أو عرض قائمة وتفاصيل بجوار بعضهما.

**متى لا ينطبق:** لا يستخدم tabs لتدفق يجب إكماله بالتتابع، ولا accordion لإخفاء تحذير حرج، ولا split view عندما يجعل كلا الجزأين غير مقروءين.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `panelPattern` | `string` | `"task-based"` | `system` | tabs أو accordion أو split بحسب العلاقة بين المحتوى. |
| `tabActivation` | `string` | `"manual-when-latent"` | `system` | التفعيل التلقائي فقط إذا كان العرض فوريًا ولا يسبب انتظارًا مع كل سهم. |
| `persistActivePanel` | `boolean` | `true` | `tenant/user` | يحفظ المعرف ضمن السياق ولا يفتح محتوى غير مفوض. |
| `urlSync` | `boolean` | `true` | `system/tenant` | لأقسام مفيدة كرابط مباشر؛ لا يضع قيم نماذج حساسة في الرابط. |
| `mountPolicy` | `string` | `"preserve-data-lazy-view"` | `system` | يمكن إزالة الرندر مع بقاء حالة النموذج في موضع مستقل. |
| `allowMultipleExpanded` | `boolean` | `true` | `tenant/user` | مناسب لمقارنة المحتوى؛ قد يقيّد عند تصميم معلوم. |
| `resizablePanels` | `boolean` | `false` | `system/tenant` | يفعّل مع حد أدنى وحالة محفوظة وبديل لوحة مفاتيح. |
| `mobileFallback` | `string` | `"contextual-single-pane"` | `system` | قائمة ثم تفاصيل أو accordion وفق المهمة دون فقد المحتوى. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-024-R01"></a>
### VCGF-UI-COMP-024-R01 - نمط يعكس العلاقة

استخدم tabs لمحتوى متوازٍ وaccordion لكشف تفاصيل وsplit لعمل يحتاج رؤيتين متزامنتين. عندما يكون المطلوب ترتيب إنجاز استخدم wizard بدل تبويبات توهم حرية الانتقال.

<a id="VCGF-UI-COMP-024-R02"></a>
### VCGF-UI-COMP-024-R02 - هوية وروابط

لكل قسم معرف ثابت وتسمية مترجمة، ويدعم الرابط المباشر عندما يكون مفيدًا. رابط قسم غير متاح يعرض fallback مفهومًا ولا يكشف محتواه أو يغيّر القيمة المختارة إلى قسم حساس.

<a id="VCGF-UI-COMP-024-R03"></a>
### VCGF-UI-COMP-024-R03 - حالة محفوظة

تبديل القسم لا يمحو حقولًا dirty أو يكرر رفع مرفقات. افصل حالة البيانات عن mount/unmount المرئي، واحسم ما إذا كان الحفظ يغطي قسمًا أم النموذج كله.

<a id="VCGF-UI-COMP-024-R04"></a>
### VCGF-UI-COMP-024-R04 - أخطاء غير مخفية

عند وجود خطأ في قسم غير نشط اعرض مؤشرًا ذا معنى وملخصًا ينقله إلى موضعه. لا تسمح برسالة راجع الأخطاء بينما لا يرى المستخدم أي حقل متأثر.

<a id="VCGF-UI-COMP-024-R05"></a>
### VCGF-UI-COMP-024-R05 - تحميل كسول صادق

حمل محتوى القسم عند الحاجة دون فقد السياق، وميز تحميله من غياب بياناته. لا تفعّل tabs تلقائيًا مع كل سهم إذا كان ذلك يطلق طلبات بطيئة أو يشتت المستخدم.

<a id="VCGF-UI-COMP-024-R06"></a>
### VCGF-UI-COMP-024-R06 - لوحات قابلة للتحجيم

عند split view وفر حدودًا دنيا وقيمًا محفوظة وإعادة ضبط، مع فاصل قابل للوحة المفاتيح ومسمى. لا يسمح السحب بإخفاء جزء أساسي بلا وسيلة استعادته.

<a id="VCGF-UI-COMP-024-R07"></a>
### VCGF-UI-COMP-024-R07 - تكيّف بلا إسقاط

على الهاتف استخدم صفحة واحدة أو قائمة وتفاصيل أو accordion بحسب المهمة. لا تحذف أقسامًا أو إجراءات لتلائم العرض، واحتفظ بالاختيار والبيانات عند تغيير الاتجاه أو المقاس.

<a id="VCGF-UI-COMP-024-R08"></a>
### VCGF-UI-COMP-024-R08 - صلاحيات وتنظيف

القسم المحجوب لا يُحمّل بياناته خلف الكواليس لمجرد أنه غير ظاهر. تغير الصلاحية يزيل بياناته المؤقتة ويختار قسمًا آمنًا، ولا يجعل cache الباقي منفذًا للوصول.

<a id="VCGF-UI-COMP-024-R09"></a>
### VCGF-UI-COMP-024-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-024-R10"></a>
### VCGF-UI-COMP-024-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-024-R11"></a>
### VCGF-UI-COMP-024-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-024-R12"></a>
### VCGF-UI-COMP-024-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `panels`, `activePanelId`, `expandedIds`, `layoutSizes`, `dirtyState`, `capabilities`, `loadingStates`

**الأحداث المفاهيمية:** `panelActivated`, `sectionExpanded`, `layoutResized`, `resetRequested`, `hiddenErrorRevealed`

**مصدر السلطة:** بيانات الأقسام والصلاحيات من خدماتها؛ تنظيم العرض لا يغير محتواها أو قواعد حفظها.

```text
ready -> panel-loading -> panel-ready/error; dirty data persists across view switches
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-003](VCGF-UI-COMP-003-SmartFormFields.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-009](VCGF-UI-COMP-009-AdaptiveNavigation.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

## 5. النقاط الهندسية وحدود المسؤولية

- ربط tabId بالمخطط لا بالفهرس؛ إعادة ترتيب الأقسام لا تبدّل معنى الرابط المحفوظ.
- keepMounted ليس حلًا وحيدًا للحفاظ على البيانات؛ قد يضاعف DOM وكلفة الرندر، فافصل البيانات عن العرض.
- ضع query keys لكل قسم وسجل ونطاق تفويض، وامنع استجابة قديمة من تعبئة قسم سجل جديد.
- لا تستخدم أدوار tab وtabpanel لأزرار تنقل صفحات عادية إلا إذا طابق التفاعل النمط.
- حفظ نسب split view يمر بحدود min/max وإصدار layout حتى لا يعيد إعداد قديم واجهة غير قابلة للاستخدام.

## 6. الوصولية والعربية والتجاوب

- tabs بنمط لوحة مفاتيح وaria-selected وعلاقة panel سليمة؛ accordion بأزرار headings وaria-expanded.
- فاصل resize له اسم وقيمة وحدود وبديل للوحة المفاتيح عندما تكون الخاصية مفعلة.
- اختبر ترتيب القراءة وإخفاء المحتوى من شجرة الوصول عندما لا يكون مرئيًا وتفعيل التركيز عند الكشف.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- إزالة تبويب نشط ديناميكيًا تختار جاره أو القسم الافتراضي المسموح وتعيد التركيز.
- عناوين طويلة لا تجعل التبويبات المخفية غير قابلة للوصول؛ وفر تمريرًا أو قائمة مناسبة.
- الطباعة أو التصدير يحددان صراحة الأقسام المشمولة ولا يطبعان الظاهر فقط إن كان المقصود السجل كله.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [Radix UI Primitives](https://www.radix-ui.com/primitives/docs/components) | عناصر تفاعل غير منسقة تشمل Dialog وPopover وTabs وDropdown Menu. | اختبار التركيب وإدارة التركيز يظل مطلوبًا؛ اختيارها لا يمنح التطبيق شهادة وصولية تلقائية. |
| [React Aria Components](https://react-aria.adobe.com/Tree) | بديل لمكوّنات تفاعلية مع اهتمام بالدلالات ولوحة المفاتيح. | اختر النمط الموافق للبنية ولا تركب primitives متضاربة؛ راجع وثائق المكوّن والإصدار المستعمل. |
| [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels) | لوحات قابلة لتغيير الحجم في React. | اختبر الفاصل باللمس ولوحة المفاتيح وحدود الأحجام وحفظ التخطيط قبل الاعتماد. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **التنظيم لا يبرر إخفاء أخطاء أو معلومات يحتاجها القرار.**
- **تغيير القسم لا يمحو العمل.**
- **عندما تزيد التبويبات الغموض أعد تصميم بنية الشاشة لا عدد التبويبات فقط.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-024 / AdaptiveContentPanels - التبويبات والأقسام القابلة للطي واللوحات المقسمة.
تنظيم المعلومات المتوازية أو التفصيلية مع الحفاظ على حالة المستخدم وإمكانية الوصول، دون استخدام التبويبات لإخفاء بنية شاشة غير مفهومة أو أخطاء يجب علاجها.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: التنظيم لا يبرر إخفاء أخطاء أو معلومات يحتاجها القرار. تغيير القسم لا يمحو العمل. عندما تزيد التبويبات الغموض أعد تصميم بنية الشاشة لا عدد التبويبات فقط.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: جهز شاشة بيانات ومرفقات وسجل مع خطأ داخل تبويب غير نشط وsplit قابل للتحجيم، ثم اختبر الجوال والرابط المباشر وتغيير الصلاحية وبقاء البيانات غير المحفوظة.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.

- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
