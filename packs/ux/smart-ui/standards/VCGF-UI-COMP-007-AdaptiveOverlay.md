# VCGF-UI-COMP-007 - النوافذ الحوارية والأدراج والقوائم العائمة

**AdaptiveOverlay**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

توفير طبقة تفاعل واضحة تستخدم Modal أو Drawer أو Popover وفق طول المهمة وخطورتها والمساحة، مع إدارة تركيز تمنع ضياع المستخدم أو احتجاز عمله.

**متى ينطبق:** ينطبق على التأكيدات والعمليات المركزة والتفاصيل الجانبية والخيارات المؤقتة. يختار النوع حسب المهمة لا بمجرد أن التصميم يحتوي صندوقًا عائمًا.

**متى لا ينطبق:** لا توضع كل صفحة في نافذة، ولا تُكدس modals لإكمال سلسلة طويلة، ولا تُفرض مصيدة تركيز على Popover غير نمطي أو drawer غير modal دون مقتضى.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `presentation` | `string` | `"adaptive"` | `system/tenant` | اختيار النوع بحسب المهمة والجهاز؛ يسجل سبب الاختيار. |
| `closeOnEscape` | `boolean` | `true` | `system` | يغلق الطبقة العليا فقط مع احترام حماية التغييرات. |
| `closeOnOutside` | `string` | `"safe-only"` | `system/tenant` | لا يتجاهل نموذجًا متسخًا أو عملية حساسة بصمت. |
| `restoreFocus` | `boolean` | `true` | `system` | إلى عنصر الفتح أو بديل منطقي إذا حذف العنصر. |
| `modalBehavior` | `string` | `"task-dependent"` | `system` | تحديد صريح: modal يحجب الخلفية وغير modal لا يفعل. |
| `maxNestedLayers` | `integer` | `2` | `system` | اقتراح لتقييد التعقيد؛ أي زيادة تتطلب تبريرًا واختبارًا. |
| `mobilePresentation` | `string` | `"sheet-or-fullscreen"` | `system` | حسب طول المهمة ولوحة المفاتيح والمساحة الفعلية. |
| `overlayStack` | `string` | `"centralized"` | `system` | إدارة طبقات واحدة بدل أرقام z-index عشوائية. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-007-R01"></a>
### VCGF-UI-COMP-007-R01 - اختيار النمط

اختر Popover لمعلومة أو اختيار قصير، وDrawer لتفاصيل سياقية، وModal لإجراء يحتاج تركيزًا أو تأكيدًا. صفحة مستقلة أفضل للعمليات الطويلة ذات الرابط أو التفرع الكبير.

<a id="VCGF-UI-COMP-007-R02"></a>
### VCGF-UI-COMP-007-R02 - الفتح والتركيز

ضع التركيز الأول في موضع يساعد فهم المحتوى؛ ليس دائمًا أول input. في إجراء خطر يفضل الخيار الآمن أو العنوان حسب السياق، وفي قائمة بحث يذهب للحقل الداخلي وفق معيارها.

<a id="VCGF-UI-COMP-007-R03"></a>
### VCGF-UI-COMP-007-R03 - الإغلاق الآمن

Escape والنقر خارج النافذة والزر الصريح تمر عبر سياسة إغلاق واحدة. عند تغييرات غير محفوظة اعرض حفظًا أو تجاهلًا أو متابعة، ولا تمنع الخروج بلا مسار واضح.

<a id="VCGF-UI-COMP-007-R04"></a>
### VCGF-UI-COMP-007-R04 - الطبقات المتداخلة

عند فتح تقويم أو قائمة داخل نافذة يظل المحتوى في نطاق التركيز والتسمية الصحيحين. Escape يغلق الأعمق أولًا، ولا تفتح طبقة خلف الخلفية المعتمة أو تقصها حاوية overflow.

<a id="VCGF-UI-COMP-007-R05"></a>
### VCGF-UI-COMP-007-R05 - حجب الخلفية

في modal فعلي امنع تفاعل الخلفية بطريقة دلالية مع حفظ تمرير الصفحة. في النمط غير modal لا تفرض aria-modal أو focus trap خلافًا للسلوك الحقيقي.

<a id="VCGF-UI-COMP-007-R06"></a>
### VCGF-UI-COMP-007-R06 - التكيف واللوحة الافتراضية

تأقلم مع حجم الشاشة والـvisual viewport ولوحة مفاتيح الهاتف. اجعل العنوان وأزرار المهمة قابلين للوصول ولا تحاصر الحقل النشط أسفل منطقة غير قابلة للتمرير.

<a id="VCGF-UI-COMP-007-R07"></a>
### VCGF-UI-COMP-007-R07 - التحميل والعمليات

الطلب الطويل لا يحتجز المستخدم بلا تفسير. ميّز إغلاق العرض من إلغاء العملية، ووفر مسار متابعة لمهمة الخلفية الفعلية عند دعمها، ولا تدّع إلغاءً لم يؤكده الخادم.

<a id="VCGF-UI-COMP-007-R08"></a>
### VCGF-UI-COMP-007-R08 - عودة السياق

بعد الإغلاق أعد التركيز لعنصر الفتح أو العنصر المنطقي التالي إذا حذف السجل. احتفظ بمرشحات القائمة وموضعها ولا تعيد المستخدم لأول الشاشة بلا سبب.

<a id="VCGF-UI-COMP-007-R09"></a>
### VCGF-UI-COMP-007-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-007-R10"></a>
### VCGF-UI-COMP-007-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-007-R11"></a>
### VCGF-UI-COMP-007-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-007-R12"></a>
### VCGF-UI-COMP-007-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `open`, `presentation`, `modality`, `title`, `dirtyState`, `closePolicy`, `initialFocusTarget`

**الأحداث المفاهيمية:** `openChanged`, `closeRequested`, `discardConfirmed`, `focusRestored`

**مصدر السلطة:** خدمة الطبقات تدير الواجهة؛ حفظ أو إلغاء معاملات الخادم يتطلب عقوده المستقلة.

```text
closed -> opening -> open -> close-requested -> confirm-discard/closed
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`, `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- ضع إدارة الطبقات والأحداث وإلغاء الاستماع في خدمة مشتركة تمنع تكرار handlers عند كل فتح.
- اختبر portals مع RTL وmodal inert ومع القوائم التابعة؛ لا تصلح المشكلة بقيمة z-index هائلة.
- التنقل المباشر إلى شاشة تفصيل يجب أن يملك fallback مستقلًا عن وجود سجل parent في ذاكرة الواجهة.
- احترام reduced motion وعدم تعليق التركيز على نهاية حركة قد تتعطل أو تلغى.
- التغييرات غير المحفوظة تستخدم عقد draft موحدًا؛ التأكيد البصري لا يضمن حفظ البيانات.

## 6. الوصولية والعربية والتجاوب

- اسم ووصف عند الحاجة وaria-modal مطابق للحقيقة، مع تسلسل Tab وShift+Tab صالح.
- زر إغلاق واضح مسمى حتى عند وجود Escape، وحجم لمس مناسب.
- عدم استخدام role=dialog للقوائم العائمة كلها؛ النمط الدلالي يطابق الوظيفة الفعلية.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- حذف عنصر الفتح أثناء فتح النافذة يحتاج fallback للتركيز.
- فتح نافذة ثانية من الأولى يجب أن يعيد الأولى لحالتها بعد الإغلاق لا أن يترك scroll lock دائمًا.
- تبدل الاتجاه أثناء الفتح لا يعكس ترتيب البيانات ولا يخرج اللوحة من الشاشة.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [Radix UI Primitives](https://www.radix-ui.com/primitives/docs/components) | عناصر تفاعل غير منسقة تشمل Dialog وPopover وTabs وDropdown Menu. | اختبار التركيب وإدارة التركيز يظل مطلوبًا؛ اختيارها لا يمنح التطبيق شهادة وصولية تلقائية. |
| [React Aria Components](https://react-aria.adobe.com/Tree) | بديل لمكوّنات تفاعلية مع اهتمام بالدلالات ولوحة المفاتيح. | اختر النمط الموافق للبنية ولا تركب primitives متضاربة؛ راجع وثائق المكوّن والإصدار المستعمل. |
| [shadcn/ui](https://ui.shadcn.com/docs/components) | مكوّنات قابلة للتخصيص ضمن نظام تصميم React مناسب. | افحص primitive والبنية في الإصدار الفعلي؛ لا تفترض أن كل Combobox يضع البحث داخل النافذة، ولا تثبّت كل المكوّنات دفعة واحدة. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **لا تحاصر المستخدم ولا تفقد عمله لإرضاء شكل النافذة.**
- **إدارة التركيز جزء من الوظيفة وليست تحسينًا اختياريًا.**
- **إغلاق العرض لا يعني إلغاء العملية.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-007 / AdaptiveOverlay - النوافذ الحوارية والأدراج والقوائم العائمة.
توفير طبقة تفاعل واضحة تستخدم Modal أو Drawer أو Popover وفق طول المهمة وخطورتها والمساحة، مع إدارة تركيز تمنع ضياع المستخدم أو احتجاز عمله.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: لا تحاصر المستخدم ولا تفقد عمله لإرضاء شكل النافذة. إدارة التركيز جزء من الوظيفة وليست تحسينًا اختياريًا. إغلاق العرض لا يعني إلغاء العملية.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: افتح نموذجًا داخل Drawer مع قائمة البحث والتقويم ثم اختبر تسلسل Escape والنقر الخارجي والتغييرات غير المحفوظة ولوحة مفاتيح الهاتف والعودة إلى الصف الأصلي.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
