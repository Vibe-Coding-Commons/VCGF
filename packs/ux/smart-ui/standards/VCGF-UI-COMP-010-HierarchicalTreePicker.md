# VCGF-UI-COMP-010 - الاختيار الهرمي والشجري

**HierarchicalTreePicker**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تمثيل علاقات الأبناء والآباء بصورة مفهومة دون منح معنى إداري للاختيار لم يحدده نطاق العمل، مع الحفاظ على الأداء وصلاحيات الفروع.

**متى ينطبق:** ينطبق على الإدارات والمجلدات والتصنيفات والهياكل التي تكون علاقتها الهرمية ضرورية للاختيار أو الاستكشاف.

**متى لا ينطبق:** لا يستبدل القائمة المسطحة إذا لم تكن علاقة الأب والابن مفيدة، ولا يفرض اختيار كل الأبناء عند اختيار الأب، ولا يعد التوسيع اختيارًا.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `selectionMode` | `string` | `"single"` | `system/tenant` | single أو multiple حسب الحقل؛ لا يتغير بلا ترحيل للقيم. |
| `selectionPropagation` | `string` | `"none"` | `system` | none افتراضيًا؛ descendants يتطلب قاعدة أعمال واضحة. |
| `selectableNodeTypes` | `array` | `["leaf"]` | `system/tenant` | أنواع العقد المسموح اختيارها؛ يمكن دعم الفروع صراحة. |
| `lazyLoading` | `boolean` | `true` | `system` | للهياكل الكبيرة؛ تحميل كل شجرة صغيرة جائز بقرار موثق. |
| `searchMode` | `string` | `"authorized-paths"` | `system` | النتائج والمسارات لا تكشف أسلافًا محجوبة. |
| `showPath` | `boolean` | `true` | `tenant/user` | إظهار المسار المسموح لتفريق الأسماء المتشابهة. |
| `rememberExpanded` | `boolean` | `true` | `tenant/user` | بمعرفات ثابتة ومحدودة بنطاق المستأجر. |
| `allowReparenting` | `boolean` | `false` | `system/tenant` | نقل الفروع إجراء منفصل مفوض وليس جزءًا تلقائيًا من picker. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-010-R01"></a>
### VCGF-UI-COMP-010-R01 - هوية وعلاقة

استخدم nodeId وparentId ثابتين، وافصل عنوان العقدة ومسارها عن المعرف. امنع الدورة في مصدر البيانات وتحقق من العلاقة عند نقل عقدة، لا في الرسم فقط.

<a id="VCGF-UI-COMP-010-R02"></a>
### VCGF-UI-COMP-010-R02 - تركيز واختيار وتوسيع

وفر حالات منفصلة للتركيز والتحديد والتوسيع. الضغط على سهم الفرع يفتح أبناءه ولا يختار قيمة الحقل تلقائيًا، والاختيار له علامة أو فعل واضح.

<a id="VCGF-UI-COMP-010-R03"></a>
### VCGF-UI-COMP-010-R03 - نطاق الانتشار

عند اختيار أب يحدد العقد ما إذا كان الاختيار ذاتيًا أو يشمل أبناءً. مع التحميل الكسول لا تعرض علامة جميع الأبناء محددون لأن المرئيين فقط اختيروا؛ التغطية تُحسم من المصدر.

<a id="VCGF-UI-COMP-010-R04"></a>
### VCGF-UI-COMP-010-R04 - بحث مع سياق

عند البحث اعرض المطابقة ومسارًا مسموحًا يميزها، مع فتح الأسلاف اللازمة أو شاشة نتائج مناسبة. مسح البحث يعيد حالة توسع معقولة ولا يفقد الاختيارات.

<a id="VCGF-UI-COMP-010-R05"></a>
### VCGF-UI-COMP-010-R05 - تحميل فروع

لكل فرع حالة تحميل وخطأ وإعادة محاولة. لا يصبح فشل التحميل معنى لا توجد أبناء، ولا ينهار كامل المكوّن عند فشل فرع واحد.

<a id="VCGF-UI-COMP-010-R06"></a>
### VCGF-UI-COMP-010-R06 - صلاحيات هرميّة

تتحقق الخدمة من الوصول لكل عقدة ومسار وطلب بحث. حجب فرع لا يترك أسماءه في عدد النتائج أو مسار ابن مكشوف بطريقة غير معتمدة.

<a id="VCGF-UI-COMP-010-R07"></a>
### VCGF-UI-COMP-010-R07 - استعادة القيم

اعرض الاختيارات المحفوظة حتى إن لم تكن ضمن الفروع المحملة أولًا، عبر تحميل مفوض بالمعرف. العقدة المحذوفة أو غير المتاحة تظهر كحالة معالجة لا تُستبدل بأول عقدة.

<a id="VCGF-UI-COMP-010-R08"></a>
### VCGF-UI-COMP-010-R08 - نقل وإعادة ترتيب منفصلان

إذا فُعّل نقل العقد أو ترتيبها فاعرض أثر العملية وتحقق من الصلاحية والنسخة في الخادم. وفر بديلًا للسحب وأعد الحالة عند الرفض.

<a id="VCGF-UI-COMP-010-R09"></a>
### VCGF-UI-COMP-010-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-010-R10"></a>
### VCGF-UI-COMP-010-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-010-R11"></a>
### VCGF-UI-COMP-010-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-010-R12"></a>
### VCGF-UI-COMP-010-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `nodes`, `selectedIds`, `expandedIds`, `selectionPolicy`, `loadChildren`, `searchNodes`, `capabilities`

**الأحداث المفاهيمية:** `selectionChanged`, `nodeExpanded`, `childrenRequested`, `moveRequested`, `resolutionFailed`

**مصدر السلطة:** خدمة الهيكل مصدر العلاقات والانتشار والصلاحيات؛ المكوّن يعرض ويختار فقط ما يسمح العقد به.

```text
ready -> branch-loading -> expanded/branch-error; search -> results -> selection
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-007](VCGF-UI-COMP-007-AdaptiveOverlay.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- الصلاحيات على الأسلاف لا تُفترض مطابقة للأبناء؛ يحدد المجال سياسة الوراثة والاستثناءات.
- استخدم cursor أو حد أطفال عند الفروع الكبيرة ووضح وجود المزيد بدل تجميد الشاشة.
- لا تخلط checkbox ثلاثي الحالة بحالة selection إذا كان معناهما مختلفًا دون تصميم وتعليمات واضحة.
- مخطط cache يشمل nodeId وإصدار الهيكل ونطاق التفويض؛ يبطل عند النقل أو تغيير الدور.
- توسع الشجرة تفضيل محلي؛ نقل العقدة أو حذفها تعديل أعمال يحتاج خدمة وأدلة مستقلة.

## 6. الوصولية والعربية والتجاوب

- طبق نمط Treeview المناسب واختبر الأسهم وHome وEnd والاختيار دون تعديل القيمة بمجرد مرور التركيز.
- أعلن المستوى والتوسيع وحالة التحميل عند الحاجة دون سرد كامل الشجرة.
- توفير بحث متاح وبديل عملي للشجرة العميقة على الهاتف لا تعتمد فيه النقرات الدقيقة وحدها.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- حذف عقدة مختارة أثناء التحرير يستدعي تنبيهًا وإعادة تحقق قبل الحفظ.
- سلسلة آباء طويلة لا تُقص بطريقة تخفي التمييز بين عقدتين متطابقتين في الاسم.
- عقدة يتيمة بسبب بيانات غير سليمة لا تُصلح بصمت؛ تظهر حالة آمنة ويُسجل الخلل.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| [MUI X Tree View](https://mui.com/x/react-tree-view/) | بديل للشجرة ضمن مشروع يعتمد MUI. | تحقق من قدرات Simple وRich وPro وترخيص الميزات المطلوبة وتوافق نظام التصميم. |
| [Radix UI Primitives](https://www.radix-ui.com/primitives/docs/components) | عناصر تفاعل غير منسقة تشمل Dialog وPopover وTabs وDropdown Menu. | اختبار التركيب وإدارة التركيز يظل مطلوبًا؛ اختيارها لا يمنح التطبيق شهادة وصولية تلقائية. |

## 9. الوصايا الذهبية

- **توسيع العقدة ليس اختيارها واختيار الأب ليس تفويضًا لاختيار الجميع.**
- **لا تحكم على أبناء لم تُحمّلهم من عدد العناصر الظاهرة.**
- **العلاقة الهرمية قرار بيانات لا أثر بصري فقط.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-010 / HierarchicalTreePicker - الاختيار الهرمي والشجري.
تمثيل علاقات الأبناء والآباء بصورة مفهومة دون منح معنى إداري للاختيار لم يحدده نطاق العمل، مع الحفاظ على الأداء وصلاحيات الفروع.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: توسيع العقدة ليس اختيارها واختيار الأب ليس تفويضًا لاختيار الجميع. لا تحكم على أبناء لم تُحمّلهم من عدد العناصر الظاهرة. العلاقة الهرمية قرار بيانات لا أثر بصري فقط.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر شجرة إدارات كبيرة بأسماء متشابهة وتحميل كسول وحقوق مختلفة، ثم تحقق من قيمة محفوظة بعيدة ومن اختيار أبناء غير محملين ومنع دورة عند النقل.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
