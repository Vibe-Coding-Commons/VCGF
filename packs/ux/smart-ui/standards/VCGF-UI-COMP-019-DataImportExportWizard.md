# VCGF-UI-COMP-019 - استيراد وتصدير البيانات مع المعاينة والتحقق

**DataImportExportWizard**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

نقل البيانات من وإلى النظام ضمن نطاق مفوض ومفهوم، مع اكتشاف الأخطاء قبل الأثر وتوثيق السجلات المتأثرة والنتائج الجزئية ومنع تكرار العملية.

**متى ينطبق:** ينطبق على استيراد CSV أو XLSX أو تصدير مجموعات تشغيلية، ويتوسع إلى مهام خادمية مجزأة عندما يزيد الحجم أو الأثر.

**متى لا ينطبق:** ليس فتح ملف جدول إذنًا بتنفيذ صيغه أو وحداته البرمجية، ولا يستورد البيانات إلى الإنتاج بمجرد نجاح التحليل في المتصفح، ولا يفرض استيرادًا جزئيًا بلا موافقة سياسة.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `allowedFormats` | `array` | `["csv", "xlsx"]` | `system/tenant` | قائمة سماح حقيقية للخدمات المثبتة؛ لا يدعي دعم xlsm ضمنيًا. |
| `maxRows` | `integer` | `10000` | `system/tenant` | اقتراح للدفعة؛ يضبط بالحجم والموارد والخدمة. |
| `previewRows` | `integer` | `50` | `system` | المعاينة عينة؛ التحقق النهائي يشمل كل الصفوف. |
| `duplicatePolicy` | `string` | `"reject"` | `system/tenant` | reject أو skip أو update بعقد مفاتيح فريدة وصلاحيات. |
| `transactionMode` | `string` | `"explicit-required"` | `system` | atomic أو per-row أو per-batch؛ يجب حسمه قبل التنفيذ. |
| `exportScope` | `string` | `"filtered-authorized"` | `system` | يحدد هل الصفحة أم كل النتائج ويعيد التفويض. |
| `formulaPolicy` | `string` | `"no-execution"` | `system` | لا ينفذ صيغًا أو روابط خارجية؛ يصدر النصوص بطريقة آمنة للهدف. |
| `jobRetentionHours` | `integer` | `24` | `system/tenant` | اقتراح للملفات المؤقتة والتقارير مع مراعاة سياسة المنشأة. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-019-R01"></a>
### VCGF-UI-COMP-019-R01 - مسار مفهوم

قسّم الاستيراد إلى رفع وتحليل وربط أعمدة وتحقق ومعاينة أثر وتأكيد وتنفيذ ونتيجة. اعرض مصدر كل حقل وميز المطلوب من الاختياري، ولا تبدأ كتابة بيانات أثناء مجرد المعاينة.

<a id="VCGF-UI-COMP-019-R02"></a>
### VCGF-UI-COMP-019-R02 - ربط محفوظ ذو إصدار

ربط الأعمدة يعتمد أسماء أو معرفات واضحة ومخططًا بإصدار، ويُتحقق منه عند إعادة استخدام قالب. أعمدة غير معروفة لا تصبح حقول قاعدة بيانات تلقائيًا.

<a id="VCGF-UI-COMP-019-R03"></a>
### VCGF-UI-COMP-019-R03 - تحقق شامل

تحقق من كل صف في الخادم وليس العينة فقط، بما في ذلك الأنواع والعلاقات والتفرّد والصلاحيات. تقرير الأخطاء يتضمن رقم الصف والعمود وسببًا آمنًا دون محتوى شخصي زائد.

<a id="VCGF-UI-COMP-019-R04"></a>
### VCGF-UI-COMP-019-R04 - تواريخ وأرقام وهوية

فسر التواريخ بصيغة وتقويم معلومين والأرقام بعقد محلي، وحافظ على الأصفار البادئة للمعرفات. عند Excel serial dates افحص نظام التاريخ والبيانات الوصفية ولا تحوّل الأرقام اعتباطيًا إلى تاريخ.

<a id="VCGF-UI-COMP-019-R05"></a>
### VCGF-UI-COMP-019-R05 - نطاق وأثر التكرار

اعرض أعداد الإنشاء والتحديث والتخطي والرفض قبل التنفيذ وحدد المفتاح الذي يقرر التكرار. update لا يتيح تعديل حقول محجوبة أو سجلات منشأة أخرى.

<a id="VCGF-UI-COMP-019-R06"></a>
### VCGF-UI-COMP-019-R06 - معاملة ومنع تكرار

اختر atomic أو جزئية موثقة، واربط المهمة ببصمة ملف وربط وإعدادات ومعرف تنفيذ. تغيير البيانات بعد المعاينة يستدعي إعادة تحقق وقت التنفيذ ولا يعاد تنفيذ مهمة مكتملة عند انقطاع الرد.

<a id="VCGF-UI-COMP-019-R07"></a>
### VCGF-UI-COMP-019-R07 - تصدير آمن

أعد التفويض وحدد الأعمدة والنطاق والوقت وإصدار تنسيق التصدير. تعامل مع نصوص قد تُفسر كصيغ في البرنامج المستهدف؛ اقتباس CSV وحده ليس ضمانًا كافيًا، وملفات XLSX تجعل القيم النصية نصوصًا حيث يلزم.

<a id="VCGF-UI-COMP-019-R08"></a>
### VCGF-UI-COMP-019-R08 - نتائج ومتابعة

للعمليات الطويلة اعرض jobId وحالة وتقدمًا حقيقيًا وعددًا معلومًا أو غير معلوم بصدق. الإلغاء لا يعكس السجلات المكتملة دون خطة تعويض؛ تقرير النتيجة يحدد المنفذ وغير المنفذ.

<a id="VCGF-UI-COMP-019-R09"></a>
### VCGF-UI-COMP-019-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-019-R10"></a>
### VCGF-UI-COMP-019-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-019-R11"></a>
### VCGF-UI-COMP-019-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-019-R12"></a>
### VCGF-UI-COMP-019-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `fileRef`, `mapping`, `schemaVersion`, `validationReport`, `importPolicy`, `jobState`, `exportScope`

**الأحداث المفاهيمية:** `mappingChanged`, `validationRequested`, `commitConfirmed`, `jobCanceled`, `reportRequested`

**مصدر السلطة:** خدمة الاستيراد والتصدير تملك التحقق والتفويض والمعاملة؛ المتصفح يقدم المعاينة والتحكم فقط.

```text
uploaded -> mapped -> validating -> review -> queued/running -> completed/partial/failed/canceled
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-002](VCGF-UI-COMP-002-SmartDataGrid.md) - [VCGF-UI-COMP-003](VCGF-UI-COMP-003-SmartFormFields.md) - [VCGF-UI-COMP-005](VCGF-UI-COMP-005-SmartFileUploader.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-011](VCGF-UI-COMP-011-SmartFormWizard.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md) - [VCGF-UI-COMP-017](VCGF-UI-COMP-017-SmartNumericInput.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`, `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- حد الحجم وعدد الصفوف والأوراق والخلايا وطولها ونسبة الضغط قبل المعالجة؛ الملفات المضغوطة قد تستهلك موارد كبيرة.
- لا تقيم formulas أو macros ولا تتبع روابط workbook خارجية خلال التحليل غير الموثوق.
- يدعم parser الترميز وفواصل CSV وعلامات الاقتباس والأسطر المتعددة؛ لا تستخدم split على الفاصلة بوصفه محللًا.
- توثق exports الخاصة بالتكامل بنسخة مستقرة لا تتغير مع تفضيل تاريخ مستخدم؛ العرض البشري خيار منفصل.
- استيراد الصلاحيات أو المستخدمين أو الأرصدة يحتاج بوابة مخاطر إضافية لا يرث تلقائيًا سياسة بيانات عادية.

## 6. الوصولية والعربية والتجاوب

- ربط الأعمدة متاح بلوحة المفاتيح ومعه أسماء المصدر والهدف ومؤشر إلزام.
- تقرير الأخطاء يمكن قراءته أو تصديره بأمان ولا يعتمد على خلايا حمراء فقط.
- على الهاتف يمكن مراجعة الملخص والأخطاء دون فرض جدول عريض غير قابل للوصول.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- رأس عمود مكرر أو مسافة مخفية في الاسم يكتشف قبل ربطه بحقلين مختلفين.
- صفوف فارغة وسط الملف لا تغيّر أرقام الصفوف التي يشير إليها تقرير الأخطاء.
- فشل تنزيل التقرير بعد نجاح الاستيراد لا يعيد عملية الاستيراد نفسها.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [Papa Parse](https://www.papaparse.com/docs) | تحليل وتصدير CSV مع خيارات ترميز وفواصل مناسبة. | لا يستبدل تحقق الأعمال ولا يعالج Excel بذاته؛ اختبر منع حقن الصيغ وفق العميل المستهدف. |
| [ExcelJS](https://github.com/exceljs/exceljs) | التعامل مع ملفات workbook في البيئات والميزات المدعومة. | اختبر حجم الملف وأنواع الخلايا والتواريخ؛ لا تستخدمه لتقييم صيغ أو macros غير موثوقة. |
| [Laravel Excel](https://docs.laravel-excel.com/) | تكامل استيراد وتصدير مناسب لبعض مشاريع Laravel. | راجع إصدار PHP وLaravel والمكتبة وسياسة معالجة الصفوف والمهام، ولا تفترض توافق جميع الإصدارات. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **نجاح قراءة الملف لا يعني صلاحية إدخال بياناته.**
- **المعاينة لا تكتب، والتنفيذ يعيد التحقق.**
- **لا تدّع تراجعًا كاملًا عن مهمة جزئية دون تعويض مثبت.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-019 / DataImportExportWizard - استيراد وتصدير البيانات مع المعاينة والتحقق.
نقل البيانات من وإلى النظام ضمن نطاق مفوض ومفهوم، مع اكتشاف الأخطاء قبل الأثر وتوثيق السجلات المتأثرة والنتائج الجزئية ومنع تكرار العملية.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: نجاح قراءة الملف لا يعني صلاحية إدخال بياناته. المعاينة لا تكتب، والتنفيذ يعيد التحقق. لا تدّع تراجعًا كاملًا عن مهمة جزئية دون تعويض مثبت.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: استورد ملفًا عربيًا بأخطاء خارج العينة ومعرفات صفرية وتواريخ ملتبسة وصفوف مكررة، ثم اختبر انقطاع الرد والإلغاء والتصدير بنص يشبه الصيغة في العميل المستهدف.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
