# VCGF-UI-COMP-017 - إدخال الأرقام والمبالغ والنسب والكميات

**SmartNumericInput**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

الفصل بين القيمة العددية الدقيقة وتنسيقها المحلي ووحدتها وقواعد حسابها، مع تجربة إدخال تسمح بالتصحيح دون قفز المؤشر أو تقريب مالي خفي.

**متى ينطبق:** ينطبق على المبالغ والكميات والنسب والأوزان والقياسات. لكل نوع عقد وحدات ودقة وحدود وقواعد تقريب حسب المجال وليس الإعداد الجمالي وحده.

**متى لا ينطبق:** لا يفترض أن جميع العملات منزلتان عشريتان، ولا يستخدم float عاديًا كضمان دقة محاسبية، ولا يحول معرفًا طويلًا أو رقم هاتف إلى حقل عدد.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `locale` | `string` | `"tenant"` | `system/user` | من إعداد اللغة؛ لا يحسم وحدة القيمة أو العملة. |
| `numberingSystem` | `string` | `"latn"` | `tenant/user` | دعم arab عند اعتماد المنتج مع تطبيع الإدخال دون تغيير القيمة. |
| `currency` | `string` | `"tenant"` | `system/tenant` | رمز عملة صريح لكل مبلغ؛ لا يفترض من اللغة وحدها. |
| `decimalScale` | `string` | `"domain-defined"` | `system` | تعريف لكل حقل أو وحدة؛ لا تفرض منزلتين على جميع العملات والكميات. |
| `roundingMode` | `string` | `"domain-defined"` | `system` | يحدد في عقد الحساب والخادم قبل تفعيل المعاملة المالية. |
| `grouping` | `boolean` | `true` | `tenant/user` | فواصل عرض فقط ويُحسم قبولها في الإدخال المحلي. |
| `emptyPolicy` | `string` | `"null-not-zero"` | `system` | الفراغ ليس صفرًا؛ يحدد المجال null أو required. |
| `allowNegative` | `boolean` | `false` | `system/tenant` | قيد حقل ومجال لا تعديل بصري؛ الخادم يعيد التحقق. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-017-R01"></a>
### VCGF-UI-COMP-017-R01 - قيمة ووحدة

يحمل المبلغ value وcurrency وتحمل الكمية value وunit حيث يلزم. لا يخزن رمز العملة أو فاصل الآلاف جزءًا من القيمة الحسابية، ولا يغيّر تبديل اللغة العملة تلقائيًا.

<a id="VCGF-UI-COMP-017-R02"></a>
### VCGF-UI-COMP-017-R02 - إدخال مرحلي

احتفظ بنص التحرير الخام منفصلًا عن القيمة المحللة. يسمح بالحالات الوسيطة مثل سالب أو فاصل لم تكتمل قيمته دون حفظها كرقم صالح، ويحافظ على المؤشر عند التصحيح.

<a id="VCGF-UI-COMP-017-R03"></a>
### VCGF-UI-COMP-017-R03 - تحليل محلي صريح

عرّف الفاصل العشري وفاصل التجميع والأرقام المقبولة حسب نمط الحقل. عند قيمة ملتبسة مثل 1,234 لا تخمن على نحو يغير المبلغ؛ اشرح أو ارفض وفق الإعداد.

<a id="VCGF-UI-COMP-017-R04"></a>
### VCGF-UI-COMP-017-R04 - دقة حسابية

استخدم decimal string أو نوع Decimal أو وحدات صغرى بعقد محدد للحسابات الدقيقة، ولا تمرر القيمة عبر float قبل المكتبة العشرية. الخادم يطبق الحساب والتقريب المرجعيين.

<a id="VCGF-UI-COMP-017-R05"></a>
### VCGF-UI-COMP-017-R05 - حدود وقواعد

تحقق من min وmax وscale وstep والقيمة السالبة في الخادم والواجهة. لا يصلح النظام قيمة خارج الحد تلقائيًا بلا تنبيه لأن القص أو التقريب قد يغير قرار المستخدم.

<a id="VCGF-UI-COMP-017-R06"></a>
### VCGF-UI-COMP-017-R06 - نسب واضحة

حدد هل النسبة محفوظة ككسر 0.15 أم مقدار 15 لمعنى 15 بالمئة، واعرض الوحدة دائمًا. لا تخلط percentage points بنسبة التغير في حسابات المؤشرات.

<a id="VCGF-UI-COMP-017-R07"></a>
### VCGF-UI-COMP-017-R07 - تقريب محكوم

حدد موضع التقريب: لكل سطر أو عند الإجمالي أو عند التسوية. يعرض الملخص القيم المتوافقة مع الحساب المرجعي، ولا ينتج الإجمالي من نصوص منسقة قربت مسبقًا.

<a id="VCGF-UI-COMP-017-R08"></a>
### VCGF-UI-COMP-017-R08 - فراغ وصفر ومعرفات

ميّز null والصفر والسالب صفرًا عندما يهم المجال. لا تحوّل سلسلة معرف أو رقم حساب طويل إلى Number فتفقد أصفارًا بادئة أو دقة، واستخدم حقل نص للهوية.

<a id="VCGF-UI-COMP-017-R09"></a>
### VCGF-UI-COMP-017-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-017-R10"></a>
### VCGF-UI-COMP-017-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-017-R11"></a>
### VCGF-UI-COMP-017-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-017-R12"></a>
### VCGF-UI-COMP-017-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `rawInput`, `canonicalValue`, `unit`, `currency`, `scale`, `roundingPolicy`, `min`, `max`

**الأحداث المفاهيمية:** `rawChanged`, `valueParsed`, `parseRejected`, `valueCommitted`

**مصدر السلطة:** محرك المجال والخادم مصدر الحساب والتقريب؛ المكوّن يدير الإدخال والعرض.

```text
empty -> editing -> valid/invalid/ambiguous -> committed
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-003](VCGF-UI-COMP-003-SmartFormFields.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

## 5. النقاط الهندسية وحدود المسؤولية

- Intl.NumberFormat للعرض وليس parser عامًا مضمونًا للنصوص المحلية؛ التحليل يحتاج عقدًا واختبارات مستقلة.
- عند استخدام decimal.js أو بديل مرر سلسلة دقيقة وحدد precision وrounding صراحة حسب المجال.
- وحدات العملة الصغرى ليست دائمًا 100؛ راجع سياسة العملة والقيم الخاصة بالمجال.
- لا تعيد احتساب معاملات مالية قديمة بتغيير إعداد عرض أو تقريب مركزي دون ترحيل واعتماد منفصل.
- عمليات الفرز والمقارنة والتصدير تستخدم القيمة المعيارية لا النص العربي المنسق.

## 6. الوصولية والعربية والتجاوب

- لوحة مفاتيح رقمية مناسبة عبر inputmode مع اسم وحدة وقيمة ورسالة خطأ واضحة.
- عزل الاتجاه للمبلغ والرمز عند اختلاط العربية واللاتينية دون عكس الإشارة السالبة أو الفاصل.
- spinbutton يستخدم فقط إذا التزم التفاعل بزيادات مفهومة؛ ليس لكل مبلغ يحتاج إدخالًا حرًا.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- أعداد أكبر من المجال الآمن للنوع المستخدم لا تقبل بتحويل ضمني يخفض الدقة.
- لصق مسافات غير قابلة للكسر أو أرقام عربية يعالج بتطبيع موثق لا حذف علامات قد تغير المعنى.
- تغيير الوحدة من كيلوغرام إلى غرام يحتاج تحويلًا صريحًا لا تغيير label فقط.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [react-number-format](https://s-yadav.github.io/react-number-format/docs/intro/) | تنسيق مدخلات رقمية مع إدارة موضع المؤشر. | ليس محرك حساب مالي؛ القيمة المعيارية والدقة والتحقق الخادمي تبقى مستقلة. |
| [decimal.js](https://mikemcl.github.io/decimal.js/) | حساب عشري عند الحاجة إلى دقة محددة. | تحديد precision وrounding وتمرير سلاسل دقيقة مطلوب؛ لا يصلح فقد الدقة الذي حدث قبل دخوله. |
| [React Aria Components](https://react-aria.adobe.com/Tree) | بديل لمكوّنات تفاعلية مع اهتمام بالدلالات ولوحة المفاتيح. | اختر النمط الموافق للبنية ولا تركب primitives متضاربة؛ راجع وثائق المكوّن والإصدار المستعمل. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **القيمة والوحدة والتنسيق ثلاثة أشياء لا نص واحد.**
- **لا تُصلح مبلغًا بتقريب أو قص صامت.**
- **لا تحول المعرفات إلى أرقام لمجرد احتوائها على أرقام.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

**Then - النتيجة المطلوبة:** تكتمل المهمة أو يعلن سبب المنع بوضوح، ولا يقع التركيز في عنصر مخفي أو غير ذي معنى.

### VCGF-UI-COMP-017-AC11 - التعريب والاستجابة دون فقد المعنى

**المتطلب المرتبط:** [VCGF-UI-COMP-017-R11](#VCGF-UI-COMP-017-R11) - **الحالة:** `not_run`

**Given - بفرض:** بيانات عربية وإنجليزية طويلة ومعرفات وأرقام مختلطة

**When - عندما:** تتبدل اللغة ويضيق العرض ويكبر النص

**Then - النتيجة المطلوبة:** تبقى القيم والمعرفات الصحيحة قابلة للقراءة والوصول، ولا تضيع عملية أساسية أو يختلط ترتيب الرموز.

### VCGF-UI-COMP-017-AC12 - التعافي والأداء بأدلة

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-017 / SmartNumericInput - إدخال الأرقام والمبالغ والنسب والكميات.
الفصل بين القيمة العددية الدقيقة وتنسيقها المحلي ووحدتها وقواعد حسابها، مع تجربة إدخال تسمح بالتصحيح دون قفز المؤشر أو تقريب مالي خفي.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: القيمة والوحدة والتنسيق ثلاثة أشياء لا نص واحد. لا تُصلح مبلغًا بتقريب أو قص صامت. لا تحول المعرفات إلى أرقام لمجرد احتوائها على أرقام.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر مبالغ عشرية ونسبًا وكميات بأرقام عربية وفواصل ملتبسة وحدود كبيرة، ثم قارن الحفظ والإجمالي والتصدير مع محرك خادمي مرجعي.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
