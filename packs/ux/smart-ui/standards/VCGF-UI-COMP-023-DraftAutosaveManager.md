# VCGF-UI-COMP-023 - الحفظ التلقائي والمسودات والتغييرات غير المحفوظة

**DraftAutosaveManager**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

حماية وقت المستخدم من انقطاع الاتصال أو الانتقال العرضي، مع تعريف صريح لما حُفظ وأين وبأي إصدار، ومنع الكتابة فوق عمل مستخدم آخر أو تخزين أسرار على الجهاز.

**متى ينطبق:** ينطبق على النماذج الطويلة والمحررات والطلبات متعددة المراحل عندما يبرر احتمال فقد العمل وجود مسودات. يظل الحفظ اليدوي كافيًا للمهام الصغيرة حسب التقييم.

**متى لا ينطبق:** لا يدّعي الحفظ بمجرد وضع البيانات في ذاكرة أو localStorage، ولا يعد draft موافقة أو إرسالًا نهائيًا، ولا يضمن استمرار beforeunload أو الاتصال عند إغلاق المتصفح.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `enabled` | `boolean` | `false` | `system/tenant` | يفعّل في الحقول والمهام المعتمدة فقط بعد سياسة خصوصية واسترجاع. |
| `debounceMs` | `integer` | `1500` | `system/tenant` | اقتراح للحفظ بعد سكون الكتابة؛ لا يرسل لكل ضغطة. |
| `maxWaitMs` | `integer` | `10000` | `system/tenant` | حد تجريبي لمنع تأخير غير محدود أثناء كتابة متواصلة. |
| `storageMode` | `string` | `"server"` | `system/tenant` | التخزين المحلي opt-in ومحدود التصنيف؛ ليس بديلًا صامتًا عن الخادم. |
| `localSensitiveStorage` | `boolean` | `false` | `system` | الأسرار والرموز وكلمات المرور ممنوعة افتراضيًا. |
| `conflictPolicy` | `string` | `"block-and-resolve"` | `system` | لا يستخدم آخر حفظ يفوز بلا قرار مجال موثق. |
| `resumePolicy` | `string` | `"ask-and-revalidate"` | `system/tenant` | يتحقق من الحساب والصلاحية ومخطط المسودة قبل الاستعادة. |
| `retentionDays` | `integer` | `7` | `system/tenant` | اقتراح للمسودات يخضع لسياسة الجهة والحجز والقيمة التجارية. |

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-023-R01"></a>
### VCGF-UI-COMP-023-R01 - حالات حفظ صادقة

اعرض dirty وsaving وsaved وoffline-pending وfailed وconflict مع وقت آخر إقرار خادمي. لا تستخدم تم الحفظ إذا لم يتجاوز العمل ذاكرة الجهاز أو لم يصل إقرار.

<a id="VCGF-UI-COMP-023-R02"></a>
### VCGF-UI-COMP-023-R02 - تجميع وتسلسل

اجمع التغييرات بمؤقت ثم أرسل لقطة ذات مراجعة، مع منع تداخل طلبين قد تصل استجابتهما خارج الترتيب. لا تجعل إقرار لقطة أقدم يمحو dirty لتعديلات أحدث.

<a id="VCGF-UI-COMP-023-R03"></a>
### VCGF-UI-COMP-023-R03 - نسخ وتعارض

أرسل expectedRevision أو ETag واستخدم شرطًا خادميًا مناسبًا. عند التعارض اعرض خيارات مقارنة أو إعادة تحميل أو دمج معتمد، ولا تكتب فوق النسخة الأحدث بصمت.

<a id="VCGF-UI-COMP-023-R04"></a>
### VCGF-UI-COMP-023-R04 - استعادة بهوية

المسودة مرتبطة بالحساب والمستأجر ونوع النموذج وموضوعه ومخططه. عند تسجيل دخول مختلف أو تبديل منشأة لا تستعد مسودة سابقة تلقائيًا ولا تعرض مقتطفها.

<a id="VCGF-UI-COMP-023-R05"></a>
### VCGF-UI-COMP-023-R05 - خصوصية واحتفاظ

اعتمد قائمة حقول قابلة للحفظ ومساحة ومدة محددتين. التخزين المحلي لا يحمي من XSS بذاته، ولا ينشئ حفظًا دون اتصال للمحتوى الحساس فقط لأن مكتبة IndexedDB متاحة.

<a id="VCGF-UI-COMP-023-R06"></a>
### VCGF-UI-COMP-023-R06 - حماية الانتقال

اربط الانتقال داخل التطبيق بحالة التغييرات وإقرار الحفظ. beforeunload مساعدة محدودة لا ضمان؛ لا تعتمد عليه وحده لحفظ آخر لحظة ولا تمنع الخروج عندما لا توجد تغييرات.

<a id="VCGF-UI-COMP-023-R07"></a>
### VCGF-UI-COMP-023-R07 - المسودة والإرسال النهائي

الحفظ التلقائي لا يرسل الطلب ولا يعتمد الوثيقة. عند الإرسال النهائي تتم مزامنة أو مراجعة اللقطة المطلوبة ثم تحقق كامل ومعاملة منفصلة، وتُنهى المسودة أو تربط بالنتيجة وفق السياسة.

<a id="VCGF-UI-COMP-023-R08"></a>
### VCGF-UI-COMP-023-R08 - استرداد وفشل محدود

فشل الحفظ يعرض إعادة محاولة محدودة أو تصديرًا آمنًا عند الحاجة. انتهاء التخزين أو تغير المخطط أو حذف المسودة لا يؤدي حلقة إرسال غير منتهية، وتُوثق خسارة محتملة بوضوح.

<a id="VCGF-UI-COMP-023-R09"></a>
### VCGF-UI-COMP-023-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-023-R10"></a>
### VCGF-UI-COMP-023-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-023-R11"></a>
### VCGF-UI-COMP-023-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-023-R12"></a>
### VCGF-UI-COMP-023-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `draftKey`, `values`, `schemaVersion`, `allowedFields`, `revision`, `storagePolicy`, `dirtyState`

**الأحداث المفاهيمية:** `saveScheduled`, `saveStarted`, `saveAcknowledged`, `conflictDetected`, `restoreRequested`, `discardConfirmed`

**مصدر السلطة:** خدمة المسودة تحدد الحفظ النهائي للنسخة؛ الذاكرة المحلية والواجهة تمثلان حالة مؤقتة معلنة.

```text
clean -> dirty -> scheduled -> saving -> saved/dirty-again/offline/failed/conflict
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-003](VCGF-UI-COMP-003-SmartFormFields.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- لكل مسودة draftId وrevision وschemaVersion وowner scope؛ السيرفر لا يثق بمعرف owner مرسل بلا تحقق.
- mutation queue تتعامل مع التغييرات أثناء الطلب ومع إلغائه؛ إلغاء fetch لا يثبت أن الخادم لم يحفظ.
- idb يدير IndexedDB ولا يوفر تلقائيًا تشفيرًا أو تفويضًا أو مزامنة متعددة الأجهزة.
- إبقاء قاعدة بيانات محلية بعد تسجيل الخروج قرار سياسة؛ الافتراضي تنظيف النطاق الحساس وإبطال رموزه.
- أي دمج تلقائي يحدد الحقول القابلة للدمج ويمنع دمج قرارات أو مبالغ أو صلاحيات متعارضة بلا مراجعة.

## 6. الوصولية والعربية والتجاوب

- حالة الحفظ نصية هادئة ولا تقطع قارئ الشاشة عند كل ضغطة.
- شاشة التعارض تتيح قراءة النسختين والعمل عليهما دون اعتماد ألوان فرق فقط.
- استعادة المسودة تعرض ملخصًا ووقتًا واضحًا وأزرار قبول أو تجاهل مسماة.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- عودة استجابة حفظ بعد انتقال المستخدم لسجل آخر لا تحدّث شارة السجل الجديد.
- حذف المسودة من جهاز آخر يوقف الكتابة تلقائيًا إلى معرف منتهي ويطلب قرارًا واضحًا.
- تحديث التطبيق أثناء التحرير يحتاج توافق schemaVersion أو مسار استعادة آمن لا إعادة تحميل عمياء.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [TanStack Query / @tanstack/react-query](https://tanstack.com/query/latest/docs/framework/react/overview) | تنسيق حالة البيانات والطلبات وcache وإعادة الجلب. | اضبط query keys وإبطال البيانات حسب المستأجر والصلاحيات؛ ليست محرك تفويض أو قاعدة بيانات. |
| [React Hook Form](https://github.com/react-hook-form/react-hook-form) | إدارة حالة الحقول والنماذج والتحقق في React. | التحقق في العميل لا يستبدل تحقق الخادم؛ وثائق الموقع المباشرة حجبت الجلب فاستُخدم مستودع المشروع الرسمي. |
| [idb](https://github.com/jakearchibald/idb) | واجهة Promise للعمل مع IndexedDB عند اعتماد تخزين محلي. | لا توفر وحدها تشفيرًا أو تفويضًا أو مزامنة، ولا تُستخدم للمحتوى الحساس دون سياسة. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **لا تكتب تم الحفظ قبل إقرار المكان الذي وعدت بالحفظ فيه.**
- **الحفظ التلقائي لا يبرر الكتابة فوق عمل غيرك.**
- **لا تحول حماية الوقت إلى تسريب بيانات على جهاز مشترك.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-023 / DraftAutosaveManager - الحفظ التلقائي والمسودات والتغييرات غير المحفوظة.
حماية وقت المستخدم من انقطاع الاتصال أو الانتقال العرضي، مع تعريف صريح لما حُفظ وأين وبأي إصدار، ومنع الكتابة فوق عمل مستخدم آخر أو تخزين أسرار على الجهاز.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: لا تكتب تم الحفظ قبل إقرار المكان الذي وعدت بالحفظ فيه. الحفظ التلقائي لا يبرر الكتابة فوق عمل غيرك. لا تحول حماية الوقت إلى تسريب بيانات على جهاز مشترك.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر كتابة مستمرة مع طلبين واستجابة متأخرة وانقطاع وتبويبين، ثم بدّل الحساب وحاول استعادة مسودة قديمة وإرسالًا نهائيًا لا يجتاز تحقق الأعمال.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.

- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
