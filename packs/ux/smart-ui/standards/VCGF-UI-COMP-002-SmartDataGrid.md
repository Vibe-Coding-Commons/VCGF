# VCGF-UI-COMP-002 - الجداول الذكية المتقدمة

**SmartDataGrid**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تمكين المستخدم من فحص البيانات ومقارنتها واتخاذ إجراءات على نطاق معلوم، مع الحفاظ على دقة النتائج والأداء والصلاحيات عند نمو عدد السجلات.

**متى ينطبق:** ينطبق على قوائم تشغيلية تحتاج فرزًا أو تصفية أو تخصيص أعمدة أو إجراءات على صفوف. يبدأ بجدول دلالي بسيط ثم يفعّل قدرات إضافية بحسب حجم البيانات والمهمة.

**متى لا ينطبق:** لا يستخدم بدل صفحات القراءة أو تدفقات الموافقة التي تحتاج سياقًا قصصيًا. لا تُضاف افتراضيًا خصائص تعديل خلايا أو تجميع أو تصدير لم يطلبها نطاق العمل.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `pageSize` | `integer` | `25` | `tenant/user` | خيارات 10 و25 و50 و100 ضمن حد الخادم. |
| `paginationMode` | `string` | `"server"` | `system` | client لمجموعة كاملة صغيرة ومعلومة فقط؛ يجب التصريح بنمط البيانات. |
| `selectionScope` | `string` | `"visible-page"` | `system/user` | اختيار جميع النتائج يحتاج إجراء صريحًا ونطاقًا مثبتًا من الخادم. |
| `density` | `string` | `"adaptive"` | `tenant/user` | لا يغيّر القيم أو حقوق العرض. |
| `persistColumns` | `boolean` | `true` | `tenant/user` | يحفظ معرفات الأعمدة وإصدار المخطط لا بيانات الصفوف. |
| `allowInlineEdit` | `boolean` | `false` | `system/tenant` | يتطلب عقد حفظ وتحقق وصلاحية مستقلة لكل حقل. |
| `exportEnabled` | `boolean` | `false` | `system/tenant` | إذن تصدير مستقل؛ لا يكفي إذن العرض. |
| `virtualization` | `string` | `"measured"` | `system` | تُفعّل بعد قياس مع بديل وصولي واختبار التركيز. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-002-R01"></a>
### VCGF-UI-COMP-002-R01 - نمط البيانات الصريح

تستخدم جميع عمليات الفرز والترقيم والتصفية نفس مجموعة البيانات. عند server mode تُرسل الحالة للخادم ولا تُفرز الصفحة المحمّلة فقط بما يوهم أن النتائج كلها مرتبة.

<a id="VCGF-UI-COMP-002-R02"></a>
### VCGF-UI-COMP-002-R02 - هوية الصف

استخدم معرفًا ثابتًا لا رقم الفهرس. حافظ على الاختيار عند إعادة الترتيب وحدث حالة الصف بإصداره، ولا تنقل تحديد سجل إلى سجل آخر يشغل موقعه القديم.

<a id="VCGF-UI-COMP-002-R03"></a>
### VCGF-UI-COMP-002-R03 - نطاق الاختيار الجماعي

فرّق بين تحديد الصفحة وتحديد جميع النتائج المطابقة. اعرض العدد والنطاق قبل التنفيذ، وعند جميع النتائج استخدم query snapshot أو token يقره الخادم مع قائمة استثناءات وإعادة تفويض عند التنفيذ.

<a id="VCGF-UI-COMP-002-R04"></a>
### VCGF-UI-COMP-002-R04 - تفضيلات الأعمدة

ادعم إظهار الأعمدة وترتيبها وتثبيتها وإعادة ضبط العرض حسب الصلاحيات. الأعمدة المحجوبة أمنيًا لا تُرسل أصلًا إلى العميل، ولا يعيدها زر إعادة الضبط.

<a id="VCGF-UI-COMP-002-R05"></a>
### VCGF-UI-COMP-002-R05 - تفاصيل الجوال

وفر عرضًا مناسبًا للمهمة على الجوال مع ملخص وتفاصيل يمكن الوصول إليها، أو تمريرًا أفقيًا واضحًا عند ضرورة المقارنة. لا تسقط معلومات حرجة بمجرد إخفاء عمود.

<a id="VCGF-UI-COMP-002-R06"></a>
### VCGF-UI-COMP-002-R06 - التحديث والتزامن

حافظ على النتائج السابقة أثناء تحديث الخلفية مع وسم عدم حداثتها عند الحاجة. لا تمسح الجدول لمجرد فشل تحديث، ولا تخفي تعارض تعديل صف على أنه نجاح.

<a id="VCGF-UI-COMP-002-R07"></a>
### VCGF-UI-COMP-002-R07 - الإجراءات والتصدير

اربط قائمة إجراءات الصف بقدراته وحالته. التصدير يعيد استخدام النطاق والتفويض من الخادم ولا يعتمد على DOM أو القيم المخفية فقط، وتُعلن أي نتائج جزئية.

<a id="VCGF-UI-COMP-002-R08"></a>
### VCGF-UI-COMP-002-R08 - البحث وحالات الفراغ

ميّز عدم وجود بيانات أصلًا عن عدم وجود نتائج بعد الفلاتر وعن فشل الاتصال. لا يعرض العدد صفرًا أثناء التحميل، ويحافظ تغيير الفلاتر على ترتيب طلبات النتائج.

<a id="VCGF-UI-COMP-002-R09"></a>
### VCGF-UI-COMP-002-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-002-R10"></a>
### VCGF-UI-COMP-002-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-002-R11"></a>
### VCGF-UI-COMP-002-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-002-R12"></a>
### VCGF-UI-COMP-002-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `rows`, `columns`, `rowId`, `pageState`, `sortState`, `filterState`, `selection`, `capabilities`

**الأحداث المفاهيمية:** `queryChanged`, `selectionChanged`, `actionRequested`, `columnPreferencesChanged`

**مصدر السلطة:** الخادم يملك النطاق الكامل والعدد والصلاحيات والقيم المحفوظة؛ الواجهة تملك حالة العرض المؤقتة.

```text
initial-loading -> ready/empty -> refreshing -> ready/stale-error
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-004](VCGF-UI-COMP-004-AdvancedFilterBuilder.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`, `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- استخدم ترتيبًا ثانويًا ثابتًا بالمعرف لتقليل تكرار أو فقد الصفوف عبر الصفحات؛ cursor pagination أنسب لبعض تدفقات البيانات المتغيرة.
- عند inline editing افصل draft cell عن server value ووثق هل الحفظ للخلية أم الصف ولا تربطه بخروج التركيز دون بيان.
- يشمل مفتاح cache المستأجر والمستخدم أو نطاق صلاحياته والفلاتر وإصدار البيانات؛ امسحه عند تبديل الحساب.
- التحديد عبر كل النتائج يتطلب حماية من توسع النطاق ومدة صلاحية واضحة للـsnapshot وإعادة تحقق قبل التنفيذ.
- لا تضف role=grid لجدول قراءة عادي؛ عند اعتماد grid تلتزم بسلوك لوحة المفاتيح كاملًا.

## 6. الوصولية والعربية والتجاوب

- عناوين أعمدة وعلاقة دلالية بالصفوف ومؤشر aria-sort؛ أزرار الفرز بأسماء مفهومة.
- توفير طريقة لإعادة ترتيب الأعمدة وتغيير عرضها دون السحب وحده.
- اختبار virtualization مع قارئ شاشة ومع الصف المحدد عند خروجه من نافذة العرض.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- حذف آخر صف بالصفحة الأخيرة يعيد المستخدم إلى صفحة صالحة دون حلقة إعادة طلب.
- مخطط أعمدة محفوظ قديمًا يتم ترحيله أو تصفيره جزئيًا مع إبقاء الأعمدة الأمنية محجوبة.
- التصدير الكبير يتحول إلى مهمة ذات معرف وحالة؛ إلغاء نافذة الواجهة ليس إثباتًا لإلغاء المهمة.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [TanStack Table / @tanstack/react-table](https://tanstack.com/table/v8/docs/introduction) | أساس headless لبناء سلوك الجداول وتركيب الواجهة حسب الهوية. | ليس جدولًا مكتمل التصميم ولا خدمة استعلام؛ virtualization والتفويض والفرز الخادمي تحتاج دمجًا واختبارًا. |
| [TanStack Query / @tanstack/react-query](https://tanstack.com/query/latest/docs/framework/react/overview) | تنسيق حالة البيانات والطلبات وcache وإعادة الجلب. | اضبط query keys وإبطال البيانات حسب المستأجر والصلاحيات؛ ليست محرك تفويض أو قاعدة بيانات. |
| [AG Grid](https://www.ag-grid.com/license-pricing/) | بديل جدول غني عند الحاجة إلى قدرات جاهزة متقدمة. | راجع الفرق بين Community وEnterprise وترخيص كل خاصية في تاريخ اعتماد المشروع؛ لا تفترض إتاحة جميع القدرات مجانًا. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **لا تخلط فرز الصفحة بفرز قاعدة النتائج.**
- **تحديد الكل وعدد الصفوف عقد أعمال وليس مجرد checkbox.**
- **الجدول أداة للمهمة؛ كثرة الخصائص ليست معيار الجودة.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-002 / SmartDataGrid - الجداول الذكية المتقدمة.
تمكين المستخدم من فحص البيانات ومقارنتها واتخاذ إجراءات على نطاق معلوم، مع الحفاظ على دقة النتائج والأداء والصلاحيات عند نمو عدد السجلات.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: لا تخلط فرز الصفحة بفرز قاعدة النتائج. تحديد الكل وعدد الصفوف عقد أعمال وليس مجرد checkbox. الجدول أداة للمهمة؛ كثرة الخصائص ليست معيار الجودة.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: طبّق قائمة معاملات بمئة ألف سجل، وبحث عربي، وثلاثة أدوار مختلفة، ثم اختبر تحديد الصفحة مقابل جميع النتائج والتصدير وإعادة فتح تخطيط الأعمدة من الجوال.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
