# VCGF-UI-COMP-005 - رفع الملفات وإدارة المرفقات

**SmartFileUploader**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

إنشاء دورة حياة واضحة للمرفق من الاختيار إلى الرفع والفحص والربط بالسجل، بحيث لا تختلط نسبة نقل الملف بسلامته أو اعتماده أو حفظ المعاملة المرتبطة به.

**متى ينطبق:** ينطبق عند إرفاق وثائق أو صور أو ملفات إلى سجلات أو رسائل أو طلبات. يتوسع إلى الرفع المجزأ أو القابل للاستئناف عندما تبرر الأحجام والشبكات ذلك.

**متى لا ينطبق:** لا يضيف محول مستندات أو مضاد فيروسات وهميًا إلى الواجهة، ولا يتيح مصادر سحابية أو روابط خارجية ما لم تعتمدها سياسات المشروع وخدماته الفعلية.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `allowedTypes` | `array` | `[]` | `system/tenant` | قائمة سماح صريحة حسب الوحدة؛ الفارغ يعني الرفع غير مهيأ وليس السماح بكل الأنواع. |
| `maxFileBytes` | `integer` | `0` | `system/tenant` | صفر يعني يتطلب إعدادًا قبل التفعيل؛ لا يفترض حدًا صالحًا لكل مشروع. |
| `maxFiles` | `integer` | `10` | `system/tenant` | قيمة اقتراحية تقيد حسب قواعد العمل. |
| `parallelUploads` | `integer` | `3` | `system/tenant` | حد تجريبي يطابق قدرات الخادم والشبكة. |
| `resumable` | `boolean` | `false` | `system` | يفعّل فقط مع دعم بروتوكول وخادم يملكان الاستئناف فعليًا. |
| `scanPolicy` | `string` | `"required"` | `system` | لا يمكن للمستخدم تخفيف سياسة الفحص؛ يجب كشف عدم توفر الخدمة. |
| `autoAttachOnUpload` | `boolean` | `false` | `system` | الربط بالسجل عملية مستقلة ومفوضة بعد اعتماد المرفق. |
| `temporaryRetentionHours` | `integer` | `24` | `system/tenant` | اقتراح للملفات المؤقتة؛ سياسة المنشأة والحجز القانوني تتقدم عليه. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-005-R01"></a>
### VCGF-UI-COMP-005-R01 - اختيار متاح

وفر زر اختيار ملفات أصليًا مسمى إلى جانب السحب والإفلات. افحص حدود العميل لإعطاء استجابة مبكرة لكن أعد الفحص في الخادم، واجعل الأخطاء مرتبطة بكل ملف.

<a id="VCGF-UI-COMP-005-R02"></a>
### VCGF-UI-COMP-005-R02 - دورة حياة المرفق

اعتمد حالات selected وuploading وuploaded وscanning وready وrejected وattached. اكتمال النقل لا يتيح التنزيل أو الربط قبل نجاح الفحص المقرر، ولا يخفي طابور الفحص تحت رسالة تم الحفظ.

<a id="VCGF-UI-COMP-005-R03"></a>
### VCGF-UI-COMP-005-R03 - إلغاء واستئناف حقيقيان

الإلغاء يتطلب إنهاء عملية الرفع أو تعليمها ملغاة في الخادم وتنظيف الأجزاء وفق السياسة. عند الاستئناف تحقق من صاحب الجلسة وتطابق الملف ولا تعتمد الاسم والحجم وحدهما.

<a id="VCGF-UI-COMP-005-R04"></a>
### VCGF-UI-COMP-005-R04 - تحقق دفاعي

تحقق في الخادم من الحجم والنوع الفعلي والتواقيع والامتدادات المسموحة والصلاحيات. امنع تنفيذ الملفات المرفوعة، وعالج الملفات المضغوطة وحدود استخراجها كمسار مستقل لا كنوع آمن تلقائيًا.

<a id="VCGF-UI-COMP-005-R05"></a>
### VCGF-UI-COMP-005-R05 - تخزين وروابط

خزن بمعرف داخلي واسم آمن، واحتفظ بالاسم الأصلي كبيانات وصفية مطهرة فقط. تنزيل الملف المحمي يحتاج تفويضًا فعليًا أو رابطًا قصير العمر حسب السياسة، ولا يعتمد على صعوبة تخمين المسار.

<a id="VCGF-UI-COMP-005-R06"></a>
### VCGF-UI-COMP-005-R06 - ربط المعاملة

اربط معرف الملف المعتمد بالسجل بإجراء يتحقق من ملكيته وحالته وإصداره. إذا فشل حفظ النموذج لا يدّعي رفع المرفق حفظ المعاملة، وتُعالج الملفات اليتيمة بعملية تنظيف محددة.

<a id="VCGF-UI-COMP-005-R07"></a>
### VCGF-UI-COMP-005-R07 - التكرار والترتيب

عرّف سياسة التكرار هل تقارن المحتوى أم الاسم أم تسمح بنسخ متعددة. إعادة ترتيب المرفقات تغيّر ترتيب العرض فقط ولا تعيد رفعها، وحذف مرفق مرتبط لا يحدث بلا صلاحية وأثر واضح.

<a id="VCGF-UI-COMP-005-R08"></a>
### VCGF-UI-COMP-005-R08 - إخفاق الفحص

عند تعطل خدمة الفحص لا تُحوّل الحالة إلى آمن تلقائيًا. وفر تعليقًا وإعادة محاولة مفوضة ومهلة موثقة، واعرض للمستخدم ما يمكنه فعله دون كشف عينة محتوى خطرة.

<a id="VCGF-UI-COMP-005-R09"></a>
### VCGF-UI-COMP-005-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-005-R10"></a>
### VCGF-UI-COMP-005-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-005-R11"></a>
### VCGF-UI-COMP-005-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-005-R12"></a>
### VCGF-UI-COMP-005-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `uploadPolicy`, `files`, `recordContext`, `capabilities`, `transportAdapter`

**الأحداث المفاهيمية:** `filesAdded`, `transferProgress`, `scanStateChanged`, `attachmentLinked`, `cancelRequested`

**مصدر السلطة:** الخادم يملك حالة الرفع والفحص والربط والأذونات؛ نسبة المتصفح ليست دليل اكتمال الأعمال.

```text
selected -> uploading -> uploaded -> scanning -> ready -> attached; rejected/canceled/expired
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

## 5. النقاط الهندسية وحدود المسؤولية

- فصل معرف جلسة الرفع عن معرف المرفق النهائي ومنع إعادة استخدام الجلسة لملف أو مستأجر آخر.
- طبق حدودًا على الطلب والأجزاء والحجم الكلي والعدد والتزامن؛ حدود الواجهة وحدها غير كافية.
- خزّن الملفات خارج مسار التنفيذ العام واستخدم خدمة تنزيل تفوض الوصول وتضبط Content-Type وContent-Disposition.
- المرفقات من URL تحتاج حماية SSRF وفحص الوجهة وإعادة التوجيه والمهلات؛ لا تفعل هذا المسار ضمنيًا.
- لا ترفع البيانات إلى خدمة خارجية أو OCR سحابي دون سياسة معلنة وموافقة نطاق المعالجة.

## 6. الوصولية والعربية والتجاوب

- لا تجعل السحب والإفلات الوسيلة الوحيدة؛ زر الإضافة والإلغاء وإعادة المحاولة مسمى وقابل للوحة المفاتيح.
- أعلن مراحل مهمة فقط في live region لا كل نسبة تقدم صغيرة.
- تمييز أسباب الرفض بالنص، وعرض أسماء الملفات الطويلة دون تعطيل فهم الامتداد.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- انتهاء صلاحية الرابط أثناء الاستئناف يعالج بتجديد مفوض لا تجاوز المصادقة.
- إغلاق الشاشة أثناء الفحص لا يحذف الحالة؛ تعاد قراءتها من خدمة الملفات عند العودة.
- الحجز القانوني أو الارتباط بوثيقة نهائية يمنع الحذف حتى لو ظهرت صلاحية حذف عامة.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [Uppy / @uppy/core](https://uppy.io/docs/) | أساس رفع ملفات قابل للتركيب مع نقل ومصادر وواجهات اختيارية. | استئناف tus يتطلب ناقلًا وخادمًا متوافقين؛ الفحص والربط والصلاحيات ليست ميزات أمان مكتملة بالواجهة. |
| [FilePond](https://pqina.nl/filepond/docs/) | بديل لإدارة اختيار الملفات وتجربة الرفع مع adapters متعددة. | تحقق من إضافات المشروع وخدمة النقل وسياسة التحقق في الخادم قبل إعلان الدعم. |
| [react-dropzone](https://react-dropzone.js.org/) | اختيار الملفات والسحب والإفلات في React. | ليس uploader خادميًا ولا فحصًا أمنيًا؛ اربطه بناقل وخدمة ملفات مستقلين. |

## 9. الوصايا الذهبية

- **مئة بالمئة نقل لا تعني مئة بالمئة سلامة أو اعتماد.**
- **لا تمنح معرفة الرابط صلاحية الوصول.**
- **لا تدّع الاستئناف أو الفحص دون خدمة خادم تثبتهما.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-005 / SmartFileUploader - رفع الملفات وإدارة المرفقات.
إنشاء دورة حياة واضحة للمرفق من الاختيار إلى الرفع والفحص والربط بالسجل، بحيث لا تختلط نسبة نقل الملف بسلامته أو اعتماده أو حفظ المعاملة المرتبطة به.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: مئة بالمئة نقل لا تعني مئة بالمئة سلامة أو اعتماد. لا تمنح معرفة الرابط صلاحية الوصول. لا تدّع الاستئناف أو الفحص دون خدمة خادم تثبتهما.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر رفع عدة ملفات من شبكة متقطعة مع رفض نوع مضلل وتعطل الفحص وانتهاء الجلسة، ثم احفظ النموذج مرة واحدة وتحقق من عدم ترك مرفقات يتيمة مكشوفة.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
