# VCGF-UI-COMP-003 - النماذج والتحقق الذكي الموحد

**SmartFormFields**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تقليل أخطاء الإدخال وحفظ جهد المستخدم، مع فصل قواعد البيانات والأعمال عن تجميع الحقول وطريقة عرضها والتحقق المبكر داخل المتصفح.

**متى ينطبق:** ينطبق على إنشاء السجلات وتعديلها والبحث المتقدم والنماذج المشروطة. يوسع النموذج القائم ولا ينقل المشروع إلى مكتبة جديدة لمجرد التشابه البصري.

**متى لا ينطبق:** لا يستبدل تحقق الخادم، ولا يطلب حقولًا لا يحتاجها الإجراء، ولا يتحول كل نموذج قصير إلى مولّد نماذج ديناميكي معقد.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `validationMode` | `string` | `"blur-then-change"` | `system/tenant` | تحقق عند الخروج ثم عند تعديل حقل أخطأ؛ القاعدة تتكيف مع نوع الحقل. |
| `showErrorSummary` | `boolean` | `true` | `system` | للنماذج الطويلة أو متعددة الأخطاء؛ يربط كل خطأ بحقل. |
| `preserveValuesOnError` | `boolean` | `true` | `system` | لا يحفظ كلمات المرور في التخزين الدائم. |
| `requiredIndicator` | `string` | `"text-and-symbol"` | `tenant` | التسمية متاحة ولا تعتمد على النجمة أو اللون وحدهما. |
| `submitPolicy` | `string` | `"single-inflight"` | `system` | لا يغني عن idempotency للعمليات ذات الأثر. |
| `manualInput` | `boolean` | `true` | `tenant` | يمكن تقييده فقط عندما يستلزم نوع الحقل ذلك وببديل متاح. |
| `conditionalValuePolicy` | `string` | `"explicit-per-field"` | `system` | يُحسم حفظ أو حذف قيمة الحقل المخفي ولا يترك ضمنيًا. |
| `unsavedChangesGuard` | `boolean` | `true` | `tenant` | مناسب للنماذج ذات التعديل؛ لا يعترض القراءة فقط. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-003-R01"></a>
### VCGF-UI-COMP-003-R01 - المعنى والتسمية

لكل حقل اسم وظيفي دائم ووصف عند الحاجة وحالة required معلنة. لا يُستخدم placeholder بديلًا عن label، ويميز النظام بين disabled وreadonly لأنهما يختلفان وظيفيًا.

<a id="VCGF-UI-COMP-003-R02"></a>
### VCGF-UI-COMP-003-R02 - تحقق غير معيق

ابدأ التحقق في الوقت المناسب ولا تعرض أخطاء قبل أن تتاح للمستخدم فرصة الإدخال. عند ظهور خطأ يعاد تقييمه أثناء التصحيح، ولا يُمنع إدخال نص مؤقت مشروع مثل إشارة سالبة في حقل رقمي.

<a id="VCGF-UI-COMP-003-R03"></a>
### VCGF-UI-COMP-003-R03 - الخادم مرجع

أعد التحقق من النوع والطول والعلاقات والتفرّد والصلاحيات في الخادم. حوّل أخطاء الخادم إلى حقول أو رسالة عامة مفهومة دون تسريب تفاصيل SQL أو أسماء داخلية.

<a id="VCGF-UI-COMP-003-R04"></a>
### VCGF-UI-COMP-003-R04 - الحفاظ على العمل

لا تصفّر الحقول عند فشل الشبكة أو تحديث بيانات الخلفية أو تبديل اللغة. ميّز القيم dirty من قيم الخادم ولا تعوّض الأولى تلقائيًا أثناء refetch.

<a id="VCGF-UI-COMP-003-R05"></a>
### VCGF-UI-COMP-003-R05 - حقول شرطية

وثق أثر إخفاء حقل على required وقيمته وطلب الحفظ. البيانات المخفية لا تقبل كتفويض ضمني، ولا يعيد تغيير شرط سريع قيمة قديمة لم تعد صالحة.

<a id="VCGF-UI-COMP-003-R06"></a>
### VCGF-UI-COMP-003-R06 - إرسال قابل للتتبع

عند الإرسال أظهر حالة معلومة وامنع الضغط المتكرر، واستخدم مفتاح عملية للخادم حيث يلزم. استجابة نجاح الحفظ ليست نجاحًا لإجراءات جانبية لم تنته بعد.

<a id="VCGF-UI-COMP-003-R07"></a>
### VCGF-UI-COMP-003-R07 - أخطاء قابلة للإصلاح

اعرض ملخص أخطاء قابلًا للانتقال إلى الحقول، مع الحفاظ على موضع مناسب للتركيز. الحقل داخل تبويب أو مرحلة غير ظاهرة يُكشف قبل نقله إلى التركيز.

<a id="VCGF-UI-COMP-003-R08"></a>
### VCGF-UI-COMP-003-R08 - أنواع وقيم صريحة

افصل empty وnull وzero وfalse وغياب المفتاح. لا تستخدم التحويل الضمني الذي يجعل الصفر فارغًا، واستخدم معرفات فعلية للاختيارات وخدمة التاريخ والأرقام المشتركة.

<a id="VCGF-UI-COMP-003-R09"></a>
### VCGF-UI-COMP-003-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-003-R10"></a>
### VCGF-UI-COMP-003-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-003-R11"></a>
### VCGF-UI-COMP-003-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-003-R12"></a>
### VCGF-UI-COMP-003-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `schema`, `initialValues`, `fieldPolicy`, `serverErrors`, `submitState`, `dirtyFields`

**الأحداث المفاهيمية:** `valueChanged`, `validated`, `submitRequested`, `resetRequested`, `conflictDetected`

**مصدر السلطة:** مخطط الواجهة لتحسين التجربة؛ الخادم مرجع صحة البيانات والتفويض والحفظ.

```text
pristine -> dirty -> validating -> submitting -> saved/invalid/network-error/conflict
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`, `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- اعتمد مخططًا صريحًا للمدخلات المسموحة ولا تمرر كامل كائن النموذج إلى ORM دون قائمة حقول مقبولة.
- التحقق غير المتزامن مثل التفرّد يحتاج إلغاء أو تجاهل الاستجابة القديمة ولا يمنح حجزًا دائمًا للقيمة.
- قيد الرندر بالحقول المتأثرة عند النماذج الكبيرة؛ لا تربط كل ضغطة بإعادة بناء جميع الحقول.
- لا تحفظ أسرار الجلسة أو OTP أو كلمات المرور داخل draft أو analytics أو رسائل الأخطاء.
- عند ترحيل مخطط النموذج حافظ على معنى البيانات القديمة ووثق الحقول المحذوفة وطريقة التعامل معها.

## 6. الوصولية والعربية والتجاوب

- اربط الأخطاء بالحقول عبر aria-describedby وaria-invalid حسب الحاجة مع label صحيح.
- لا تعتمد اللون وحده؛ انقل التركيز وفق نية المستخدم ولا تقفز به عند كل تحقق.
- دعم تكبير النص والكتابة العربية المختلطة وIME واللصق ومديري كلمات المرور في الحقول المناسبة.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- فشل حفظ بعد انتهاء الجلسة يحافظ على بيانات غير حساسة ضمن السياسة ويطلب تسجيلًا جديدًا دون إعادة إرسال عمياء.
- عنصر اختيار محفوظ لم يعد متاحًا يُعرض كقيمة غير صالحة تحتاج معالجة، ولا يتبدل تلقائيًا لأول عنصر.
- حقول الملفات تحتاج ارتباطًا بمعرف رفع مكتمل ومعتمد، لا مسار محلي من جهاز المستخدم.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [React Hook Form](https://github.com/react-hook-form/react-hook-form) | إدارة حالة الحقول والنماذج والتحقق في React. | التحقق في العميل لا يستبدل تحقق الخادم؛ وثائق الموقع المباشرة حجبت الجلب فاستُخدم مستودع المشروع الرسمي. |
| [Zod](https://zod.dev/) | مخططات للتحقق من مدخلات TypeScript واستنتاج أنواعها. | تحقق من توافق resolver والإصدار؛ لا تفترض تطابقًا تلقائيًا مع قواعد خادم بلغة أخرى. |
| [TanStack Form](https://tanstack.com/form/latest) | بديل لإدارة نماذج ذات احتياج إلى تحكم وتحقق منظم. | اختره أو حل النماذج المناسب الموجود؛ لا تجمع محركي نماذج لنفس النموذج بلا حاجة. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **لا تفقد عمل المستخدم بسبب خطأ واحد قابل للإصلاح.**
- **التحقق في المتصفح تجربة استخدام وليس حاجز أمان.**
- **لا تخلط غياب القيمة مع الصفر أو false.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-003 / SmartFormFields - النماذج والتحقق الذكي الموحد.
تقليل أخطاء الإدخال وحفظ جهد المستخدم، مع فصل قواعد البيانات والأعمال عن تجميع الحقول وطريقة عرضها والتحقق المبكر داخل المتصفح.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: لا تفقد عمل المستخدم بسبب خطأ واحد قابل للإصلاح. التحقق في المتصفح تجربة استخدام وليس حاجز أمان. لا تخلط غياب القيمة مع الصفر أو false.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: جهز نموذج عميل مشروط النوع بمدخلات عربية وهاتف وتاريخ ومرفقات، ثم أثبت بقاء القيم مع خطأ خادم وتبديل اللغة وتحديث خلفي ونقر إرسال مكرر.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
