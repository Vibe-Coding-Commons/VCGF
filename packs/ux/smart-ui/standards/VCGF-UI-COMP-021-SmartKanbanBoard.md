# VCGF-UI-COMP-021 - لوحات كانبان والسحب والإفلات المنضبط

**SmartKanbanBoard**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تمثيل العمل بحسب الحالات أو الأعمدة مع نقل وترتيب يمكن فهم أثرهما والتراجع عن تمثيلهما عند الرفض، دون تحويل حركة بطاقة إلى قرار أعمال غير مفوض.

**متى ينطبق:** ينطبق على مهام أو فرص أو حالات عمل يستفيد المستخدم من رؤيتها موزعة على أعمدة. يضاف السحب عندما لا يضر بالوصولية أو دقة التنفيذ.

**متى لا ينطبق:** لا يعد نقل بطاقة اعتمادًا أو إنجازًا بحد ذاته، ولا يفرض كانبان على بيانات تحتاج مقارنة أعمدة رقمية دقيقة، ولا يستخدم السحب كوسيلة وحيدة للإجراء.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `columnSource` | `string` | `"workflow-or-domain"` | `system` | أعمدة مرتبطة بمعاني حالات موثقة لا تسميات حرة فقط. |
| `dragEnabled` | `boolean` | `true` | `system/tenant` | يتوقف للصفوف غير المفوضة مع بديل قائم. |
| `keyboardMove` | `boolean` | `true` | `system` | أو قائمة نقل مكافئة متاحة؛ لا يعتمد النجاح على الفأرة. |
| `wipLimitMode` | `string` | `"advisory"` | `system/tenant` | advisory أو enforced بعقد أعمال؛ لا يلتبس التحذير بالمنع. |
| `optimisticMove` | `string` | `"reversible-low-risk"` | `system` | الانتقالات الحساسة تنتظر الخادم ولا تبدو نهائية مسبقًا. |
| `cardDensity` | `string` | `"adaptive"` | `tenant/user` | تظهر المعلومات اللازمة للقرار لا زخارف بلا فائدة. |
| `loadMode` | `string` | `"per-column"` | `system` | تحميل تدريجي مع عدادات معرفة النطاق. |
| `sortPolicy` | `string` | `"domain-or-manual"` | `system` | السحب للترتيب لا يعمل حين يفرض الفرز الآلي معنى مختلفًا. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-021-R01"></a>
### VCGF-UI-COMP-021-R01 - معنى الأعمدة

اربط columnId بالحالة أو المجموعة والمعرف المرجعي. لا يؤدي تغيير اسم عمود مترجم إلى تغيير حالة السجل، ووضح إذا كان العمود تصنيفًا لا مرحلة عمل.

<a id="VCGF-UI-COMP-021-R02"></a>
### VCGF-UI-COMP-021-R02 - نقل له عقد

قبل النقل تحقق من المسارات الممكنة والحقول المطلوبة، ثم أرسل أمرًا مفوضًا بالخادم مع إصدار السجل. نقل إلى مكتمل قد يحتاج أدلة أو تأكيدًا ولا يختصرها السحب.

<a id="VCGF-UI-COMP-021-R03"></a>
### VCGF-UI-COMP-021-R03 - بديل للسحب

وفر قائمة نقل أو أزرارًا أو نمط لوحة مفاتيح يحقق نفس النتيجة. التفاعل باللمس لا يمنع التمرير الطبيعي، ولا يتطلب موضع إسقاط دقيقًا بلا بديل.

<a id="VCGF-UI-COMP-021-R04"></a>
### VCGF-UI-COMP-021-R04 - نقل متفائل محدود

يمكن تمثيل نقل منخفض المخاطر مؤقتًا مع pending واضح، ويعود للوضع الصحيح عند الرفض. الاعتماد أو إغلاق معاملة مالية لا يُظهر نجاحًا نهائيًا قبل إقرار الخادم.

<a id="VCGF-UI-COMP-021-R05"></a>
### VCGF-UI-COMP-021-R05 - ترتيب ثابت

استخدم هوية ثابتة ومفتاح ترتيب موثق لا فهرس DOM. عند فرز آلي اجعل إعادة الترتيب معطلة أو اعرض أنها ستغير نمط الفرز، ولا تنشر ترتيبًا محليًا كأنه معتمد.

<a id="VCGF-UI-COMP-021-R06"></a>
### VCGF-UI-COMP-021-R06 - حدود العمل الجاري

إذا كانت WIP enforced فتنفذ في الخادم مع التزامن؛ إذا advisory يظهر تحذير فقط. عدد البطاقات المرئية لا يمثل كامل العمود عند التحميل الجزئي.

<a id="VCGF-UI-COMP-021-R07"></a>
### VCGF-UI-COMP-021-R07 - تحديثات متزامنة

عند انتقال بطاقة من مستخدم آخر أثناء سحبها اكتشف النسخة القديمة ولا تعكس التغيير بصمت. قدم تحديثًا أو حلًا مفهومًا مع المحافظة على سياق اللوحة.

<a id="VCGF-UI-COMP-021-R08"></a>
### VCGF-UI-COMP-021-R08 - تحميل وعدادات

حمل الأعمدة والبطاقات تدريجيًا، ووضح هل العدد كلي أو مرئي أو تقديري. فلاتر اللوحة وتصديرها وإجراءاتها تشترك في النطاق والصلاحيات، ولا تكشف عدادات الأعمدة المحجوبة.

<a id="VCGF-UI-COMP-021-R09"></a>
### VCGF-UI-COMP-021-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-021-R10"></a>
### VCGF-UI-COMP-021-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-021-R11"></a>
### VCGF-UI-COMP-021-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-021-R12"></a>
### VCGF-UI-COMP-021-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `columns`, `cards`, `workflowCapabilities`, `orderingPolicy`, `wipPolicy`, `queryContext`

**الأحداث المفاهيمية:** `moveRequested`, `reorderRequested`, `moveResolved`, `loadMoreRequested`, `conflictDetected`

**مصدر السلطة:** الخادم يملك الحالة والترتيب والحدود؛ اللوحة تصوّرها وتطلب تغييرًا مفوضًا.

```text
ready -> dragging/move-menu -> confirming? -> pending -> committed/reverted/conflict
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-007](VCGF-UI-COMP-007-AdaptiveOverlay.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- افصل order command عن transition command؛ لكل منهما تحقق وأثر مختلفان.
- لا تخزن الحالة من الاسم المترجم أو موضع العمود؛ stateId مرجع أعمال ثابت.
- خوارزمية ترتيب متزامن تحتاج سياسة تعارض وإعادة توازن عند استخدام fractional indexing أو بديله.
- كاش البطاقات لا يتسرب بين المستأجرين، والتحديث اللحظي لا يرسل أحداث بطاقات خارج الصلاحية.
- سحب بطاقة كبيرة يستخدم preview خفيفًا ولا يحرك كامل DOM بطريقة تعطل التمرير أو القراءة.

## 6. الوصولية والعربية والتجاوب

- اسم البطاقة وحالتها ووجهتها معلومة، مع إعلانات نقل مختصرة عند الحاجة.
- بديل غير قائم على السحب للإجراء وفق نفس صلاحياته وقواعده.
- على الهاتف يمكن الانتقال بين الأعمدة أو عرض قائمة مكافئة دون فقد المعلومات الحرجة.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- حذف العمود أو البطاقة أثناء السحب يلغي العملية بأمان ولا ينشئ وجهة غير موجودة.
- تحميل جزء من عمود لا يسمح بالادعاء أن إعادة ترتيب موضعه العالمي حُسمت من مواضع محلية فقط.
- تبديل الفلاتر أثناء انتقال pending لا يخفي نتيجة العملية أو ينقلها إلى بطاقة أخرى.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [dnd kit](https://dndkit.com/) | أساس للسحب والإفلات مع adapters بحسب التقنية والإصدار. | أسماء الحزم وواجهاتها تختلف عبر الأجيال؛ اختر adapter الموثق للإصدار المثبت ولا تخلط أمثلة أجيال مختلفة. |
| [shadcn/ui](https://ui.shadcn.com/docs/components) | مكوّنات قابلة للتخصيص ضمن نظام تصميم React مناسب. | افحص primitive والبنية في الإصدار الفعلي؛ لا تفترض أن كل Combobox يضع البحث داخل النافذة، ولا تثبّت كل المكوّنات دفعة واحدة. |
| [TanStack Query / @tanstack/react-query](https://tanstack.com/query/latest/docs/framework/react/overview) | تنسيق حالة البيانات والطلبات وcache وإعادة الجلب. | اضبط query keys وإبطال البيانات حسب المستأجر والصلاحيات؛ ليست محرك تفويض أو قاعدة بيانات. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **تحريك البطاقة لا ينجز العمل الذي تمثله.**
- **لا تجعل السحب شرطًا للاستخدام.**
- **عدد المرئي ليس حد العمل الجاري الكامل.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

**Then - النتيجة المطلوبة:** يرفض تجاوز القيد ولا تنتقل بيانات أو إعدادات خاصة بالمنشأة أ إلى ب؛ تبقى الإعدادات العامة المسموحة فقط.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-021 / SmartKanbanBoard - لوحات كانبان والسحب والإفلات المنضبط.
تمثيل العمل بحسب الحالات أو الأعمدة مع نقل وترتيب يمكن فهم أثرهما والتراجع عن تمثيلهما عند الرفض، دون تحويل حركة بطاقة إلى قرار أعمال غير مفوض.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: تحريك البطاقة لا ينجز العمل الذي تمثله. لا تجعل السحب شرطًا للاستخدام. عدد المرئي ليس حد العمل الجاري الكامل.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر نقل بطاقة باشتراط سبب وحد WIP وتحديث متزامن، ثم نفذ النقل نفسه بلوحة المفاتيح والهاتف مع رفض خادم ورجوع الحالة الصحيحة.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.

- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
