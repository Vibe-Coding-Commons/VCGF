# VCGF-UI-COMP-022 - المواعيد والموارد والجداول الزمنية

**UnifiedScheduler**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تمثيل مواعيد وحجوزات تشير إلى وقت ومعنى متفق عليهما عبر المناطق والتقاويم، مع منع التعارض في الخادم وعدم الخلط بين تفضيل عرض التاريخ وقواعد التكرار.

**متى ينطبق:** ينطبق على الاجتماعات والحجوزات والورديات والموارد عندما يحتاج المشروع عرضًا يوميًا أو أسبوعيًا أو شهريًا أو قائمة مواعيد.

**متى لا ينطبق:** لا يفترض دعم أم القرى أو التكرار الهجري في مكتبة جدولة لمجرد دعم locale عربية، ولا يجعل اختيار وقت متاح في الشاشة ضمانًا لحجزه.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `timeZone` | `string` | `"Asia/Riyadh"` | `system/tenant` | افتراضي مقترح للمشروعات السعودية؛ يسجل IANA zone لكل سياق لازم. |
| `defaultView` | `string` | `"week"` | `tenant/user` | day أو week أو month أو list بحسب المهمة والجهاز. |
| `slotMinutes` | `integer` | `30` | `system/tenant` | اقتراح يطابق دقة الحجز وقواعد المورد. |
| `workingCalendar` | `string` | `"tenant-defined"` | `system/tenant` | أيام وساعات وإجازات صريحة؛ لا تفترض الأحد إلى الخميس لكل مشروع. |
| `conflictPolicy` | `string` | `"reject"` | `system/tenant` | السماح بالتجاوز يتطلب صلاحية وسببًا وقاعدة واضحة. |
| `recurrenceEnabled` | `boolean` | `false` | `system/tenant` | التفعيل يحتاج تعريف تقويم التكرار ومنطق الاستثناءات. |
| `hijriRecurrence` | `boolean` | `false` | `system` | لا يفعل إلا بمحرك أم القرى وضبط محلي وعقد تكرار مختبر. |
| `displayCalendar` | `string` | `"external-calendar-policy"` | `system/user` | يرث المعيار المرتبط دون إنشاء تحويل مستقل. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-022-R01"></a>
### VCGF-UI-COMP-022-R01 - أنواع زمنية مختلفة

افصل حدث all-day بتاريخ مجرد عن موعد بلحظة زمنية وعن تكرار بوقت محلي. لا تحوّل كل تاريخ إلى منتصف الليل UTC، واحتفظ بالمنطقة الأصلية عندما يلزم معنى التكرار.

<a id="VCGF-UI-COMP-022-R02"></a>
### VCGF-UI-COMP-022-R02 - إنشاء مع سياق

اعرض التاريخ والوقت والمدة والمنطقة والمورد والمشاركين قبل التأكيد. وقت بلا منطقة أو مورد غير متاح لا يتحول إلى حجز ضمني؛ يمر التحقق بالخادم.

<a id="VCGF-UI-COMP-022-R03"></a>
### VCGF-UI-COMP-022-R03 - تعارض ذري

منع الحجز المتعارض يحتاج قيدًا أو معاملة أو قفلًا مناسبًا في الخادم. لا تعتمد على استعلام توفر سابق منفصل عن عملية الإنشاء دون حماية التزامن.

<a id="VCGF-UI-COMP-022-R04"></a>
### VCGF-UI-COMP-022-R04 - تكرار واستثناءات

احفظ قاعدة التكرار وتقويمها ومنطقتها واستثناءاتها ومعرف السلسلة. عند تعديل موعد متكرر اسأل هل هذا الحدث أم التالي أم السلسلة وفق ما تدعمه الخدمة فعلًا.

<a id="VCGF-UI-COMP-022-R05"></a>
### VCGF-UI-COMP-022-R05 - توقيت صيفي وحدود

عند دعم مناطق فيها توقيت صيفي عالج الوقت غير الموجود أو المكرر بسياسة معلنة. لا تخمن الانحياز عند الإدخال الملتبس ولا تعتمد timezone المتصفح وحدها.

<a id="VCGF-UI-COMP-022-R06"></a>
### VCGF-UI-COMP-022-R06 - تقويم هجري مضبوط

عرض التاريخ الهجري يستخدم الخدمة المركزية، أما تكرار شهري هجري فهو قاعدة أعمال مستقلة. تغيير ضبط أم القرى للعرض لا يعيد جدولة مواعيد مؤكدة أو توقيعات زمنية تلقائيًا.

<a id="VCGF-UI-COMP-022-R07"></a>
### VCGF-UI-COMP-022-R07 - سحب وتغيير مدة

سحب الموعد أو مد حافته يقدم تغييرًا قابلًا للمراجعة والتحقق لا نجاحًا محليًا نهائيًا. وفّر نموذج تعديل بديلًا، وأعد الحالة عند رفض الخادم أو التعارض.

<a id="VCGF-UI-COMP-022-R08"></a>
### VCGF-UI-COMP-022-R08 - إشعارات وتحديثات

التذكير والإلغاء والدعوات تعتمد خدمة مهام موثوقة لا مؤقت صفحة مفتوحة. فرق نجاح تحديث الحجز عن تسليم الدعوة، واحتفظ بإصدار الحدث لمنع تحديث قديم من استبدال الأحدث.

<a id="VCGF-UI-COMP-022-R09"></a>
### VCGF-UI-COMP-022-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-022-R10"></a>
### VCGF-UI-COMP-022-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-022-R11"></a>
### VCGF-UI-COMP-022-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-022-R12"></a>
### VCGF-UI-COMP-022-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `events`, `resources`, `calendarPolicy`, `timeZone`, `visibleRange`, `recurrencePolicy`, `capabilities`

**الأحداث المفاهيمية:** `slotSelected`, `eventCreateRequested`, `eventMoveRequested`, `recurrenceScopeChosen`, `rangeChanged`

**مصدر السلطة:** خدمة الحجز تملك التوفر والتعارض والوقت والتكرار؛ العارض يطلب ويعرض النتائج.

```text
loading -> ready -> draft -> availability-check -> committing -> confirmed/conflict/error
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-003](VCGF-UI-COMP-003-SmartFormFields.md) - [VCGF-UI-COMP-007](VCGF-UI-COMP-007-AdaptiveOverlay.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`, `searchable_select`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- استعمل مددًا وحدودًا محددة شاملة أو نصف مفتوحة؛ لا تمنع مواعيد متجاورة إذا كانت السياسة تسمح نهاية حدث تساوي بداية التالي.
- الفترات المشغولة قد تكون حساسة؛ free-busy لا يكشف عناوين الأحداث دون صلاحية.
- دعم التقاويم المتعددة لا يساوي دعم السلاسل المتكررة عبرها؛ وثق حدود مكتبة الجدولة والمحرك.
- إصدار قاعدة التكرار وضبط التقويم مهم لإعادة توليد الوقائع؛ لا تولد تاريخًا غير محدود في المتصفح.
- مراجعة تراخيص عرض الموارد أو timeline المتقدم قبل الالتزام بالخصائص أو إدراج حزمة تجارية.

## 6. الوصولية والعربية والتجاوب

- وفر عرض قائمة نصي للمواعيد ووسيلة إنشاء وتعديل دون السحب.
- أسماء الأحداث تتضمن الوقت والمنطقة أو المورد عند الحاجة، مع عدم الاعتماد على اللون وحده.
- اختبر شبكة الأيام بلوحة المفاتيح والتركيز والعودة بعد فتح نافذة التفاصيل.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- إجازة جديدة لا تلغي مواعيد مؤكدة بصمت؛ تحتاج سياسة إخطار وإعادة جدولة.
- تغيير منطقة المستخدم يغير التمثيل لا معنى موعد مؤكد، إلا في قواعد floating time المعلنة.
- حدث شهري في يوم لا يوجد ببعض الشهور يحتاج سياسة تخطي أو آخر يوم ولا يخمنها العارض.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [FullCalendar](https://fullcalendar.io/docs) | واجهة تقويم وجدولة مع عروض وملحقات متعددة. | راجع رخصة الموارد وTimeline والقدرات المتقدمة؛ العربية ليست إثبات أم القرى أو التكرار الهجري. |
| [React Big Calendar](https://github.com/bigcalendar/react-big-calendar) | بديل عرض مواعيد لتطبيقات React. | localizer وإدارة المناطق والتكرار والتعارض مسؤوليات تكامل؛ لا تفترض دعم أم القرى المطلوب. |
| [shadcn/ui](https://ui.shadcn.com/docs/components) | مكوّنات قابلة للتخصيص ضمن نظام تصميم React مناسب. | افحص primitive والبنية في الإصدار الفعلي؛ لا تفترض أن كل Combobox يضع البحث داخل النافذة، ولا تثبّت كل المكوّنات دفعة واحدة. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **وقت يبدو فارغًا ليس حجزًا مضمونًا.**
- **عرض هجري لا يساوي تكرارًا هجريًا.**
- **تغيير تمثيل التاريخ لا يعيد كتابة المواعيد المؤكدة.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-022 / UnifiedScheduler - المواعيد والموارد والجداول الزمنية.
تمثيل مواعيد وحجوزات تشير إلى وقت ومعنى متفق عليهما عبر المناطق والتقاويم، مع منع التعارض في الخادم وعدم الخلط بين تفضيل عرض التاريخ وقواعد التكرار.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: وقت يبدو فارغًا ليس حجزًا مضمونًا. عرض هجري لا يساوي تكرارًا هجريًا. تغيير تمثيل التاريخ لا يعيد كتابة المواعيد المؤكدة.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر موردًا واحدًا بحجزين متزامنين وسلسلة متكررة وحدث يوم كامل ومنطقة ذات توقيت صيفي، ثم غيّر ضبط العرض الهجري وتحقق من ثبات المواعيد الأصلية.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
