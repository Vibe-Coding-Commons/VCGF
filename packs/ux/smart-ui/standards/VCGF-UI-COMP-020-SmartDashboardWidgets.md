# VCGF-UI-COMP-020 - لوحات المعلومات والمؤشرات والرسوم

**SmartDashboardWidgets**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

عرض مؤشرات قابلة للتفسير والتتبع إلى بياناتها، لا أرقام جذابة بلا تعريف أو سياق، مع مراعاة حداثة المعلومات ونطاق الصلاحيات والاختلاف بين الصفر وعدم توفر البيانات.

**متى ينطبق:** ينطبق على صفحات متابعة تدعم قرارات تشغيلية أو تحليلية محددة. تختار المؤشرات والرسوم حسب السؤال والمستخدم لا لأن القالب يوفرها.

**متى لا ينطبق:** لا تضيف رسومًا وهمية أو مؤشرات تجريبية إلى بيئة إنتاج، ولا تعتبر مكتبة الرسوم محرك حساب أو دليلاً على صحة KPI، ولا تستنتج علاقة سببية من رسم ارتباط.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `defaultPeriod` | `string` | `"domain-defined"` | `system/tenant` | فترة ذات معنى للعمل؛ لا يفترض الشهر دائمًا. |
| `refreshPolicy` | `string` | `"explicit-or-measured"` | `system/tenant` | لا تستخدم polling سريعًا بلا حاجة أو قياس. |
| `showLastUpdated` | `boolean` | `true` | `system` | وقت مصدر البيانات أو الحساب لا وقت رسم المكوّن فقط. |
| `allowWidgetReorder` | `boolean` | `true` | `tenant/user` | تفضيل عرض لا يغير تعريف المؤشر. |
| `missingValueDisplay` | `string` | `"unavailable"` | `system` | غير متاح أو غير معرف لا صفر افتراضي. |
| `comparisonMode` | `string` | `"explicit-period"` | `system/tenant` | تسمية الفترة المرجعية ونوع المقارنة. |
| `drillDown` | `boolean` | `true` | `system/tenant` | يعمل فقط عند إمكانية شرح النطاق وإعادة التفويض. |
| `dataTableAlternative` | `boolean` | `true` | `system` | بديل نصي أو جدولي قابل للوصول للرسوم. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-020-R01"></a>
### VCGF-UI-COMP-020-R01 - تعريف المؤشر

لكل KPI معرف ومالك ووحدة ومعادلة وبسط ومقام إن وجد ومصدر ونطاق زمني وتواتر تحديث. لا يُعاد تعريف المؤشر نفسه في كل شاشة أو حسب مكتبة الرسم.

<a id="VCGF-UI-COMP-020-R02"></a>
### VCGF-UI-COMP-020-R02 - سياق الزمن

اعرض الفترة والمنطقة الزمنية والفلاتر ووقت آخر تحديث، وميّز وقت الحساب من وقت الأحداث. لا تقارن شهرًا كاملًا بجزء من شهر دون وصف الاختلاف.

<a id="VCGF-UI-COMP-020-R03"></a>
### VCGF-UI-COMP-020-R03 - صفر ومفقود

فرق بين صفر فعلي ومصدر غير متاح وقيمة غير معرفة مثل قسمة على صفر. لا يعالج خطأ الجلب بإعادة استخدام صفر أو قيمة قديمة بلا وسم.

<a id="VCGF-UI-COMP-020-R04"></a>
### VCGF-UI-COMP-020-R04 - رسم مناسب

اختر الرسم بحسب المقارنة أو الزمن أو التركيب، مع وحدات ومحاور ونطاقات واضحة. لا تستخدم ثلاثة أبعاد أو قص محاور يضلل المقارنة، ولا تضع مقاييس مختلفة على محور واحد بلا بيان.

<a id="VCGF-UI-COMP-020-R05"></a>
### VCGF-UI-COMP-020-R05 - تفصيل قابل للتتبع

النقر على المؤشر يفتح سجلاته أو منهجيته بنطاق متسق وصلاحيات فعلية. عند اختلاف الحبيبية أو التجميع اشرح سبب عدم مساواة عدد الصفوف للرقم المعروض.

<a id="VCGF-UI-COMP-020-R06"></a>
### VCGF-UI-COMP-020-R06 - تفويض التجميع

المؤشرات والعدادات تخضع للتفويض مثل السجلات، وقد تحتاج سياسة تجميع تمنع كشف مجموعات صغيرة حساسة. لا ترسل dataset واسعًا ثم تصفّيه في المتصفح.

<a id="VCGF-UI-COMP-020-R07"></a>
### VCGF-UI-COMP-020-R07 - تحديث ومتانة

حافظ على آخر بيانات ناجحة مع وسمها stale عند فشل التحديث إن سمحت المهمة، ولا تطمس خطأ حرج بقيم قديمة. حدّث المؤشرات المتقارنة على snapshot متسق عندما تتطلب الدقة ذلك.

<a id="VCGF-UI-COMP-020-R08"></a>
### VCGF-UI-COMP-020-R08 - تخصيص منضبط

ترتيب وإخفاء الويدجت تفضيل مستخدم، أما تعريف المؤشر وأذوناته فلا يتغيران معه. ادعم إعادة الضبط واحفظ التفضيل بإصدار مخطط دون تضمين dataset في التخزين المحلي.

<a id="VCGF-UI-COMP-020-R09"></a>
### VCGF-UI-COMP-020-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-020-R10"></a>
### VCGF-UI-COMP-020-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-020-R11"></a>
### VCGF-UI-COMP-020-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-020-R12"></a>
### VCGF-UI-COMP-020-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `metricDefinition`, `dataset`, `period`, `filters`, `freshness`, `accessScope`, `displayPreferences`

**الأحداث المفاهيمية:** `periodChanged`, `drillDownRequested`, `refreshRequested`, `layoutChanged`

**مصدر السلطة:** طبقة البيانات تملك تعريف المؤشر وحسابه وتفويضه؛ مكتبة الرسم تعرض فقط.

```text
loading -> ready/empty/undefined -> refreshing -> fresh/stale/error
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-002](VCGF-UI-COMP-002-SmartDataGrid.md) - [VCGF-UI-COMP-004](VCGF-UI-COMP-004-AdvancedFilterBuilder.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md) - [VCGF-UI-COMP-017](VCGF-UI-COMP-017-SmartNumericInput.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- احسب المؤشرات في طبقة موثوقة مع تعريف grain وdeduplication وحالة السجلات الداخلة في الحساب.
- استخدم decimals ووحدات صحيحة للمال، ولا تجعل تقريب العرض يغير الحساب أو الفرز.
- لا تطلب ملايين النقاط للعرض؛ استخدم تجميعًا أو تقليلًا موثقًا مع الحفاظ على دلالة القمم والفجوات.
- analytics المستخدمة لتحسين الاستخدام لا تجمع قيم اللوحة الحساسة افتراضيًا.
- مقاييس الأداء والأخطاء لها ميزانية مستقلة؛ حمل مكتبات الرسم الثقيلة عند الحاجة فقط.

## 6. الوصولية والعربية والتجاوب

- توفير ملخص نصي أو جدول وتسمية ووحدة لكل رسم، وليس صورة أو canvas بلا بديل.
- لا تعتمد على اللون وحده للفرق؛ استخدم أساليب خط أو تسميات أو أنماط يمكن تمييزها.
- tooltips قابلة للوصول بالتركيز أو يوجد بديل واضح؛ لا تشترط hover أو السحب لفهم القيمة.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- فترة لا توجد بها بيانات تختلف عن فشل جميع مصادر الفترة.
- تغير تعريف KPI يستدعي إصدارًا وملاحظة على المقارنة التاريخية لا إعادة تسمية الرسم فقط.
- دمج مناطق زمنية مختلفة لا ينقل معاملات بين أيام التقارير دون سياسة معلنة.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |
|---|---|---|
| [Apache ECharts](https://echarts.apache.org/en/index.html) | رسم مرئيات متنوعة عند الحاجة إلى مرونة وتحكم. | لا يحسب حقيقة KPI ولا يمنح الوصولية كاملة دون بديل نصي؛ اختبر canvas أو SVG بحسب الحجم. |
| [Recharts](https://recharts.github.io/) | خيار رسوم مناسب لمشروعات React. | تحقق من إصدار المشروع ودلالات الرسوم والبديل النصي؛ لا تجمع مكتبات رسم متعددة بلا مبرر. |
| [Chart.js](https://www.chartjs.org/docs/latest/) | بديل رسوم JavaScript يدمج مع إطار الواجهة المناسب. | حدد wrapper إن احتاجه المشروع واختبر الأداء والبديل المتاح للبيانات. |

[سياسة اختيار المكتبات](../governance/PACKAGE-SELECTION.md) - [سجل المصادر والباكيجز](../references/SOURCES.md)

## 9. الوصايا الذهبية

- **المؤشر الصحيح أهم من الرسم المبهر.**
- **غير متاح ليست صفرًا.**
- **يجب أن يستطيع المستخدم فهم التعريف والنطاق والوقت خلف كل رقم.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

**Then - النتيجة المطلوبة:** يرفض تجاوز القيد ولا تنتقل بيانات أو إعدادات خاصة بالمنشأة أ إلى ب؛ تبقى الإعدادات العامة المسموحة فقط.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-020 / SmartDashboardWidgets - لوحات المعلومات والمؤشرات والرسوم.
عرض مؤشرات قابلة للتفسير والتتبع إلى بياناتها، لا أرقام جذابة بلا تعريف أو سياق، مع مراعاة حداثة المعلومات ونطاق الصلاحيات والاختلاف بين الصفر وعدم توفر البيانات.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: المؤشر الصحيح أهم من الرسم المبهر. غير متاح ليست صفرًا. يجب أن يستطيع المستخدم فهم التعريف والنطاق والوقت خلف كل رقم.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: أنشئ لوحة بعدد ونسبة ومبلغ مع مقارنة زمنية وتفصيل سجلات، ثم اختبر المقام الصفري والمصدر المتعطل واختلاف الصلاحية وفترة ناقصة وحداثة البيانات.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
