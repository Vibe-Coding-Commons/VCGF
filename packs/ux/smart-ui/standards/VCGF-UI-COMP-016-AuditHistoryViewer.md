# VCGF-UI-COMP-016 - سجل العمليات ومقارنة الإصدارات

**AuditHistoryViewer**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

عرض دليل مفهوم على من غيّر ماذا ومتى وبأي نتيجة، دون الخلط بين شاشة تاريخ جميلة وبين سجل يمكن الاعتماد عليه أو ادعاء عدم قابلية التلاعب بلا آلية إثبات.

**متى ينطبق:** ينطبق على السجلات المهمة والتغييرات الإدارية والاعتمادات والوثائق والإعدادات، مع درجة تفصيل تتناسب مع المخاطر ومتطلبات الاحتفاظ المعتمدة.

**متى لا ينطبق:** ليس سجل console أو analytics، ولا يخزن كلمات مرور أو رموز تحقق، ولا يتيح استعادة نسخة قديمة بمجرد عرض الفرق دون خدمة تفويض وتنفيذ.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `defaultOrder` | `string` | `"newest-first"` | `tenant/user` | الترتيب حسب وقت حدث موثوق مع كاسر تعادل ثابت. |
| `pageSize` | `integer` | `25` | `tenant/user` | ضمن حد الخدمة؛ ترقيم أو cursor حسب الحجم. |
| `showFieldDiff` | `boolean` | `true` | `system/tenant` | فقط الحقول والنسخ المصرح بها. |
| `maskSensitiveFields` | `boolean` | `true` | `system` | التنقية قبل التخزين أو الإرجاع وفق التصنيف لا في CSS. |
| `retentionPolicy` | `string` | `"explicit-required"` | `system/tenant` | لا تفترض مدة موحدة؛ يراعي الحجز القانوني وسياسة المنشأة. |
| `exportAudit` | `boolean` | `false` | `system/tenant` | صلاحية مستقلة وتسجيل تنزيل عند الحاجة. |
| `displayTimeZone` | `string` | `"tenant"` | `system/user` | العرض فقط؛ اللحظة الأصلية لا تتغير. |
| `integrityLabel` | `string` | `"evidence-based"` | `system` | لا يظهر وصف immutable أو tamper-evident بلا دليل بنية وفحص. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-016-R01"></a>
### VCGF-UI-COMP-016-R01 - حدث موثوق

أنشئ الأحداث في الخادم مع actorId وsubjectRef وaction وtimestamp وoutcome وcorrelationId وversion عند الحاجة. لا تعتمد وقت جهاز العميل أو اسمًا حرًا يرسله المستخدم لإثبات الفاعل.

<a id="VCGF-UI-COMP-016-R02"></a>
### VCGF-UI-COMP-016-R02 - النتيجة لا المحاولة فقط

ميز requested وdenied وcompleted وfailed عند الحاجة، واربطها دون الإيحاء بأن مجرد محاولة الحفظ تعني تغير البيانات. سجل فشل الأثر وتفاصيله الآمنة.

<a id="VCGF-UI-COMP-016-R03"></a>
### VCGF-UI-COMP-016-R03 - مقارنة مفهومة

قارن قيمًا مطبّعة بحسب نوعها ومعرفها، لا نصوص عرض مترجمة فقط. بين إضافة وحذف وتغيير قيمة، وميّز تغير ترتيب مصفوفة من تعديل محتواها بحسب معنى المجال.

<a id="VCGF-UI-COMP-016-R04"></a>
### VCGF-UI-COMP-016-R04 - حماية القيم

لا تحفظ الأسرار أصلًا، ولا ترسل قيم الحقول المحجوبة ثم تخفيها في الواجهة. أظهر سبب الحجب بشكل آمن عند الحاجة، وراع أثر كشف القيمة القديمة بعد سحب صلاحية حالية.

<a id="VCGF-UI-COMP-016-R05"></a>
### VCGF-UI-COMP-016-R05 - ترتيب وسياق

استخدم حدثًا له معرف ثابت وترتيب موثق ووقت أصلي، مع تمثيل محلي مركزي. عند وجود أنظمة موزعة وفر معاني event time وrecorded time إن اختلفا ولا تدع ترتيبًا قطعيًا غير مثبت.

<a id="VCGF-UI-COMP-016-R06"></a>
### VCGF-UI-COMP-016-R06 - نزاهة قابلة للإثبات

وضح مستوى حماية السجل القائم فعلًا: أذونات كتابة مقيدة أو تخزين append-only أو سلسلة بصمات أو حماية مستقلة. لا تستخدم وصف غير قابل للتغيير مطلقًا لمجرد عدم وجود زر تعديل.

<a id="VCGF-UI-COMP-016-R07"></a>
### VCGF-UI-COMP-016-R07 - استرجاع ليس عرضًا

استعادة إصدار تُعامل كأمر جديد يمر بالصلاحيات والتزامن والتحقق ويسجل أثرًا جديدًا، ولا يحذف تاريخ التغيير أو يرجع قاعدة البيانات مباشرة من مخرجات diff غير موثوقة.

<a id="VCGF-UI-COMP-016-R08"></a>
### VCGF-UI-COMP-016-R08 - تصدير واحتفاظ

التصدير يخضع لنفس حجب الحقول ونطاق الوصول، ويثبت وقت استخراج ونطاقًا معلومًا. الحذف الدوري أو الأرشفة يتبع سياسة احتفاظ مع مراجعة الحجز القانوني ولا ينفذ من تفضيل مستخدم.

<a id="VCGF-UI-COMP-016-R09"></a>
### VCGF-UI-COMP-016-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-016-R10"></a>
### VCGF-UI-COMP-016-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-016-R11"></a>
### VCGF-UI-COMP-016-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-016-R12"></a>
### VCGF-UI-COMP-016-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `subjectRef`, `eventQuery`, `events`, `versionPair`, `fieldVisibility`, `integrityEvidence`

**الأحداث المفاهيمية:** `queryChanged`, `eventExpanded`, `compareRequested`, `exportRequested`, `restoreRequested`

**مصدر السلطة:** خدمة التدقيق مصدر الحدث وحمايته؛ العارض والمقارن يفسران بيانات مفوضة ولا يعيدان كتابة التاريخ.

```text
loading -> timeline-ready -> comparing -> diff-ready/error; restore is a separate command
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-002](VCGF-UI-COMP-002-SmartDataGrid.md) - [VCGF-UI-COMP-004](VCGF-UI-COMP-004-AdvancedFilterBuilder.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

**معايير خارجية قد تلزم:** `calendar`

[عقد ربط التقويم والاختيار القابل للبحث](../governance/EXTERNAL-STANDARDS-BINDINGS.md). النسختان موثقتان داخل هذه الحزمة وبصماتهما مثبتة، لكن اعتماد المسارات داخل مستودع VCGF أو مشروع بعينه يظل جزءًا من عملية الدمج الخاصة بذلك المستودع.

## 5. النقاط الهندسية وحدود المسؤولية

- سجل البيانات اللازمة فقط مع حماية من حقن أسطر أو HTML في أسماء الفاعلين والأسباب.
- افصل eventId عن subjectId وعن correlationId، ووثق مصدر actor عند انتحال مسموح أو تنفيذ خدمة.
- تجزئة الأحداث والتوقيع أو WORM اختيارات بنيوية تحتاج إدارة مفاتيح واحتفاظ ومراقبة؛ لا تمنحها مكتبة المقارنة.
- يجب أن تلتزم خدمة البحث في السجل بنفس التفويض بما في ذلك العدادات والمقتطفات.
- لا تخزن diff وحده إن كان الاسترجاع الموثوق يحتاج snapshots أو أحداثًا كاملة؛ اختر نموذجًا قابلًا لإعادة البناء واختبره.

## 6. الوصولية والعربية والتجاوب

- المقارنة تعرض labels قبل وبعد وإضافة وحذف بالنص لا الأحمر والأخضر وحدهما.
- قارئ الشاشة يستطيع قراءة الحدث بصياغة مستقلة عن شكل timeline.
- التواريخ والأرقام المختلطة الاتجاه معزولة وتستخدم معيار العرض المركزي دون تغيير وقت المصدر.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- حذف حساب الفاعل لا يمحو أثره؛ يعرض مرجعًا تاريخيًا محدودًا وفق السياسة.
- فرق كبير جدًا يقدم ملخصًا وتقسيمًا بدل تجميد المتصفح أو إرسال بيانات غير ضرورية.
- تغير ترجمة حالة لا يسجل كتغيير أعمال إذا بقي معرف الحالة نفسه.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

| المكتبة أو المنتج | الدور المقترح | الحدود والتنبيهات |

## 9. الوصايا الذهبية

- **سجل التدقيق يصف الحقيقة ولا يصنعها من حركة الواجهة.**
- **لا تحوّل السجل إلى مستودع أسرار.**
- **شارة النزاهة تحتاج دليلًا تقنيًا لا عبارة تسويقية.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-016 / AuditHistoryViewer - سجل العمليات ومقارنة الإصدارات.
عرض دليل مفهوم على من غيّر ماذا ومتى وبأي نتيجة، دون الخلط بين شاشة تاريخ جميلة وبين سجل يمكن الاعتماد عليه أو ادعاء عدم قابلية التلاعب بلا آلية إثبات.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: سجل التدقيق يصف الحقيقة ولا يصنعها من حركة الواجهة. لا تحوّل السجل إلى مستودع أسرار. شارة النزاهة تحتاج دليلًا تقنيًا لا عبارة تسويقية.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اعرض تغييرات متعددة مع حدث مرفوض وحقل محجوب واستعادة نسخة، ثم اختبر ترتيب الوقت نفسه وحماية التصدير وادعاء النزاهة مقابل الدليل الفعلي.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
