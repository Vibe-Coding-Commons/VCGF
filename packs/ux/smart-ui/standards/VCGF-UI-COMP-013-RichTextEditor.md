# VCGF-UI-COMP-013 - المحرر النصي الغني والمحتوى المنظم

**RichTextEditor**

وثيقة مقترحة موسعة للمراجعة والدمج، وليست شهادة امتثال أو تنفيذًا برمجيًا. الإصدار 0.1.0 للحزمة مستقل عن الإصدار المستهدف 1.3.0 لإطار VCGF. أولوية P0/P1/P2 تحدد ترتيب التوثيق والتبني وليست أمرًا بإنشاء المكوّن في كل مشروع.

> الصور السابقة مرجع مباشر للتقويم المزدوج والقائمة القابلة للبحث فقط. أما سلوك هذا المكوّن فهو مواصفة مقترحة مستنبطة من المهام، ولا يُدّعى أنه مطابق لصورة لم تُقدّم. عند وجود تصميم فعلي للمشروع يُراجع معه دون إسقاط متطلبات الأمان والوصولية.

## 1. الهدف ونطاق التطبيق

تحرير محتوى غني يحتاج بنية وتنسيقًا دون تحويل الحقل إلى مدخل HTML غير موثوق أو ربط محتوى المؤسسة نهائيًا بمحرك تحرير واحد.

**متى ينطبق:** ينطبق على المراسلات والملاحظات الطويلة والقوالب والمحتوى الذي يحتاج عناوين أو جداول أو روابط. يختار مجموعة أدوات صغيرة تناسب نوع المستند.

**متى لا ينطبق:** لا يستخدم بدل input قصير أو textarea كافية، ولا يعد محررًا مكتبيًا كاملًا أو نظام تعاون وتوقيع وتتبع تغييرات بمجرد تثبيت حزمة تحرير.

## 2. الإعدادات المركزية المقترحة

القيم التالية نقطة بداية مقترحة، وليست تهيئة إنتاج جاهزة. تحدد جهة المشروع الحدود التشغيلية قبل التفعيل. كلمة system تعني سياسة مركزية، وtenant نطاق المنشأة، وuser تفضيلًا مسموحًا؛ لا يجيز ترتيب الأولوية إضعاف الأمان أو تجاوز حدود البيانات.

| الإعداد | النوع | القيمة المقترحة | نطاق الإدارة | القيود والمعنى |
|---|---|---|---|---|
| `toolbarPreset` | `string` | `"basic"` | `system/tenant` | مجموعات قدرات معتمدة حسب نوع المحتوى. |
| `contentFormat` | `string` | `"schema-json"` | `system` | اختيار JSON أو HTML موثق مع schemaVersion وخطة نقل. |
| `allowedNodes` | `array` | `["paragraph", "heading", "list", "link"]` | `system/tenant` | قائمة سماح؛ التوسع يتطلب مراجعة المعقم والعارض. |
| `pastePolicy` | `string` | `"sanitize-preserve-allowed"` | `system` | ينقح التنسيق والروابط ولا يثق في محتوى Word أو الويب. |
| `imagePolicy` | `string` | `"managed-attachments-only"` | `system` | لا يسمح بروابط تتبع خارجية أو data URLs بلا حدود وسياسة. |
| `maxContentBytes` | `integer` | `200000` | `system/tenant` | اقتراح يضبط حسب المجال ويُطبق على الخادم. |
| `collaboration` | `boolean` | `false` | `system/tenant` | لا يفعل دون خدمة تزامن وتعارض وتفويض معتمدة. |
| `autosave` | `boolean` | `false` | `system/tenant` | يرتبط بعقد المسودات ولا يساوي اعتماد المستند. |

[حوكمة الإعدادات المركزية](../governance/CENTRAL-SETTINGS.md) - [مثال الإعدادات الخامل](../config/central-settings.example.json)

## 3. المتطلبات الوظيفية والتفاعلية الملزمة عند التطبيق

<a id="VCGF-UI-COMP-013-R01"></a>
### VCGF-UI-COMP-013-R01 - قدرات بحسب المهمة

وفر شريط أدوات منظمًا للخصائص المسموحة فقط، ولا تعرض زر جدول أو صورة أو تعليق إن لم تدعمه دورة الحفظ والعرض والتصدير. حدد الفرق بين تحرير قالب وتحرير نسخة صادرة.

<a id="VCGF-UI-COMP-013-R02"></a>
### VCGF-UI-COMP-013-R02 - نموذج محتوى ذي إصدار

احفظ بنية مع schemaVersion وأسماء عقد معروفة، وافصلها عن HTML المشتق. إذا كان HTML هو المصدر فلتكن له قائمة سماح واضحة ومسار ترحيل، ولا تحفظ كل الصيغ كمصادر مستقلة متعارضة.

<a id="VCGF-UI-COMP-013-R03"></a>
### VCGF-UI-COMP-013-R03 - تنقية في طبقة موثوقة

طبّق تنقية محتوى غير موثوق في الخادم وفي مسارات العرض المناسبة، مع تقييد البروتوكولات والسمات والوسوم. لا تكتفِ بتنقية على المتصفح أو regex لإزالة script.

<a id="VCGF-UI-COMP-013-R04"></a>
### VCGF-UI-COMP-013-R04 - لصق عربي من مصادر مختلفة

حافظ على النص واتجاه الفقرات والخصائص المسموحة عند اللصق، مع خيار لصق كنص. لا تحوّل كل محاذاة عربية إلى CSS مطلق ينهار عند تغير الاتجاه.

<a id="VCGF-UI-COMP-013-R05"></a>
### VCGF-UI-COMP-013-R05 - روابط ومرفقات مدارة

الصور والمرفقات ترتبط بمعرفات وخدمة وصول وتخضع للفحص. لا تقبل عنوان صورة خارجيًا يسرب عنوان IP أو يحمّل موردًا غير معتمد، ولا يُدرج base64 ضخم داخل كل حفظ.

<a id="VCGF-UI-COMP-013-R06"></a>
### VCGF-UI-COMP-013-R06 - تراجع وحفظ واعتماد

التراجع وإعادة التنفيذ محليان لتحرير المحتوى، أما حفظ نسخة أو اعتمادها فعمليات مستقلة. أظهر حالة الحفظ ولا تسمح بتحرير نسخة نهائية مقفلة دون إنشاء إصدار معتمد جديد.

<a id="VCGF-UI-COMP-013-R07"></a>
### VCGF-UI-COMP-013-R07 - تعارض وتعاون

في التحرير الفردي استخدم revision لاكتشاف تضارب النسخ. التعاون الفوري يحتاج محرك تزامن وحضور وتفويض لكل مستند ومعالجة انقطاع، وليس تشغيل خيار واجهة فقط.

<a id="VCGF-UI-COMP-013-R08"></a>
### VCGF-UI-COMP-013-R08 - اتساق العرض والتصدير

استخدم renderer يلتزم بمخطط المحتوى والسياسة نفسها في التفاصيل والبريد والطباعة والتصدير. لا تقبل معاينة تختلف دلاليًا عن النسخة المحفوظة أو تفقد جداول مهمة دون تحذير.

<a id="VCGF-UI-COMP-013-R09"></a>
### VCGF-UI-COMP-013-R09 - حوكمة الإعدادات والعزل

اقرأ الإعدادات الفعالة من خدمة مركزية ذات مخطط إصدار؛ ادمج التفضيلات المسموحة فقط ولا تسمح لقيمة من المتصفح بتجاوز سياسة الأمان. احصر التخزين المؤقت وتفضيلات المستخدم في نطاق المشروع والمنشأة والحساب، وأعد تقييمها عند تبديل السياق.

<a id="VCGF-UI-COMP-013-R10"></a>
### VCGF-UI-COMP-013-R10 - إمكانية الوصول والتركيز

اختر نمط HTML وARIA الموافق للتفاعل الحقيقي، واجعل الاسم والحالة والأخطاء مقروءة بلوحة المفاتيح وقارئ الشاشة. لا يكفي فحص آلي؛ اختبر ترتيب التركيز واستعادته والعمليات الأساسية يدويًا واحفظ الدليل.

<a id="VCGF-UI-COMP-013-R11"></a>
### VCGF-UI-COMP-013-R11 - التعريب والاستجابة دون فقد المعنى

اختبر العربية والإنجليزية واللغات المعلنة للمشروع مع RTL/LTR ونصوص مختلطة وطويلة. استخدم الخصائص المنطقية واتجاهًا بنيويًا مناسبًا. صمم الجوال والشاشات العريضة بحسب المهمة ولا تخف معلومة أو إجراءً ضروريًا لمجرد ضيق العرض.

<a id="VCGF-UI-COMP-013-R12"></a>
### VCGF-UI-COMP-013-R12 - التعافي والأداء بأدلة

عرّف ميزانية أداء خاصة بالمهمة واختبر حجم بيانات ممثلًا للإنتاج. ميّز التحميل والفشل والفراغ والبيانات القديمة؛ لا تحول غياب النتيجة إلى نجاح أو صفر. لا تقبل استجابة قديمة لتغيير حالة أحدث، ووفّر تعافيًا يحافظ على البيانات متى كان ذلك آمنًا.

## 4. العقد الوظيفي والمكوّنات المتعاونة

**مدخلات العقد المفاهيمي:** `document`, `schemaVersion`, `toolbarPolicy`, `editCapabilities`, `revision`, `attachmentAdapter`

**الأحداث المفاهيمية:** `contentChanged`, `validationFailed`, `saveRequested`, `attachmentInserted`, `conflictDetected`

**مصدر السلطة:** خدمة المحتوى تملك الإصدار والتعقيم والصلاحية؛ المحرر يدير تجربة التحرير.

```text
loading -> clean -> dirty -> saving -> saved/conflict/error; locked is read-only
```

هذا عقد تصميمي وليس توقيع API جاهزًا لمكتبة محددة. حدد أنواع الحقول والأحداث وأسباب الخطأ في Adapter المشروع، وافصل قيمة الأعمال عن النص المعروض وعن حالة التركيز والفتح. لا تخترع خدمات خلفية قائمة أو endpoints غير موثقة.

**علاقات تكامل تراجع حسب السيناريو:** [VCGF-UI-COMP-001](VCGF-UI-COMP-001-DesignSystemPrimitives.md) - [VCGF-UI-COMP-003](VCGF-UI-COMP-003-SmartFormFields.md) - [VCGF-UI-COMP-005](VCGF-UI-COMP-005-SmartFileUploader.md) - [VCGF-UI-COMP-008](VCGF-UI-COMP-008-UnifiedFeedbackSystem.md) - [VCGF-UI-COMP-012](VCGF-UI-COMP-012-PermissionAwareActions.md)

الروابط لا تفرض بناء جميع المكوّنات المشار إليها. قيّم الحاجة وأعد استخدام الموجود؛ حل التعارضات بالسياق وقواعد المجال قبل التثبيت.

## 5. النقاط الهندسية وحدود المسؤولية

- لا تمنح JSON المخطط ثقة مطلقة؛ بيانات العقد والروابط والسمات كلها مدخلات تحتاج تحققًا.
- ثبّت إصدارات extensions وتوافقها؛ إدخال امتداد جديد يوسع مساحة الهجوم ومخطط المحتوى.
- قيد الصور والجداول والتعشيق والحجم الكلي لمنع تجميد الرندر والتصدير.
- خزّن مشتقات البحث أو HTML مع ارتباط واضح بإصدار المصدر والمعقم ولا تعتبرها أصلًا ثانيًا.
- لا تُسجل محتوى الرسائل في analytics أو تقارير الأخطاء؛ استخدم مقاييس حجم وحالة غير حساسة.

## 6. الوصولية والعربية والتجاوب

- شريط الأدوات قابل للوحة المفاتيح وله تسميات وحالات pressed معروفة؛ لا يحتجز المستخدم داخل منطقة التحرير.
- دعم اتجاه كل فقرة وIME والنسخ واللصق والتكبير دون فقد المؤشر أو التحديد.
- العناوين بنيوية لا مجرد تكبير خط، والنص البديل للصور يُطلب عندما يلزم المحتوى.

[السياسة المشتركة للوصولية وRTL/LTR](../governance/ACCESSIBILITY-RTL.md)

## 7. حالات حدية ومخاطر خاصة

- تعطل رفع صورة لا يجعل المستند يبدو محفوظًا كاملًا بينما مرجع الصورة مؤقت وغير صالح.
- إلغاء extension أثناء ترقية يستلزم ترحيلًا أو عارضًا آمنًا للعقد القديمة لا حذفها الصامت.
- روابط خارجية جديدة تفتح وفق سياسة آمنة وتحافظ على معرفة المستخدم بالانتقال خارج النظام.

## 8. الباكيجز المرشحة وحدودها

هذه بدائل مرشحة، وليست تبعيات مطلوب تثبيتها كلها. افحص الموجود وراجع الترخيص والنسخة والأداء والتعريب قبل الاختيار. بعض الأسماء نظام مكوّنات أو خدمة إطار عمل وليست حزمة npm واحدة.

## 9. الوصايا الذهبية

- **التنسيق لا يبرر إدخال محتوى غير موثوق إلى أصل التطبيق.**
- **لا تربط تاريخ مستندات المؤسسة بعقد داخلية غير قابلة للترحيل.**
- **الحفظ والتعاون والاعتماد قدرات مستقلة لا ادعاءات لشريط أدوات.**

## 10. معايير القبول والاختبارات

أنشئ سجل قرار انطباق ثم سجل قرار مكتبة، واربط كل متطلب باختباره ومعرف الإصدار أو الالتزام المستهدف. المرجع الحالي لا يحتوي على تطبيق للمكوّن؛ جميع اختبارات التطبيق الواردة أدناه حالتها not_run إلى حين تنفيذها في المشروع.

## 11. البرومبت الإضافي الجاهز للتنفيذ

يُنسخ البرومبت التالي مع هذا الملف والسياسات المشتركة المطلوبة. لا تستبدل النصوص المشار إليها بملخص حذف منه شرط أمني أو اختبار حدّي.

```text
اعتمد المعيار VCGF-UI-COMP-013 / RichTextEditor - المحرر النصي الغني والمحتوى المنظم.
تحرير محتوى غني يحتاج بنية وتنسيقًا دون تحويل الحقل إلى مدخل HTML غير موثوق أو ربط محتوى المؤسسة نهائيًا بمحرك تحرير واحد.
تعامل مع هذه الوثيقة باعتبارها عقدًا سلوكيًا مشروطًا بانطباق السيناريو، لا طلبًا لتثبيت جميع المكتبات. افحص الشاشات والتبعيات والخادم الحالي أولًا، ثم أعد استخدام ما يحقق المتطلبات ولا تستبدل نظام التصميم أو قواعد الأعمال دون مبرر موثق.

طبّق الإعدادات الثمانية المذكورة في هذه الوثيقة عبر خدمة الإعدادات المركزية، مع تعريف النوع والقيمة الافتراضية وحدود التعديل، وتقديم معاينة وحفظ آمن عند وجود شاشة إدارة. القيم المقترحة ليست سياسة إنتاج نهائية قبل اعتماد مالك المشروع.

نفّذ المتطلبات R01–R12 والحالات التفاعلية والعقد الوظيفي كما هو موضح، مع دعم سيناريوهات التحميل والخطأ والتعافي والبيانات الفارغة. لا تعتبر تطابق الألوان دليلًا على صحة التفاعل، ولا تستحدث endpoints أو بيانات حقيقية غير موجودة.

احتفظ بقواعد التفويض والتحقق والتزامن والحفظ في الطبقة الموثوقة. افصل منطق الأعمال عن المكتبة المرئية، ووثق النسخ والتراخيص والقيود ومبرر اختيار المكتبة في ADR. لا تثبت البدائل الثلاثة معًا، ولا تدّع أن المكتبة تحقق جميع المتطلبات تلقائيًا.

التزم بالوصايا الذهبية التالية: التنسيق لا يبرر إدخال محتوى غير موثوق إلى أصل التطبيق. لا تربط تاريخ مستندات المؤسسة بعقد داخلية غير قابلة للترحيل. الحفظ والتعاون والاعتماد قدرات مستقلة لا ادعاءات لشريط أدوات.

استخدم سيناريو التحقق التالي ضمن أدلة التسليم: اختبر لصق محتوى عربي غني وروابط غير آمنة وصورة لم ينته فحصها، ثم تعارض حفظ وترقية مخطط ومعاينة نسخة مقفلة دون تعديل الأصل.

سلّم التطبيق المناسب للتقنية الحالية، ووثيقة ربط المتطلبات بالتنفيذ، واختبارات AC01–AC12، ونتائج فحص لوحة المفاتيح وRTL/LTR والأجهزة، وسجل القيود. ضع not_run لأي اختبار لم تنفذه ولا تنسب امتثالًا أو تحسن أداء بلا دليل. اختبر الترحيل في مسار محدود مع خطة تراجع قبل تعميم المكوّن.
```

## 12. دليل التسليم والدمج والترحيل

- قرار الانطباق: required أو recommended أو optional أو not_applicable أو unknown؛ يرفق السبب والدليل والمالك.
- عقد الإعدادات: مخطط الإصدار، الإعدادات الفعالة، حدود تعديل المستخدم، وترحيل التفضيلات القديمة.
- أدلة التنفيذ: المسارات الفعلية وأوامر التشغيل والمكتبات المثبتة دون أسرار أو بيانات مستخدمين حقيقية.
- أدلة الاختبار: البيانات المصطنعة، خطوات إعادة الإنتاج، النتائج، البيئة، التاريخ، والمراجع المرتبطة بالمتطلبات.
- الترحيل: احتفظ بالواجهات القائمة والبيانات، واستخدم تفعيلًا محدودًا ثم اختبار انحدار وخطة رجوع.
- الاستثناءات: موافقة مالك مختص، نطاق ضيق، تعويض للمخاطرة، تاريخ انتهاء، وعدم وصف الاستثناء كامتثال كامل.
