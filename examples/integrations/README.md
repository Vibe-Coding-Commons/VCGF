# Executable reference integrations — acceptance pending

The frozen scope is docs/project-history/v1.1.0/reference-stack.json. Install requirements-dev.txt and examples/integrations/requirements.txt in a dedicated Python 3.12 environment. Run `python -B tests/scenarios/test_integrations.py` from the project root. It creates only temporary synthetic data, encryption keys and a localhost TLS mail sink. The suite needs permission to open a local TCP socket. It does not contact an external provider.

## Email

email/delivery.py exposes SMTPProvider for TLS STARTTLS/implicit and Microsoft365Provider for OAuth2 SASL XOAUTH2. Pass an explicit recipient allowlist, a verified CA configuration and a bounded timeout. Supply credentials/token from the host's secret store; never paste tokens into source, logs or CLI arguments. Microsoft365Provider forbids Basic Auth fallback. OAuth token acquisition, refresh, tenant consent and Exchange mailbox authorization belong to the trusted host; the Microsoft source registry entry documents them. Use a dedicated sandbox mailbox and record actual receipt, rejected recipients, expired tokens and provider failure behavior. SMTP acceptance is not inbox delivery proof.

email/queue.py provides an encrypted SQLite outbox. Only an explicit temporary SMTP DATA refusal is automatically eligible for bounded retry/backoff. Timeouts, crashes with inflight jobs and ambiguous results need reconciliation to avoid silently sending duplicates. Run one worker process at a time unless you add tested host-level leasing. Content remains encrypted; log only job/status/attempt metadata. From/Reply-To, English/Arabic connection-test templates and SMTP timeouts are implemented. SPF/DKIM/DMARC and real provider delivery remain deployment acceptance checks, not claims from local tests. Microsoft Graph remains a preferred integration not yet implemented in this checkpoint.

## Unified backup and restore

backup/unified.py is a real SQLite + private local attachment example. The example schema contains `attachments(storage_path, checksum)`; application paths use a tenant/workspace/date hierarchy. All application writers must acquire barrier(root). A writer outside that cooperative lock invalidates the consistency guarantee. During the barrier the reference takes a SQLite backup, verifies integrity and each attachment checksum, compresses a manifest with data, then encrypts with AES-256-GCM. Manage the random 32-byte key outside the archive in a secret store; the example does not implement a KMS.

Restore requires a new destination, checks authenticated encryption, archive paths and size limits, database integrity, attachment count and per-row hashes. The test alters source data after backup, restores into a separate destination and compares restored business data and attachment bytes. It also rejects missing attachments, checksum mismatch, tampering, a wrong key and existing destinations. This is evidence for SQLite/private local storage only. It is a Linux reference using fcntl; Windows and object-storage behavior are not claimed.

backup/sql_engines.py adds executable PostgreSQL 18 and MySQL 8.4 command adapters. They require explicit executable paths, local sandbox databases named `vcgf_sandbox_*`, private credential files and an explicitly empty restore target. No shell interpolation or credential arguments are used. MySQL consistency requires InnoDB and coordinated DDL/application writes. PostgreSQL dump consistency does not itself coordinate attachment writes. A trusted caller must hold an application barrier around both. These external-engine references have not run here: binaries/services are absent. They do not yet demonstrate a unified PostgreSQL/MySQL attachment restore, which remains an explicit acceptance gap.

backup/operations.py provides manual/daily/weekly/monthly/custom schedule expressions, retention candidates (no automatic deletion), a single-use identity-bound short-lived download ticket and a recovery gate. The host must enforce recent authentication, current authorization, secure transport, audit persistence and distributed ticket storage. No permanent public backup URL is created. Production migration/restore additionally needs fresh restore evidence, justified RPO/RTO or N/A and scoped human approval. No production operations are performed here.

The scheduler, retention executor, authenticated download endpoint and provider/cloud integrations must be wired and tested in their stated host environment. These components are reference code and explicitly incomplete product integrations, never evidence that every original pack requirement passed.
