# v1.4.0 Phase 2 — token efficiency and context optimisation design record

Date: 2026-10-25. Branch: `develop/v1.4.0`, continuing from the Phase 1 commits. Baseline for every comparison: the Phase 1 tree (commit `19ea918`), whose routes already carry the complete, profile-correct control set. Phase 2 reduces repetition and over-loading; it never changes which controls a route selects.

## Binding interpretation rules applied first

Before optimising, the Phase 1 acceptance tests were corrected to the rules recorded in `spec/acceptance/README.md`: numeric thresholds became documented, configurable `parameters` (source and rationale per value, referenced by the criterion), SHOULD-level recommendations are never tested as MUST, requirement sources follow the controls → contracts → reference specifications → guidance order, and every acceptance entry carries an execution state that is `not_executed` inside this repository. `tests/scenarios/test_applicability_triggers.py` checks the hand-assigned matrix triggers with positive, negative and missing-context cases (a missing or expired fact blocks the route; it never drops a control).

## 1. Control cards and common clauses

`scripts/generate-control-cards.py` derives `spec/control-cards/<id>.md` from the control Markdown: identity, Requirement, Implementation-Neutral Guidance and every control-specific section, with the 21 clause variants shared verbatim by five or more controls emitted once in `common-clauses.md` and cited by letter. Purpose, Risk Addressed, Rationale, References and Change History stay in the full text, which the card names. The cards are 37 percent of the control bytes; `lean` and `standard` routes load cards plus the common clauses, `deep` routes load the full controls (`context_detail` in the route result). The loader strips HTML comments (attribution headers) from served text while hashing the stored bytes, so attribution stays in the repository and costs no context. `--check` in the release gate keeps the cards current; the controls remain the only normative source.

## 2. Multi-intent routing, delta loading, cache invalidation

A task may list additional reviewed `intents`; the Router selects the union of their capabilities once and takes the highest risk, instead of re-sending the shared context per intent. A task may pass `loaded_context` (path and hash of what the caller already holds); the loader sends only the delta, reports `reused_tokens` and `reused_context`, and re-sends any item whose hash no longer matches (hash-based invalidation). The registry is cached per process while no canonical source file changes (stat signature), so a second route costs about 50 ms instead of a rebuild.

## 3. Token budget enforcement

`runtime/tokens.py` keeps three quantities apart: bytes (measured), estimated tokens (ASCII/4.0 + non-ASCII/1.6, the documented heuristic) and observed tokens (only when the operator sets `VCGF_TOKENIZER`, and then labelled as a reference tokenizer). The route and ui-select budgets are enforced on estimated tokens and report `cost_bytes` beside `cost_tokens`; blocking still never drops a control. The previous byte-for-token comparison over-counted by roughly four times against the declared `limit_tokens`; callers with byte-sized budgets will now see more routes fit, which is the declared contract, not a loosening of coverage.

## 4. Tool output and Smart UI

The CLI prints hash-pinned references (`path`, `sha256`, `bytes`, `tokens`) by default and the loaded text only with `--full`; `--quiet` still omits the context entirely. `ui-select` serves requirement cards of the Smart UI standards (scope, binding requirements, state and stage contracts, discovery signals, acceptance) for lean and standard routes and the full standards for deep routes, hash-pinned on the full file; bound external standards and governance documents are served whole. `vcgf.py acceptance all` summarises definitions per control with zero executed and zero verified.

## Preserved

Selected control sets per route are identical to Phase 1 (verified by the benchmark hash per scenario and by the unchanged profile, matrix and routing tests). All 84 v1.0 controls, frozen v1.0 schemas, licence and attribution unchanged; the frozen Smart UI package unchanged (cards are a load-time projection). Nothing pushed, tagged or published.
