# موافقة التنفيذ AP-20261003-P1

المرجع: رسالة المستخدم حمادة سامي بتاريخ 2026-10-03 الساعة 15:27:32 بتوقيت Asia/Riyadh. هذا سجل نقل للموافقة في المحادثة، وليس توقيعًا تشفيريًا أو إثبات هوية خارجيًا.

## النص المعتمد

نعم، أعتمد النطاق وخطة التغييرات والقرارات المقترحة في تقرير VCGF v1.1.0 أساسًا للتنفيذ المرحلي، مع التحديدات التالية التي تُعد جزءًا من موافقتي:

النطاق العام: أعتمد تنفيذ جوهر v1.1، بما يشمل B001–B022 واختباراته، والحزم والمواءمات المحددة في التقرير، مع الحفاظ على المشروع الحالي وControl IDs والترخيص وحقوق المؤسس والتوافق وفق الخطة. لا تعني هذه الموافقة السماح بتقليل النطاق أو تأجيل متطلبات إضافية دون قرار صريح.

تفسير البريد والنسخ الاحتياطي — D10: أعتمد تنفيذهما كحزم قدرات وتكاملات مرجعية قابلة للتشغيل والاختبار، تشمل المتطلبات والتبعيات والإعدادات وإرشادات الدمج والاختبارات وأدلة النتائج. لا أوافق على اختزالهما إلى ملفات توثيق أو عقود نظرية فقط. لا يشترط ضمن هذه الموافقة بناء محركات عامة شاملة لجميع المزودين والتقنيات داخل نواة VCGF. تأجيل هذه المحركات العامة لا يعني إسقاط القدرات والتكاملات المرجعية المطلوبة للإصدار.

قبل بدء مرحلة الحزم، ثبّت قائمة التنفيذ المرجعي: التقنيات، ومزودي البريد، ومحركات قواعد البيانات، وأنواع التخزين، والقدرات المشمولة، وبيئات الاختبار ومعايير القبول. حافظ على الحد الأدنى للبريد الوارد في المواصفة: Generic SMTP over TLS وMicrosoft 365 باستخدام OAuth 2.0، مع بقاء Microsoft Graph دعمًا مفضلًا عند ملاءمته.

لا تعتبر البريد مكتملًا باختبارات المحاكاة وحدها، ولا النسخ الاحتياطي مكتملًا بمجرد إنشاء نسخة؛ يلزم إثبات التكامل والاستعادة واتساق قاعدة البيانات والمرفقات وفق النطاق المعلن. تعذر الاختبار يُسجل عائقًا أو Unverified، وليس نجاحًا أو تأجيلًا معتمدًا تلقائيًا.

التأجيلات والمنصات: أعتمد F01–F08 بحدودها المذكورة، مع الحفاظ على الأجزاء المطلوبة الآن. وأعتمد F09 للمحركات العامة فقط وفق التفسير أعلاه. لا أعتمد تقليل المنصات الوارد كخيار في F10. أبقِ Discovery/Readiness المشار إليها في D17 وF11 وحدة مستقلة مخططة داخل VCGF، تحتاج نطاقًا واعتمادًا منفصلين، دون اعتبارها ملغاة أو منفذة ضمن هذا الإصدار.

أهداف التعافي والأدلة: أعتمد D12 لتوثيق أهداف التعافي أو سبب عدم الانطباق للمشاريع الإنتاجية ذات البيانات الدائمة، دون فرض قيم افتراضية غير مبررة أو تغيير صامت لمعاني الضوابط وProfiles الحالية. نجاح مدققات v1.0 لا يُحسب نجاحًا لـv1.1، ونجاح مثال مرجعي لا يثبت تشغيل جميع المشاريع أو المنصات. اربط كل نتيجة بنطاقها وبيئتها وإصدارها ودليلها.

الإذن بالتنفيذ الآن: ثبّت هذه الموافقة في سجل القرارات، وحدّث حالة النطاق وفقها، ثم ابدأ المرحلة الأولى فقط: العقود والتوافق. لا تعِد فتح التحليل العام أو السؤال عن قرارات حُسمت هنا، إلا إذا ظهر تعارض جديد مؤثر. بعد المرحلة الأولى، قدّم الملفات المعدلة ونتائج الاختبارات وأدلة التوافق والعوائق المتبقية وتوصيتك بالانتقال، ثم انتظر موافقتي على المرحلة التالية.

لا تشمل هذه الموافقة النشر، أو العمليات على بيانات الإنتاج، أو إرسال بريد خارج بيئة الاختبار المصرح بها، أو تحمل تكاليف خارجية غير معتمدة.

## أثر الموافقة

- D01–D20: معتمدة كأساس بالقيود أعلاه؛ D17 مخطط منفصل لا إذن تنفيذ حالي له؛ D10 وD12 محكومان بالنص التفصيلي.
- F01–F08: معتمدة بحدود التقرير مع بقاء الحد المطلوب الآن؛ F09 للمحركات العامة فقط؛ F10 مرفوض؛ F11 مخطط منفصل يتطلب نطاقًا واعتمادًا.
- authorized_phase: phase-1-contracts-compatibility. المرحلة 2 وكل مرحلة تالية تحتاج موافقة انتقال جديدة.
- لا تغيير IDs أو الحقوق أو عضوية Profiles. لا إعلان release v1.1 مكتمل. لا موافقة نشر/إنتاج/إنفاق/بريد حي.
