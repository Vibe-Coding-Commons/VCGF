# Opt-in reference runtime — development checkpoint

Install the existing requirements-dev.txt in an isolated Python 3.12 environment. Run `python scripts/vcgf.py --help`. Commands are route, validate, controls, explain, handoff, evidence, release-check, acceptance and ui-select, plus the adaptive commands advise-engineering, advise-ux, design-plan and release-readiness (runtime/adaptive/cli.py; release-readiness cannot return PASS without a trusted host review). No command executes a project patch, deployment, mail or backup.

`route TASK.json CONTEXT.json --project-root PATH --dry-run` returns a RouteResult, selected capabilities and active_context. The CLI is always read-only; dry-run makes that intent explicit. `--quiet` omits loaded text, never blockers or approvals. `--presentation beginner` adds next-step help. ar/en/auto preferences belong to the independent preferences contract; `runtime.context.preferences_prompt` asks only if confirmation is missing. Language does not alter project UI/code conventions.

Task fields: task_id, intent, classification_confirmed, profile, profile_confirmed, mode, budget, inspection. Optional overlay_add_controls, overlay_remove_controls and risk_signals. Accepted intents are listed in runtime/routing-policy.yaml. Classify after inspection: this is deterministic routing over an explicitly classified task, not an arbitrary-language parser. Unknown intents are rejected. Production, destructive actions and sensitive changes raise risk. Task coverage differs from project Profile coverage; project/release evidence must cover every required Profile control.

Repository facts are refreshed only when source bytes change, observation expires or the fact is unknown. Fact values and inspections are assertions from the caller; hashes do not prove that a human inspected the project or that an asserted interpretation is true. An authenticated host must own context and classification at a sensitive execution boundary. External/user facts need a trusted observation adapter and currently remain unknown. Session handoff always requires revalidation.

The dependency resolver backtracks through alternatives, rejects cycles/missing references/conflicts, treats unknown separately from false and has a bounded search limit. requires/requires_when/any_of drive selection; recommends/provided_by retain informational semantics. Overlay removal never weakens canonical requirements. Loading is confined to the trusted root, rejects symlinks and stale hashes, deduplicates file paths and blocks instead of dropping controls when a budget cannot fit. Budget cost is an estimated token count of the served text (`cost_tokens`, heuristic ASCII/4.0 + non-ASCII/1.6) reported beside the measured bytes (`cost_bytes`); it is an observed count only when the operator sets `VCGF_TOKENIZER`, and even then it is a reference tokenizer, not necessarily the target model.

`generate-runtime-registry.py` writes a derived registry; `--check` reads only. The runtime builds from canonical sources, so the derived file never becomes a second policy authority. `generate-adapter-rules.py` creates one candidate entry per platform and `--check` verifies source equivalence. Opt-in installation must select one entry, not stack legacy copies and generated rules. Local equivalence is not a platform experiment.

Approval and evidence gates require host-owned identity/review callbacks. A callback written in an untrusted project is not a trust anchor. The CLI deliberately cannot return authenticated release PASS without a host integration. Gate authentication must validate signer, authority, scoped action/resource/digests and revocation, immediately before the sensitive effect; the host must also handle replay/TOCTOU and lock execution scope. The reference guarded_call demonstrates ordering, not a universal tool broker.

Evidence files are verified locally against their hashes and current validity, required Profile coverage, findings and exception expiry/review date. N/A requires a reason assessed by the trusted reviewer. An active exception yields CONDITIONAL rather than unconditional PASS. A reviewer must authenticate exception ownership and its approval reference. Minimal/standard/audit views never remove controls, unresolved findings or exceptions from the decision. No file validator proves a test actually ran.

Applicability and profiles (1.4.0): `spec/applicability-matrix.yaml` is the canonical, machine-readable statement of when each control applies (trigger capabilities, `always` for the minimum controls, load point, rationale). The Router first builds the profile-independent floor (capabilities, minimum controls, risk and review-mode additions) and then applies the profile layer: a control required by the confirmed Profile joins the route only when one of its triggers is among the selected capabilities, so baseline ⊆ production ⊆ high-assurance for the same task and no Profile loads a control unrelated to the task. `scripts/validate-applicability.py` proves that every non-deprecated control is reachable for high-assurance from at least one intent. Acceptance tests per control live in `spec/acceptance/<domain>.yaml` (`vcgf.py acceptance VCGF-XXX-000`); they define what a project must demonstrate and never execute here.

Context efficiency (1.4.0): `lean` and `standard` routes load the derived control cards (`spec/control-cards/`, generated and `--check`-verified from the controls) plus the shared clauses once; `deep` routes load the full control Markdown (`context_detail` in the result). The loader strips HTML comments from served Markdown while hashing stored bytes. A task may list additional reviewed `intents` (one route for the union of capabilities at the highest risk) and `loaded_context` entries (`path`, `sha256`) it already holds: only the delta is sent, `reused_tokens`/`reused_context` report what was kept, and an entry whose hash no longer matches is re-sent. The registry is cached per process while no canonical source changes. The CLI prints hash-pinned references by default and loaded text only with `--full`. `budget_unit` on the task selects what `budget` is compared with: `tokens` (1.4.0 default) or `bytes` (the pre-1.4 comparison); a task that relies on the default is warned when the old byte comparison would have blocked it (`budget.legacy_byte_comparison`), and `scripts/migrate-task-budget.py` rewrites a legacy task explicitly. `loaded_context_policy_sha256` lets a session declare the registry fingerprint it loaded under; a different fingerprint forces a full reload. Each route also returns an advisory `model_guidance` block (reasoning effort by risk and mode, stable cache prefix; see `runtime/model-guidance.md`). `vcgf.py acceptance all` summarises acceptance definitions: scope `framework_self` results come from `tests/acceptance/test_self_acceptance.py` as recorded by `scripts/run-self-acceptance.py`; target-project definitions are always `not_executed` here. A project records its own results in an `acceptance-results` record and runs `vcgf.py compliance RESULTS.json --artifact-root R --route ROUTE.json|--profile P [--expect-code-sha256 H] [--as-of T]`: every applicable definition needs a result, a PASS needs hash-verified evidence (and a reviewer for human tests), SKIP and NOT_TESTED never satisfy a control, and the report states COMPLIANT, FAILED or NOT_TESTED per control without executing anything. `route --as-of` fixes the evaluation instant for fixtures and examples; `--dry-run` is recorded in the output.

Governed Smart UI selection (1.4.0): `ui-select ROUTE.json SCREEN-CONTEXT.json [--budget N] [--quiet]` runs the frozen package's own selector on an explicit screen context and loads only the standards whose governing user-experience control (`runtime/ui-bindings.yaml`) is in the route, hash-pinned by `packs/ux/smart-ui/manifest.json`, confined to the package directory and limited to the remaining task budget. Standards selected by signals but not governed by a control in the route are listed as deferred and never loaded; a route without user-experience controls yields `not_applicable`. For lean and standard routes the standards are served as requirement cards (scope, binding requirements, state and stage contracts, discovery signals, acceptance; `served_bytes` beside the pinned `bytes`); deep routes receive the full standards. The result is the `ui-selection` contract; `--quiet` omits loaded text and the raw selection plan, never blockers; `--full` inlines the text.

Protected canonical controls, Profiles and legal files remain unchanged; new controls are additive and immutable once introduced. The repository VERSION file is the only authoritative framework version. No deployment or publication permission is inferred from any result.
