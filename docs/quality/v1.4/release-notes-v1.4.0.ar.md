# VCGF v1.4.0 — تفاصيل التحديث وحالة الإصدار

**التاريخ:** 26 أكتوبر 2026  
**المستودع:** https://github.com/Vibe-Coding-Commons/VCGF  
**الترخيص:** Apache-2.0  
**المؤسس والمشرف:** Eng. Hamada Sami

## حالة النشر المثبتة

تم دمج شفرة v1.4.0 في الفرع `main` عبر PR رقم 4، ويعرض ملفا `VERSION` و`CITATION.cff` الرقم 1.4.0، بينما لا يزال `VCGF-MANIFEST.yaml` يحدد الحالة `release-candidate`. عند التحقق في 26 أكتوبر 2026 **لم يظهر Tag باسم `v1.4.0` ولا GitHub Release منشور بهذا الاسم**؛ وآخر إصدار ظاهر في GitHub Releases هو v1.3.0. هذه الوثيقة تشرح شفرة v1.4.0 المدمجة، ولا تدّعي اكتمال النشر الرسمي الموقّع. لا ينبغي تغيير الحالة إلى `stable` قبل إتمام خطوات الإصدار الفعلية.

## ما الجديد مقارنة بـv1.3.0؟

1. **التوجيه والانطباق:** مصفوفة مركزية قابلة للقراءة آليًا تحدد متى ينطبق كل ضابط؛ واختيار تراكمي للضوابط حسب مستوى المخاطر، مع دمج النوايا المتعددة لتقليل تكرار السياق.
2. **88 ضابطًا:** الحفاظ على معرّفات ونصوص الضوابط الـ84 الأصلية، وإضافة أربعة ضوابط UX للإتاحة والتوطين واتجاه النصوص وسلامة التفاعل والتجاوب، مع الحفاظ على الفرق بين MUST وSHOULD.
3. **395 تعريف قبول:** نُفذت 20 حالة قبول ذاتية للإطار واجتازتها؛ أما 375 حالة تخص التطبيقات المستهدفة فلم تُنفذ في مستودع الإطار. يفحص أمر `vcgf.py compliance` نتائج المشاريع وأدلتها وبصماتها وحداثتها بدل قبول الادعاءات غير المدعومة.
4. **Smart UI محكوم:** يختار `ui-select` المعايير الملائمة بناء على المسار والملف والضوابط وحقائق الشاشة. بقيت مواصفة Smart UI المجمدة من v1.3.0 محفوظة: 36 معيار مكون و24 نمط تفاعل و20 تركيب شاشة و18 نمط رحلة؛ ولا تعني المواصفات اعتماد كل واجهة تطبيق فعليًا.
5. **تحسين السياق:** Control Cards مع مدقق تطابق معياري، وبنود مشتركة، وتوجيه متعدد النوايا وتحميل تفاضلي ببصمات، وميزانيات توكنز/بايتات صريحة. في مقارنة 16 سيناريو موثقة انخفضت البايتات من 2,800,412 إلى 1,480,014 (**47.2%**)، مع تطابق الضوابط المختارة. ولا يمثل tokenizer المرجعي فاتورة توكنز المزوّد.
6. **الإنفاذ والأمان:** حارس لملفات الحوكمة يعتمد على سجل موافقة، وخطاف pre-commit، ومصفوفة تصنف الإمكانات بحسب أدلتها، واختبارات حدود الثقة. دون موثّق هوية خارجي موثوق تكون السجلات قابلة لاكتشاف التلاعب وليست منيعة عنه.
7. **CI وسلسلة التوريد:** اجتاز التزام `f67ddeb` الخاص بـPR #4 **22/22 فحصًا** على Ubuntu وWindows مع Python 3.12/3.13 وCodeQL وتدقيق الاعتماديات وSBOM وبوابة الجودة. لا تعني هذه النتائج شهادة مستقلة لأي مشروع.
8. **التوافق:** الحفاظ على مخططات v1.0 المجمّدة والنصوص الأصلية وترخيص Apache-2.0 وحقوق المؤسس. ويمكن للمشاريع القديمة استخدام `budget_unit: bytes` صراحةً بعد مراجعة ميزانياتها.

## البدء السريع

```bash
git clone https://github.com/Vibe-Coding-Commons/VCGF.git
cd VCGF
python -m pip install -r requirements-dev.txt
python scripts/release-quality-gate.py
python scripts/vcgf.py acceptance all
python scripts/vcgf.py route examples/runtime/login/task.json examples/runtime/login/context.json --project-root . --dry-run
```

بعد ذلك اتبع [دليل إعداد المنصة](../../platform-guides/README.md). أوامر CLI المرجعية تقرأ وتتحقق وتوجّه؛ ولا تثبت الإطار تلقائيًا داخل كل منصة AI.

## الحدود المعروفة والخطوات المتبقية

- لم يثبت بعد نشر Tag موقّع وGitHub Release لـv1.4.0 بأصول وتجزئات تحقق.
- مثال Claude Code Hooks يحتاج تجربة فعلية على المنصة قبل وصفه بأنه إنفاذ مثبت.
- توجد أربع نتائج مفتوحة داخل حزمة Smart UI المجمّدة، وقد يفشل قالب مخالف للمخطط إذا نسخه مطور يدويًا.
- نجاح اختبارات الإطار الذاتية لا يعني اجتياز اختبارات المشاريع المستهدفة الـ375 أو اعتماد تطبيق إنتاجي.
- تحتاج المراجعة البشرية والثقة بمفتاح التوقيع والموافقات على المضيف والتحقق من أصول الإصدار إلى أدلة مستقلة.
